# ACP adapter 执行与集成合同

无论 adapter 来自上游还是自行开发，至少应满足以下合同。
协议版本、字段和可选能力以锁定依赖对应的 ACP SDK/类型及实际握手为准，不在本合同中
另定义一套私有请求格式。自行开发时优先复用 ACP SDK，并把新增 SDK 作为精确版本的生产依赖。

## 协议和输出

- 通过 stdin/stdout 传输 ACP；
- stdout 只能包含协议数据，日志、调试信息和诊断必须写到 stderr；
- 支持初始化、创建会话、执行提示词、取消和连接关闭；恢复能力按真实支持情况声明并测试；
- 启动失败时在 stderr 给出可诊断错误，并以非零退出码结束；
- 正确处理不完整输入、异常断开、超时和重复取消；
- 路径中包含空格或中文时仍可工作。

## 会话和模型

Agent 应为每个 ACP 会话维护清晰的会话身份，不要把不同任务合并到同一个全局会话。

如果 Agent 支持模型选择，应通过 ACP 能力与模型列表对外声明；如果不支持，就使用 Agent 自己
的默认模型。不要把主 Agent 当前使用的模型名称直接传给外部 Agent，因为两者的模型命名空间
通常不同。

## 权限

adapter 必须通过 ACP 权限请求上报受控操作，不能绕过运行时策略直接执行。宿主可提供统一权限模式，投影关系如下：

| 宿主权限意图         | 设置值                    | ACPX `permissionMode` | `nonInteractivePermissions` |
| -------------------- | ------------------------- | --------------------- | --------------------------- |
| 禁止受控操作         | `deny-all`                | `deny-all`            | `deny`                      |
| 只读，拒绝操作后继续 | `read-only` + `continue`  | `approve-reads`       | `deny`                      |
| 只读，立即终止任务   | `read-only` + `fail-task` | `approve-reads`       | `fail`                      |
| 完全访问             | `full-access`             | `approve-all`         | `fail`                      |

只读模式还可以选择“拒绝越权操作后继续任务”或“立即终止任务”。只有被 Agent/adapter 正确
上报为权限请求的操作才能被该策略控制；因此权限适配是正式接入的必要项，不应只验证聊天回复。

## 认证

认证应继续使用 Agent 官方支持的凭据存储或由部署方明确提供的进程环境。禁止把 token、密码、
cookie、认证文件内容写入：

- 产品目录或插件的公共文件；
- 启动参数；
- 源码和提交记录；
- 日志与测试快照；
- 安装包中的公共配置。

如果应用启动 Agent 时使用隔离状态目录，而 Agent 默认只会从用户目录读取登录状态，需要在
adapter 内实现最小化的认证衔接，并验证文件权限、刷新流程和退出清理。不要实现“复制整个用户
配置目录”的通用逻辑。

测试时至少覆盖“未登录”“凭据过期”“凭据格式损坏”和“登录状态有效”四种情况。

## 进程生命周期

取消当前回合与关闭会话是两件事：取消应停止当前工作，会话是否保留由原生生命周期决定；
不要把可恢复会话中的存活进程直接判为孤儿进程。会话关闭、父进程退出、协议 stdin 关闭或
应用关闭后，应清理该任务所属的 Agent 与辅助进程。Windows 上要验证进程树清理，
且只能按已核验的启动路径和进程归属清理，不能按 `codex` 等名称杀掉用户的其他进程。

## MCP 工具与 Skills

当前 ACPX 只接受 stdio MCP 启动项。用户 Server 配置仅消费 `command`、`args`、`env`，不支持把 OpenClaw 专用 `cwd`、请求超时、远程 HTTP／SSE 传输或 headers 当作 ACP 会话能力。宿主须先过滤禁用、无命令或不受支持的项，以及保留的工具桥名称，再按用户明确选择发布。

Agent／adapter 必须消费 ACP 会话真实提供的 MCP Server 信息；握手成功不能证明工具可用。应验证枚举、成功调用、权限拒绝、超时、取消和 Server 异常退出，凭据不能经 Server 名称、参数或错误详情泄漏。

Skills 不因开启 MCP 自动共享。外部 Agent 可使用它自身支持的技能；共享宿主技能需要另外设计明确、安全且真实支持的流程。

### 路由技能

本包自带 `skills/acp-router`，只按宿主当前配置且启用的 Agent 目录和实际原生 schema 发送；上游别名不代表已安装或授权。缺少依赖、连接失败或结果未知不会触发下载安装、修改全局命令、启用 Agent、切换执行方式或重放输入。明确直连请求也须核实与受管路径相同的命令、认证、权限和生命周期归属。

## 受管命令、诊断与服务生命周期

本包接收可信宿主在构建／配置阶段提供的结构化 `command` 和 `args`，不把终端用户任意输入变成 executable，也不让缺失命令落到上游 package runner。适配器运行依赖必须在交付前准备，运行时禁止 npm／npx、公共下载或自更新。缺少文件应返回安装／构建诊断。

`acpx.agent.doctor` 只证明启动和基础 ACP 初始化；未启用但已登记的项可诊断，诊断不能扩大任务准入。应区分缺失程序、协议错误、启动超时与握手后的认证失败，不能把一次 doctor 成功宣称为任务、权限、模型或取消均验收。

启动探测默认关闭，避免缺失可选 adapter 使整个后端不健康。连接超时约束启动和控制操作，不代替原生整轮时限。停止服务必须等待会话和诊断清理完成；清理失败时，不在该服务实例上激活替代 owner。恢复只使用精确未消费的 resumable 记录，不继承前次 Gateway 的进程租约。

Windows 命令包装器、隔离认证、平台依赖裁剪和来源记录见 [README](overview.md) 与 [UPSTREAM](../../../../plugins/extensions/acpx/UPSTREAM.md)。包内实现不导入宿主应用源码，也不把 Core 调度和持久任务状态移进插件。

## 开发与验证

新增专用 adapter 的协议转换、认证和目标特例须归本包，可采用 `adapters/<agent-id>/` 组织；这只是推荐布局，并不存在自动注册约定。集成构建必须显式编译稳定入口、登记其命令并核验目标平台必需文件，单放 TypeScript 源码不会生成可执行入口。

依赖使用精确版本并同步本包 lockfile、许可证及第三方声明，不把一个平台的依赖树复用于另一平台。分发策略以包内 [package.json](../../../../plugins/extensions/acpx/package.json)、[package-lock.json](../../../../plugins/extensions/acpx/package-lock.json) 和 [THIRD_PARTY_NOTICES.md](../../../../plugins/extensions/acpx/THIRD_PARTY_NOTICES.md) 为准。

包内 `tests/`、`src/*.test.ts` 及注册入口测试覆盖认证、命令 shim、运行代次、session owner、reset／恢复、进程租约、reaper、runtime proxy 和 service lifecycle。测试工作区必须提供匹配的原生 SDK。宿主另测产品目录／设置、MCP 投影、安装包归档以及禁止运行时安装时的真实握手和任务。

正式接入须覆盖非 ASCII 路径、协议污染、格式错误、非零退出、未登录／过期凭据、所有已声明权限与恢复能力；纯聊天、模拟进程和合成协议测试不能替代真实 CLI 及最终安装包验收。每个目标平台记录实际版本、认证前提、通过项及未验证项。
