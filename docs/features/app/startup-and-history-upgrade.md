# 启动分流与历史会话升级

启动先确定数据与交付状态，再选择首次安装、历史迁移、正常升级或普通启动。普通启动允许先进入主页；发送、历史读取和原生管理能力仍等待当前引擎的执行准入。升级和恢复始终保留各自的数据门禁。

## 四类启动

判定发生在产品 Store、配置投影和 Gateway 打开现有环境之前。先读取启动记录和随包的
package/manifest 轻量版本信息；已完成安装、原生版本相同且无降级或未完成事务时直接
选择普通启动，不进入详细数据分类。其余路径再识别数据代际并处理升级或恢复。

| 事实                                                           | 路由         | 行为                                                                                                |
| -------------------------------------------------------------- | ------------ | --------------------------------------------------------------------------------------------------- |
| 无活动产品环境                                                 | 首次安装     | 当前四步初始化                                                                                      |
| 已发布版本的活动 JSONL 索引或旧 `cowork_messages` 产品库       | 需迁移升级   | 选择性备份、新环境准备、历史恢复、启动检查                                                          |
| 已有环境，OpenClaw 版本变化、缺少完成回执或有未完成升级        | 正常升级安装 | 全部保留；原生检查、备份、结构更新和复验后再启动                                                    |
| 已有完成记录，OpenClaw 版本相同、无未完成事务或待确认降级      | 正常启动     | 包括仅应用升级或构建指纹变化；加载已有数据和必要配置后并行准备 Gateway 与界面，界面就绪即可进入主页 |
| 仅剩旧原生配置、无产品库及活动原生历史                         | 需迁移升级   | 保留判定并进入选择性恢复事务，不按首次安装直接覆盖                                                  |
| 有未完成的阶段记录                                             | 继续上次流程 | 恢复当前阶段；已确认的备份、目标环境不重复替换                                                      |
| 格式未知、损坏、当前产品库中的活动 JSONL/SQLite 混合或读取失败 | 恢复错误页   | 保留数据，拒绝自动清空重建                                                                          |

### 路由记录与旧数据范围

`startup-state.json` 使用稳定的数据代际 `native-sqlite`，不是每个应用版本一个标记。
已有当前版本用户缺少该文件或交付完成回执时，先检查并进入保留全部数据的正常升级流程。
缺少 `.justdo-initialized` 不会触发首次安装或历史迁移。旧展示标记写入失败也不改变路由。
备份、原生导入归档和已删除 JSONL 不算活动旧环境。不自动寻找其他品牌的目录。
存在活动 JSONL 但缺少产品标题/会话索引时，在隔离前停止，不能以空会话列表宣布升级成功。

迁移升级只处理已发布 JSONL 代际；正常升级调用当前锁定 OpenClaw 的数据库维护 owner，
不导入旧版本代码、不自写原生迁移 SQL，也不恢复已撤回的 9.6→9.8 SQLite 兼容桥。
旧发布版也可能生成原生 SQLite 文件。含 `cowork_messages` 的旧产品库仍选择迁移升级，
不能仅凭这些文件存在就按当前代际混合拦截。迁移恢复活动 JSONL 与旧消息缓存；
旧 SQLite 及其归档只保留为可核验的恢复原件，不解析旧 schema，不写入新活动环境。
SQLite 独有而未出现在 JSONL/缓存中的消息不会因此自动显示在迁移后的会话中。

已发布旧版只迁移 `main` 的助手与会话。产品记录的 `agent_id` 为 NULL、空值或 `main` 时
按 main 恢复；其他记录和其他原生 agent 的索引不参与恢复，也不改归 main。main 索引中
明确属于其他 owner 的键同样排除。旧版隐藏的定时任务身份、按模型生成的临时身份等只留
原备份，不建立新版助手档案，不提供历史助手兼容层。已迁移的当前用户数据不在此流程自动清理。

### 恢复入口与配置兼容范围

发布版 JSONL 的恢复统一由本模块负责。Gateway 管理器不再额外扫描全部 Agent 的旧
`sessions.json`，也不提供第二套迁移计划、确认或进度 IPC。正常 OpenClaw 数据库升级
继续由 `startup/upgrade` 调用当前原生维护能力，与这里的一次性历史导入分开。
新产品库直接建立完整当前结构；旧设置、未发布的产品库中间结构、旧原生配置字段和
旧 preload 协议不再逐项转换。具名 UI 偏好只从 Main KV 恢复，不搬迁旧 origin 的 localStorage。

## 普通启动与执行准入

普通启动不执行宿主产品库 quick_check、会话目录扫描、运行包全量哈希、Python 健康检查，
也不启动离线 schema 检查或会话规范校验子进程。只读取轻量交付信息和必要的启动记录、
确认既有产品库路径存在以避免静默新建，再由产品 Store 正常打开数据。Gateway 在必要
配置加载后立即启动，本机集成准备与其并行，工作界面在核心外壳及首个工作区就绪后即可开放交互，不等待引擎或本机集成结束；当前 schema、会话和插件准入由 Gateway
自身负责。实际打开或原生启动失败仍显示真实错误，不转成升级重试或重建数据。

### 配置队列与目标历史准备

Renderer 启动时的扩展清单发现可能等待引擎，但发现阶段不持有应用配置队列；
查询进入前等待此前设置事务，发现完成后的本地配置投影再通过短队列等待重叠
保存或失败补偿。后续配置初始化可以独立读取已确认设置，避免引擎冷启动超过
30 秒时被误报为 `configService.init` 超时。
全局 Gateway ready 后，目标 Agent 的会话库仍可能处于后台准备阶段。打开已有聊天时，
Renderer 按原生明确的暂不可用原因保留加载状态，并在精确会话及连接所有权内有界重读；
不把临时准备误报为已读取空历史，也不为此恢复普通启动的宿主检查或升级流程。

等待、取消及终态失败规则见[历史加载](../../architecture/15-chat-rendering.md#4-历史加载与有界展示)。

### 主页可操作与 AI 可发送

普通启动在必要数据与配置就绪后发布 shell Ready，在遮罩下加载 App 和首个工作区；引擎和本机集成的 waiting/running 不延迟揭幕。`enginePreparationPending` / `enginePreparationFailure` 仅表示执行准入，不再控制主页展示。引擎失败通过标题栏提供诊断和重试，保留导航、设置和登录，不卸载已开放的主页。

Main 的唯一准备 owner 等待引擎准备完成，并核对认证连接、执行权限、process/lifecycle 代次和真实 Running 后才开放能力。HTTP 健康、单独 Running 或可选任务结束均不够。重试先发布新的 pending；旧操作的迟到结果不能覆盖新操作，独立重启也重新核对当前代次。另外三类启动在完成 shell 前仍执行原有准入与进程复核。

未准入时的操作分别处理：

- 聊天发送、快捷键和原生操作禁用，文字草稿可继续编辑。Main 在异步等待前后检查新聊天和续发，不将拒绝的请求排到就绪后自动发送。
- 历史正文、插件清单和定时任务在就绪后自动首次读取，不用空数据或连接失败表示正常准备。插件/任务导航外壳始终可进入，已挂载表单在后续重启时保留。
- 本地外观和登录不等待引擎；原生电脑控制和 Worktree 设置等引擎就绪后加载。登录成功、模型同步和执行可用各自反馈，不能互相推断。

### 后台集成与退出

本机集成持有唯一后台 Promise 并立即观察失败。可选错误保留独立失败行；普通启动的意外集成异常保留主页服务提示，不将已运行引擎或已加载界面改成失败，也不永久阻塞设置。关键数据、配置读取或 Renderer 初始化失败仍进入真实错误页。

退出停止派发新准备，并等待全部在途 owner 收尾，再关闭服务和 Store；退出中迟到完成不更新任务状态。此处保留正常清理，不把提前展示主页变成提前退休后台资源。

## 正常升级安装

正常升级保留产品数据库、原生会话、助手、配置、登录资料、插件和定时任务，不进入
历史迁移的隔离、清空、新库或默认值重建路径。首个真实路由窗口冻结前，独立的只读
检查进程使用已准入运行包及其独立 Node 检查数据库；不得调用会写入 token、端口和
配置的普通 CLI 环境生成器。读取失败、未知结构或不支持的版本保留数据并显示原因。

schema 结构维护在打开产品 Store、同步配置、开放浏览器/CLI/app-server 和启动 Gateway
之前完成；会话规范准备则在配置同步及历史恢复后、开放外部入口与 Gateway 之前完成。
只使用当前发行包的原生维护锁、数据库作用域、lease、一致性备份和结构升级 owner；
不运行会修正插件、服务、模型或配置的通用 Doctor 修复。目标模块受当前版本静态合同
及冻结产物校验约束，缺入口或身份不符即拒绝，不回退到旧包或主机 Node。

### 维护产物与完成身份

开发运行包可能保留 `gateway.asar`，实际发行过滤可省略此重复归档。Electron Main 对
归档本身的物理类型与整文件哈希使用 `original-fs`，读取归档内部模块仍使用 Electron
原有的归档文件系统；不能用普通 Node 的 `stat` 结果推断 Electron 行为，也不全局关闭
ASAR 支持。归档存在时必须通过整包与逐模块双重校验，省略时仍严格验证实际 dist owner。

启动事务记录目标交付身份和未完成阶段。退出等待维护子进程及其资源退休；失败或
结果未知不写成功回执。重启先重新检查原生事实，已完成的更新不因缺少子进程回执
再次盲目执行。只有同一目标的原生复验和应用初始化完成，才提交本次交付完成身份。
数据库更新成功与模型、Gateway 或某个任务的执行成功分别判断；引擎的可恢复配置
错误仍显示真实原因并保留设置入口。

### schema、备份与退出

v2026.10.7 的 shared schema 仍为 20，agent schema 为 25（与10.6相同，10.4为24）；结构变更由
原生拥有。正常升级覆盖当前合同允许的 24→25 和已为 25 的维护/复验；未知、更老或
更新的结构不得由应用自行推断修复。迁移升级的 JSONL 导入和全新安装直接建立当前结构。

维护先取得原生 Gateway 排他锁与 agent 维护 lease，再完成全部发现数据库的一致性
快照、更新和复验，避免备份期间有其他 agent writer。备份组保留首次更新前原件，
重试不覆盖；不能把它描述成每次重试都包含后来外部写入的新快照。
跨数据库不是一个整体事务，失败或取消后可能部分数据库已到目标结构；重启先按原生
实际状态重新核对并继续，不自动恢复所有数据库到旧结构，也不盲目重复未知操作。
正常退出等待原生资源关闭。超出有限退休观察预算时保持结果未知、阻止本进程继续，
不把超时当作已经完成 join 或升级成功。

Gateway 使用同一子进程唯一的关闭 owner 和首次 deadline；先请求原生退出，保留其
330 秒清理窗口，强制终止后最多再观察 15 秒。仅实际正常 close/exit 能确认成功，
信号退出、非零退出及无确认均保留失败，阻止本进程重新启动引擎。Main 先等待启动资源，
其他服务前后合计使用有限预算，并始终尝试 Gateway 关闭；超时任务仍有观察者，
迟到完成不能消除本次失败。只有全部资源已确认退休才能关闭现存产品 Store，
不会为退出惰性初始化 Store，也不会在失败后继续安装更新。监督层共用
shared shutdown policy，并以目标原生策略测试检测后续上游预算变化。

### 会话规范准备与准入回执

首次安装、迁移和正常升级在配置同步、历史恢复之后、Gateway 启动之前，执行原生会话规范准备。
它独立于 schema 版本：schema 已是目标版本，仍可能有首次校验或待校验历史。准备由
离线受信 Node 执行，使用原生文件代际回执和 Worker，不与 Gateway 同步插件加载争用
提交授权。仅有真实待写工作时才先确认完整原生备份组；已有有效回执且无 pending 时不
派发 Worker、不重复备份。实际备份和校验活动
仍由 Main 上报。

会话准备使用独立的 `sessionInspect/sessionBackup/sessionPrepare/sessionVerify`
活动，与 schema 升级的 `nativeInspect/nativeBackup/nativeUpgrade/nativeVerify` 区分，
维护路径不把会话规范校验描述为数据库结构升级。
schema 检查保持只读，不拿私有快照的物理身份冒充原文件校验回执。

已有有效原生规范回执且无 pending 时，在首次排他维护 lease 内完成完整文件组检查、
原生回执探测及 ready 断言，等待 lease 退休后直接返回；不再经历无写入意义的 Worker
交接、第二次 lease 与其前后的重复全组扫描。存在待写工作时仍先确认备份，再派发
原生 Worker 并重新取得 lease 复验。物理身份、配置、维护权及子进程实际关闭检查均保留。
`NativeDatabaseStartup` 记录每次离线检查/准备操作的耗时与退休是否确认，不记录会话正文。

维护成功回执必须同时具备 schema 就绪和会话规范准备完成。规范校验失败、子进程未确认
退休或退出期间迟到的成功，都不能放行 Gateway 或刷新交付身份。首次安装保留设置
入口时也保持原生启动门禁；用户修复问题后重新启动，重新检查原生事实。
原生备份可按目标版本和实际文件组身份复用首次原始快照，不把该回执描述为每次都新建
最新快照；损坏的组明确拒绝，不覆盖原备份，也不自动恢复旧快照覆盖后来新增的数据。

### 跨版本升级与降级策略

路由不按相邻发布版本串接分支。交付方向判断、目标原生 schema、允许的来源 schema
及选定维护 owner 各自集中声明；跨过若干版本时，直接由目标版本检查现有数据是否在
其支持范围内，再交给目标原生 owner 维护。不在范围内时保留数据并说明不兼容，
不能猜测一串中间版本、跳过备份或清空重建。后续升级需补目标合同和实际来源数据测试，
不能只更新版本号与 schema 数字。

#### 版本方向与交付身份

应用版本与 runtime 版本分别比较；任一降低都属于降级，不能用另一个版本升高来抵消。
仅应用版本升高或冻结构建指纹变化不单独触发正常升级界面：构建配方包含应用的
package 信息，应用普通更新也会改变 manifest。OpenClaw 版本按去掉可选 `v` 前缀后的
数字版本比较；已有完成记录且版本相同时直接正常启动，不额外查询原生数据库来决定
是否需要维护。缺完成回执、原生版本变化或未完成升级则仍走相应维护流程。
`completedIdentity` 保留最后一次真实维护完成的交付身份；普通应用打开成功只更新独立的
`lastOpenedIdentity`，不标记 schema 或会话校验成功。

版本顺序及降级确认使用
`lastOpenedIdentity ?? completedIdentity`；维护完整成功时才同时更新二者。
写入失败报错并保留旧记录；相同普通打开身份无需重复写入。
构建指纹用于本次运行的精确产物准入、子进程回执和完成身份，不作为跨次启动的兼容门槛，
也不根据哈希大小判断版本先后。未完成目标与当前目标版本同级或向前时，首次安装、历史迁移
和正常升级均可沿用原事务接续；应用版本变化、同版本重打包或 OpenClaw 正常升级不会单独
触发“另一个运行包”的拦截。未完成目标也参与版本方向判断，不能借缺少完成回执掩盖回退。
原已使用版本的方向判断和降级确认独立保留；未知版本、未知数据结构和实际不受支持的 schema
仍拒绝推断兼容。

程序自动读取版本、阶段和数据库事实，不要求用户手动改删启动记录。

#### 未完成事务的接续

路由按版本和阶段决定，不为选路由提前扫描原生数据库。执行前重读并核对原事务的关键身份、
阶段、版本和隔离清单；时间、摘要及附加诊断字段变化不阻断，提交时合并保留。
Migration 的 `Backup`/`Isolate` 尚未写入目标
环境，直接按当前版本保全、隔离旧输入，在成功的阶段提交中更新目标；事务 ID、旧候选快照
和已确认备份均保留。其他已可能写入目标数据的阶段先由当前原生 owner 只读检查，核对事务
后在原阶段记录新目标；无需维护时一次提交即可。需要维护时，先持久记录新目标和
`schemaPreparationPending: true`，然后调用原生维护；该方法只在备份、维护后复验及子进程
退休全部确认后返回，宿主不再紧接着重复扫描。

成功后清除此标记；结果未知或提交失败保留
标记，同包重启也重新检查实际事实。
正常升级继续使用既有检查、原生备份、升级和复验链，不因为旧流程已到 Check 就跳过。
`Complete` 仍残留目标身份的记录不是已确认交付，保留原事务转为正常升级并同步写入 route。

迁移接续不回退阶段、不重新暂存已导入或归档的 JSONL；ImportHistory 由当前 Doctor 核对并
补完，RestoreMetadata 由当前原生身份验证后继续；Check 也重新核对原生身份和产品回执，
不重写已修改的标题、工作目录或其他产品元数据。早期 schema 检查不替代初始化/导入完成后
当前 owner 的最终 schema 与会话规范准备，也不复用旧进程的成功状态作为完成证据。
每次执行阶段只先检查一次 schema；无需升级且无数据写入时不立即重复检查，实际升级由
原生 owner 自带复验。配置或历史导入后可能新增数据库的最终准备仍保留。

准备失败时保留已验证的真实事务阶段供展示，日志记录新旧交付身份、持久阶段和能否接续，
不再用新建的默认事务覆盖错误上下文。界面的备份步骤也包含 `Isolate`，不能仅凭此步骤
判断是否尚未开始隔离。

真实随包原生检查已验证：合法 shared20 搭配 agent25 或可升级的 agent24，旁边保留未导入的
合成 JSONL 与索引时，分别返回无需升级、需要升级；数据库、配置和待导入文件字节不变，
子进程与原生句柄关闭均确认。无需为接续新增放宽原生检查的模式。

#### 降级确认

检测到降级时，在打开 Store、配置同步和 Gateway 前暂停，展示上次使用与当前安装的
应用/runtime 版本，建议使用原版本或较新版本，同时提供“仍然启动”。用户点击后，
Main 只释放本进程当前目标的启动等待，接回同一正常启动链；不重跑整个 initApp，
不提前标记就绪，也不把选择写成永久兼容授权。
确认请求绑定当前 coordinator、随机 requestId、完整内部目标身份和受信窗口主 frame；
重复、迟到、其他窗口或退出中的确认不能释放新的目标。退出取消当前等待。
继续后仍执行正常的数据库、配置与运行资源检查；不支持的 schema、未知格式或实际
加载失败显示具体错误，保留文件，不通过删库重建来继续。

明确的兼容合同和实际测试
用于判断数据是否支持，而“仍然启动”只表达用户愿意尝试正常启动。
完成回执不是历史数据的替代品；缺少回执的首次采用仍须通过目标原生数据检查。
降级确认继续复用正常升级外壳并保留确认前不检查数据库、不写文件的顺序；
仅应用版本降低也先显示该提醒，不能因 OpenClaw 版本相同而隐藏确认窗口。

## 备份与恢复边界

本节只描述迁移升级的历史备份与环境替换，不适用于正常升级安装。

备份位于 `<userData>/backups/<transactionId>/history/`：

- `justdo.sqlite` 的一致性快照，包含已提交 WAL；不能只复制主文件。
- `openclaw/state/agents/*/sessions/sessions.json` 和原生历史 JSONL。
- 旧原生存储中的 SQLite 原件及 WAL/SHM/rollback journal、孤立侧文件和恢复副本，
  包含各 Agent 的 `agent/` 及共享 `openclaw/state/state/` 下 SQLite 文件族；另保留历史归档、
  `sessions/cold/`、旧索引备份、`session-sqlite-import-archive/` 和
  `session-sqlite-migration-runs/` 回执。这些原件进入校验清单，但不参与 JSONL 导入或新环境恢复。
- `openclaw/state/media/` 历史附件。
- 校验清单、导入计划与不含正文的原生身份校验回执。

### 备份完整性

不复制轨迹日志、技能提示缓存、插件、定时任务、原生配置和凭据文件到新环境。
旧产品快照只作恢复来源，其中原有的设置不进入新活动库。
源文件变化、链接路径、校验失败或身份冲突都停止升级，不覆盖备份。
原生 SQLite 仅逐字节保全，不使用产品库驱动打开或转换；复制前后核对完整原件清单与
摘要，隔离前再次核验，新增、删除或变化的侧文件/归档均中止隔离。旧应用必须停止写入；
此处不是在线原生一致性快照，也不以文件大小或修改时间推断历史是否已经导入。
事务记录通过临时文件、文件同步和原子替换提交；备份清单全部校验通过后才隔离旧目录。
若中断发生在备份阶段提交之前，保留原候选快照并重新采集活动旧数据，避免遗漏中断后新增的历史。
此阶段若活动环境已变成当前代际则拒绝覆盖，不沿用过期的迁移判定。

### 隔离旧环境

旧环境使用同卷重命名归档到 `<userData>/backups/<transactionId>/retired/`。
迁移成功后仍保留已完成的归档和选择性历史备份，暂不自动清理。
必须成功归档的根项只有 `openclaw/`、`outbound-header-proxy/`、`developer/` 和全部 `justdo.sqlite*`
（包括主库、WAL/SHM/journal 及其他同前缀文件）；访问失败、移动失败、两处重名冲突，
或源与归档均缺失，均阻断初始化，不能猜测数据归属。Windows 名称比较不区分大小写。

`logs/`、根目录的 `install-timing.log` 和 `install-resource.log` 均留在原位，不参与归档；
恢复中断事务时，即使旧隔离清单包含这两个安装日志，也跳过移动。
`LOGIN_STORAGE_CONFIG.directoryName` 配置的登录目录同样排除；整个目录及其登录信息和其他
业务文件留在原位，恢复中断事务时也不按旧清单移动，目录名直接取自配置而非固定名称。
备份自身、启动记录及其临时文件、当前进程的 OS 锁文件同样不参与目录替换。
其他根项统一尝试移动，不再按 Chromium 目录名维护排除清单。

仅对具体源项访问或
重命名遇到 `EPERM`、`EACCES`、`EBUSY` 或 `ETXTBSY` 时记录项目名和错误码，保留原位继续；
旧清单中的可选项已经自行消失也不阻断。备份校验、路径边界、归档目录创建、事务提交，
以及磁盘空间、I/O 等其他错误仍阻断。因此根目录可以保留被占用的非必需项。
恢复旧隔离事务时沿用原清单，并补入当前根目录中新增的必需项；扩展清单先持久化再移动，
提交初始化阶段前再次确认根目录中已无必需项。已有备份不重建或覆盖。
归档前只允许内存中的引导窗口，持久化主窗口在隔离完成之后才创建；否则 Chromium
还可能提前加载旧缓存和其他会话数据。

上次归档后被当前启动重新生成的非必需项，与旧归档重名时，另存到
`retired-additions/<随机ID>/<原名>`，两份均保留；若移动被占用则两处均不动，移动后中断可以继续原事务。
产品 Store 不再从根目录 `config.json` 自动导入旧设置；即使文件因占用留在原处，
新建或重开数据库也不会读取它。已有 KV 设置保持原样，不增加导入开关或跳过标记。

#### Windows 占用的验证边界

Windows 隔离验证使用包含合成词典、Service Worker、CacheStorage、IndexedDB、OPFS、
持久分区和图形缓存的已有 profile。仅创建两个内存启动窗口、不开持久主窗口时，
`Service Worker` 仍出现 `EPERM`；同次验证中 `Cache`、`Code Cache`、`GPUCache`、Dawn 缓存、
`DIPS`、`Partitions`、`Preferences` 和 `Local State` 等其余项可移动。词典占用在用户环境中
另有确认。提前打开持久主窗口的对照会额外占用多个缓存和会话目录，因此必须保留窗口创建顺序守卫。

这些验证不保证其他进程或文件权限不会导致占用；可选项统一容忍上述访问错误，
不再要求先复现或识别目录名，必需项及备份/事务基础设施仍严格校验。

### 产品元数据恢复

新目标直接建立当前产品表。旧产品库以只读连接提取
ID、标题、归属、时间、置顶状态和关联，不在旧库上删表或升级 schema。
自定义分组只恢复名称和已准入历史会话的成员关系，保留空组及同名的不同组；
旧分组 ID 仅用于关联，不带入旧颜色、排序或创建时间，使用当前新库默认颜色、排序及本次恢复时间。
旧库没有分组表或归组字段时按未分组处理，没有置顶字段时按未置顶处理；找不到对应分组的旧引用也按未分组处理，
不影响会话历史恢复。置顶只保留布尔状态，不恢复额外排序偏好。
正常升级安装继续使用当前库，不执行这里的环境替换。

### 原生历史

使用安装包中锁定 OpenClaw 的 `doctor --session-sqlite import` 和 `inspect`，
两者都显式传入 `--session-sqlite-agent main`，中断后重试也保持相同的 main 范围。
投影历史身份、时间、压缩历史、标签与父子关系；不带入模型覆盖、技能快照、
权限、Goal、待输入、待投递或插件运行状态。只定位备份中的文件，不跟随旧机器绝对路径。
压缩快照引用重新指向目标副本，备份中的原始 transcript 字节保持不变。
原 `sessionFile` 只用于定位备份目录内的 basename；topic 和其他合法文件名保留，
重新指向当前目录，不假定正文总是 `<sessionId>.jsonl`。

导入发生在最终规范 state 路径，Gateway 与外部聊天入口在此之前不能启动。
导入后以原生 SDK 的公开 `getSessionEntry` 逐条校验原生 session ID 和 `spawnedBy`，
身份/关联缺失时不提交产品映射。Main 不用 SQL 读取或修复原生 transcript。
退出时等待导入子进程退休，未知结果保持当前阶段，重启交由原生导入器核对。

#### 关闭历史工具占位

迁移目标中的旧工具调用统一关闭，不能在重新打开历史时继续显示运行中。启动迁移模块在
Doctor 导入前规范待导入 JSONL 副本，覆盖主文件、子会话、同 session ID 的历史副本及压缩前后快照。
没有结果的调用补入原生格式的静态缺失结果说明；空 `sessions_yield` 结果也明确关闭。
补件使用原生 synthetic missing-tool-result 语义，注明原执行结果缺失，不作为真实工具完成或能力回放证据；
已有非空输出、明确失败和取消信息保留，不生成新工具执行、审批、Widget 或整轮结算回执。
真实侧分支结果保留在原分支；活动路径仍缺结果且没有显式叶选择时，在末尾独立补件关闭该路径。

工具和原消息身份、原最终正文及分支选择保持；重试从不可变备份重新生成，补件 ID 确定且重复处理不追加。
无需变更的文件保持字节一致，不添加 Renderer、IPC、KV 或原生运行时补丁形式的历史兼容分支。
工具补件支持 session v2/v3/v4 的原生树形及旧线性记录；含工具的 v1、需规范处理的
索引式压缩记录、同帧重复工具编号和无法确认父引用的记录明确拒绝，不猜测身份或覆盖备份。

#### 子会话状态与终态证据

所有具有 main 父关联的历史子会话在迁移输出中统一为成功或失败：任一原始记录为 `done` 则输出 `done`，
否则一律输出 `failed`，包括无状态、未知、旧运行中、中断、停止和超时；不会迁移出“执行状态待核实”的历史子会话。
真实运行元数据只从原生索引中已有的完整整轮终态快照恢复：必须有 main 父关联、
`done/failed/interrupted/killed/timeout` 终态、对应 `lastRunId`、合法结束时间，且没有当前 `lifecycleRunId`。
中断、停止和超时的完整快照按失败匹配。只恢复所选二态结果对应唯一一致快照的运行 ID、有效起止时间/累计耗时及错误说明，不恢复活动运行、队列、自动恢复或结果投递状态。

精确终态运行 ID 由原生 Doctor 按原件导入；公开 SDK 不暴露其私有运行 owner 字段，
首次恢复产品元数据前通过同一公开原生读取器复核物理身份、父关联及公开终态/时间/错误字段；检查阶段只复核不可变身份，
不因子会话后续合法续跑或终态变化而覆盖状态或拒绝恢复。
这些字段不是所有旧 JSONL 代际都具备；旧 `subagents/runs.json` 不在选择性恢复范围，
缺少完整快照时只写上述二态状态，不补造运行 ID、时间或结算回执；不会将最后一条正文、`stopReason` 或消息完整度推定为执行成功。
已完成迁移的现有库不自动从备份回写终态，也不重导原生历史；它可能已续跑或换代。

#### 重复身份与别名

main 索引中的重复规范键必须指向同一原生 session ID，不按“较新时间”挑选。
同一规范键、物理会话及 main 父关联的别名共用上述二态归一化规则：任一原始别名为成功则 `status: done`，否则 `status: failed`，不按枚举顺序选取结果。物理身份或父关联冲突均拒绝迁移，不猜测历史归属。
与所选二态结果一致的完整原生快照去重后只有一份时保留其真实运行 ID、时间和错误信息；没有匹配快照或存在多份不同快照时仅写二态 `status`，不借用另一结果的运行 ID，也不生成身份、时间或结算回执。
首次公开原生读取校验这些实际投影的字段；仅有 `status` 的归一化只确认历史显示值已导入，不代表新增整轮结算证据。

这项临时归一化完全位于启动迁移模块，复用原生既有状态展示，不增加专用产品表、KV、IPC 字段或 Renderer 历史兼容；之后的新运行由原生生命周期正常更新。
已知旧产品/Multica 命名空间遵循原生规范键折叠规则，原始大小写另存回执；
不把该规则推广到 Matrix、Signal 等不透明外部身份。

### 旧消息缓存与映射

原生正文缺失但仍有旧缓存的会话，先转换为一次性的原生导入输入，再由原生工具写入 SQLite。
存在原生索引时继续使用原生 session ID 与父子关联，不另建身份替代它。
保留文本、Thinking、时间，以及工具名称、参数、结果等历史证据；工具记录以静态历史文本呈现，
不生成可执行 tool call、授权、待处理请求或运行终态。目标不创建 `cowork_messages`。

#### 映射提交与重启

`history_session_bindings` 保留产品会话、精确原生 key/session ID、原始外部映射和恢复事务。
标题、置顶、分组及绑定共用迁移事务，先恢复分组再恢复会话归属；事务临时使用 SQLite `synchronous=FULL`，提交并确认完整 checkpoint 后恢复原策略，
再持久化检查阶段，防止独立阶段记录先于映射落盘。即使没有会话，也必须确认新 schema 和默认值落盘。
检查阶段恢复只核验不可变身份回执，
不覆盖中断前合法更新的标题、目录、活动时间、置顶或分组，也不重新创建用户已删除的分组。
外部历史可以作为当前产品会话继续，不重新激活旧外部入口，也不标为旧实时同步的只读会话。

历史绑定独立于原生 worktree 绑定；发送准备核对原生身份和连接代次，并应用当前工作边界及权限。
单条和批量删除共用精确原生身份核对；批量仅删除已确认项，失败项保留，
丢失确认时必须得到明确的原生不存在回执。真正 worktree 仍需逐条删除。
只恢复 main 的原生身份，使用新版默认运行配置，不恢复旧角色文件，不为其他 owner 创建占位助手。
历史身份投影失败时保留检查阶段并停止 Gateway 准入，下次启动重试当前投影。
非 main 记录不转为 main 的空历史入口。

#### 正文或工作目录缺失

原始正文已经缺失时保留标题并明确提示，不推测正文。
原工作目录不存在时，用户可选择现存目录；Main 核对调用窗口、会话身份和未运行状态，
选择期间身份或运行状态变化则拒绝更新。不自动重建旧项目目录。
空目录字段按未绑定目录处理，和不存在的目录一样只计入结果提醒，不阻断历史迁移。
用户选择将项目放在旧应用数据目录内部时，项目随其所在目录归档并保留原件；不自动改写
原工作目录指向归档路径，不将项目复制进新活动环境。工作目录失效仍由用户选择新位置。
跨品牌来源识别及其他附件位置的扩展不属于本次补充范围。

#### 首次继续历史会话

历史会话首次打开或首次准备运行时，使用当前新会话默认权限，并保持无旧模型覆盖，
由当前助手/应用默认模型解析；不恢复旧权限、角色模型选择和审批状态。
产品绑定的 `defaults_applied` 标记使该初始化只发生一次，用户之后选择的模型和权限不会在重开时被重置。
为已使用当前结构的历史绑定补列时默认视为已应用，保留用户已有选择。

### 失败处理与迁移结果

磁盘空间不足、文件占用、访问被拒绝和旧版仍在写入分别显示处理建议，保留真实错误与恢复阶段。
用户可打开数据目录；Windows 文件占用/访问问题可打开任务管理器，手动核对并结束属于旧版应用的占用进程。
应用不猜测占用者、不自动结束进程。处理后通过“重新启动并重试”沿用已确认阶段，未提交的备份重新采集。
磁盘提示说明备份、新数据库和临时文件都需要额外空间，不设置未经验证的固定预留阈值。

#### 结果确认与项目规则提醒

Main 与首个工作区实际就绪后，共用引导停留在迁移结果页，显示恢复会话数、正文缺失数、
需要重新选择目录的会话数。恢复结果压缩为顶部卡片，详细说明、备份位置和打开备份动作
默认折叠；下方常显项目规则整理提醒。用户需手动移除旧项目目录中的 `AGENTS.md`、
`BOOT.md`、`BOOTSTRAP.md`、`HEARTBEAT.md`、`IDENTITY.md`、`SOUL.md`、`TOOLS.md`、`USER.md`。
不存在的文件可忽略。第二步采用四条短句分别说明：新建项目 `AGENTS.md`、迁入上一步
移除文件中的自定义项目内容、自动追加模型上下文，以及不要沿用旧版自动生成的版本。
结果页仅提示，不执行项目文件移除或写入。

默认 1280×815 窗口中，中文和英文的默认完成页完整显示而不产生滚动条；紧凑布局仅用于
真实完成结果，展开详情或缩小窗口时仍允许自然滚动，不通过隐藏溢出来裁掉内容。
用户点击“进入应用”后播放原有揭幕动画；首次安装、正常升级和正常启动继续自动进入。
结果页等待和揭幕期间的新错误都保持首页不可交互。
打开备份、数据目录和任务管理器使用独立、带调用窗口校验的 IPC；Renderer 只传动作，目标路径由 Main 决定。

## 共用引导与柔光汇聚

`app ready` 后立即创建独立的中性启动窗口，与路由判定并行加载；其画面只含本地品牌、
启动文字与不定进度，不读取用户配置或产品 Store，也不提前声称首次安装或正常启动。
窗口无 preload、IPC 或 Node 能力，拒绝页面跳转和新窗口。安装版复用只读 loopback 宿主，
仅准入 `startup-bootstrap.html` 并保留物理路径、字节摘要与 CSP 校验，不扫描完整应用资源树。
真实路由冻结后才创建对应引导或主窗口。

Windows 启动窗口使用相同无系统边框策略，
独立交接 owner 将后继窗口对齐到旧窗口的当前位置；后继 ready-to-show 后以 240ms
原生窗口透明度淡入，旧窗口始终保持不透明垫底，淡入完成后才关闭；用户已最小化启动窗时，
后继继承最小化状态而不抢到前台，最大化也保留原生窗口状态。用户已主动显示后继窗口时，
以该窗口的新状态为准，不用旧窗口的最小化或几何状态覆盖。中性窗到临时引导、
临时引导到主窗口共用该 owner，不在多个 ready 回调中各自 show/close。
两个 WebContents、partition 与 loopback 宿主仍隔离，不通过给中性页完整 preload 来复用窗口。

自动后台启动保持隐藏，退出或用户关闭交接中的窗口会撤销后续显示；已退休中性窗口迟到的
ready-to-show 不能重新显示界面。交接不恢复托盘或调度轮询，也不修改任何后台准备状态。

### 静态首屏与图标

中性窗口与普通、首次安装及升级的静态首屏直接内嵌同一份本地图标 PNG，显式优先加载并
同步解码，不等待 React 导入或独立图片请求。开发与打包入口共用该构建投影，避免相对地址
落入开发服务器的 HTML 回退，或在柔光动画结束之后才加载图标；原有 CSP 与资源宿主边界不变。

### 各路由的真实进度

首次安装显示四步；需迁移升级显示六步：
“备份历史 → 创建用户目录 → 检查运行资源 → 准备本机文件 → 恢复会话 → 完成启动检查”。
引导共用品牌、步骤栏、当前操作、用时、进度和折叠诊断。
普通启动显示紧凑品牌、当前操作及五项独立状态：“打开应用数据”“加载启动配置”
“启动 AI 引擎”“连接本机服务”“加载工作界面”。真实依赖仍按顺序准备，后面三项
可同时进行，不使用序号或唯一当前步骤表达并发工作。Main 在内存 `tasks` 中分别上报
数据、配置和集成任务的 waiting/running/complete/failed；旧快照不可变，正常进入 Ready
不自动补齐尚未完成的任务，Ready 后只允许已运行的任务收尾。

引擎与界面状态不写入
这份 Main 任务投影，继续由各自实际所有者提供。
AI 引擎只在实际 `EnginePhase.Running` 后显示成功，工作界面只在 Renderer 自身及首个
工作区就绪后显示成功；Main `Ready` 或发起异步启动不能替代这两项证据。
插件加载属于引擎启动，不单独推断所有可选插件都成功。引擎失败保留诊断、重试及
设置访问，不额外阻塞应用就绪。成功项保留对号，失败项显示叉号，其他项显示进行中或等待。
HTML 首屏和加载占位页也显示相同五项，仅呈现已知事实，不猜测尚未取得的 Main 状态。
普通启动仍无运行环境检查项或宿主原生预检，数据与配置行表示实际加载，不能从旧的
串行 completedSteps 推算并行任务成功。

本机服务的各项初始化失败会汇总为独立失败行，
可选服务失败不把已运行的引擎或已加载的界面改成失败，也不永久阻塞设置访问。
Main、Renderer 或引擎失败时提供诊断详情与已有 Main 日志目录入口；调用失败显示反馈。
日志入口沿用系统文件管理器定位接口，不具备系统窗口实际打开成功的回执。
正常升级安装显示五步：“检查并更新数据库 → 载入已有数据 → 检查运行资源 →
准备本机文件 → 完成启动检查”。数据库检查、备份、更新和复验均显示真实操作，
不会因计时、动画或子进程启动成功而推进。HTML 首屏、React 引导和窗口交接使用同一冻结路由。
恢复流程沿用已确认的进度，不回退到未完成的备份步骤；常规本机就绪检查仍会执行。

### 动画与窗口时钟

“柔光汇聚”使用本地图片、渐变、transform 和 opacity：中心标志可见，柔光汇聚后移动至品牌位置，
内容与步骤依次进入，入场时长 1280ms。视觉时钟与总启动耗时分离：真实路由文档的
preload 第一次同步读取时，Main 才设置一次视觉起点，避免资源清单加载耗尽动画时间。
窗口专属只读通道只接受所属 WebContents 主 frame，销毁即移除；中性窗口不读取该时钟。
preload 仍只暴露现有 entryStartedAt 数值，优先使用该窗口通道，其次兼容显式旧启动参数，
最后使用当前文档时间。后续临时窗口、主窗口、reload、HTML 与 React 继续同一视觉时钟，
不重播入场；总启动耗时仍使用原始 startedAt。

动画不推进任何后台步骤或伪造百分比。

### 首页揭幕与错误阻断

Main、App 和首个工作区实际就绪且入场完成后，以 640ms 双层幕布揭示首页；完成前保持 inert 与 aria-hidden。普通启动按[执行准入](#普通启动与执行准入)允许引擎和集成继续后台准备，首次安装、迁移与正常升级保留原有维护和引擎检查。迁移结果页还需用户明确进入。

错误立即停止入场或揭幕并恢复错误页，迟到动画完成不能开放交互。动画沿用现行 Windows 策略，不因减少动态效果设置停用。全部展示资源随包交付，不依赖公共网络、字体 CDN 或首次下载。

## 初始化错误

App 向门禁传递真实 Error，诊断保留错误码、堆栈和 cause；友好文案与诊断分开。
设置、主题、语言、模型和会话各自报告真实活动，操作开始时同步上报，避免同一事件循环中的错误
被错误记在上一个步骤。关键配置读取失败不再当作“没有配置”，也不以默认值覆盖未读设置。

语言文案本地提供。系统语言读取有本地回退，语言偏好写入继续使用原配置队列，但不阻塞界面就绪。
已初始化的非法语言值回退到英语并异步修复，不能将不支持的字典键传给界面。
不再因语言偏好等待超过五秒而要求用户手动重载；真实不可恢复错误仍有重载/重启和诊断入口。

## 所有权与模块

Main 和 Renderer 各自以 `startup/` 为启动模块，按以下领域组织：

| 子模块           | Main                                                         | Renderer                                     |
| ---------------- | ------------------------------------------------------------ | -------------------------------------------- |
| `routing`        | 只读安装判定、持久阶段记录、升级事务                         | 固定启动模式、就绪门禁、实际活动上报         |
| `history`        | 一致性备份、历史投影、原生导入与身份校验、缺失目录恢复       | 正文缺失提示、选择新的工作目录               |
| `initialization` | 初始化进度与错误、初始化 IPC                                 | 共用准备引导、普通启动页、柔光汇聚动画、诊断 |
| `upgrade`        | 当前发行包的离线数据库检查、维护、备份、复验与子进程生命周期 | 复用共用引导的正常升级展示                   |

Main 的实现位于 `src/main/startup/`，Renderer 位于
`src/renderer/app/shell/startup/`；原有 core/app 和 IPC 入口保留为薄转发。
窗口工厂仍负责安全窗口创建，preload 只传递 Main 冻结的模式、时钟和显式 IPC。
产品 SQLite 保存标题、索引与映射回执；正文由 OpenClaw 原生存储持有。
路由冻结后先创建初始化快照并注册状态、诊断与恢复 IPC，此阶段不访问要求 Store 就绪的
引擎 getter。普通启动的引擎准备管理器在 `initStore()` 成功且退出检查通过后、主窗口创建
之前构造；数据或引擎管理器构造失败仍能从既有状态接口取得原始失败，不以缺失 IPC 覆盖原因。

## 当前验证边界

主页可操作与 AI 可发送是两个时间点。已有观测仍有 Gateway 超过一分钟的启动；
尚未证明达到 30 秒完整启动目标，也未重新测量最终安装版完整启动/退出。
观测依据与剩余定位维护在[Gateway 启动耗时计划](../../plans/gateway-startup-latency.md)。
窗口立即隐藏不代表原生安全清理已结束，完整桌面合成画面是否闪烁仍需现场检查。

真实企业 JSONL 覆盖安装、客户现场、无缓存且公网阻断的冷启动，以及持久阶段中断、
断电、磁盘不足/占用故障尚未完成现场验收。支持按钮的目标解析和 IPC 有回归，
真实系统目录与任务管理器的打开效果仍需现场验证。客户原始异常日志尚缺，受控环境
复现与修复不能证明客户问题的唯一根因。以上既有测试与演练不是本次文档整理重新执行的结果。
