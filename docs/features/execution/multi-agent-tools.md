# 多 Agent 工具与交互

Agent Team 的任务成员、群聊成员和 Swarm Workflow 的执行节点都沿用原生工具执行与权限链。
普通产品会话、插件创建的原生会话、产品界面所显示的来源是三个不同的身份，不能互相替代。
工具是否允许执行取决于实际调用者；界面归属只决定在哪里展示请求和页面。

## 执行与来源

工具通过公开的版本 2 工厂取得真实原生会话和当前调用检查，不能从模型参数、会话名后缀或
提示词取执行身份。浏览器还要求最终工具权限、精确 run/toolCall 与会话 incarnation 均有效。
Ask User 的待答请求保留原始调用身份；回答、取消和默认值超时都只能结算该请求。

可选业务插件通过 Main SDK 的 `resolveExecutionSession` 提供自身已记录的关联。Team 查询
真实成员及群聊执行关系；Workflow 查询自身节点、批次与原生执行收据。宿主核对插件当前
准入代次、关联产品会话和冲突认领。此端口不传消息正文、不建立第二份 transcript，也不
把来源的权限、工作目录或成功终态赋给子 Agent。

插件负责证明当前执行的具体来源，Team 的成员独立聊天、incoming 投递与群聊规则见
[Team 集成](../../plugins/extensions/agent-team/integration.md)，Workflow 的节点与批次见
[Workflow 集成](../../plugins/extensions/swarm-workflow/integration.md)。接纳待确认时保留
待答请求并拒绝浏览器创建，明确回执到达后重新投影，不在错误会话创建页面或重放工具。

来源可能没有产品会话。例如单独创建的 Team 群聊不一定有来源聊天，不能拿房间 ID 冒充
产品会话，也不能把它挂到用户当前聊天。插件关闭或代次撤回时，旧来源关联不能继续放行
新的界面效果；原生仍负责已存在执行的收据和清理。

## 浏览器

当前主界面消息会话新建侧栏浏览器页面时，自动展开侧栏并选中新 Tab。以下后台展示规则
适用于侧栏中的 Team 会话（包括主 Agent）、子 Agent、Workflow 节点及其他未选中会话；
按受信执行归属区分，不以 Agent 的角色、名称或提示词判断。

每个子会话 incarnation 使用独立资源身份，持有自己的页面、目标、元素引用、上传/下载
工作目录及执行租约。有真实产品来源时，额外的显示身份将页面放进相应侧栏；显示身份
不参与工具目标注册和执行授权。取消或回收一个成员的资源不能关闭同伴页面。

侧栏当前展示的 Tab 由用户选择。成员新建页面、切换自身工具目标或执行点击、输入等操作，
只更新自己的页面及逻辑活动目标，不展开侧栏、不切换用户正在看的群聊、文件或浏览器 Tab，
也不获取窗口或键盘焦点。新页面仍会加入来源聊天的侧栏，用户可以主动选择查看；切换查看
不会重建其他成员的页面。这里的后台操作仍使用原侧栏页面，不等同于 `headless: true` 的
独立隐藏窗口，不改变页面创建模式、来源权限或共享登录状态。

隐藏、未选中或正由 Agent 操作的网页派生新标签时，继续保留当前选择。用户在当前可见、
未由 Agent 控制的网页点击新页面链接或使用“在新标签打开”时，自动选中新 Tab；该页即使
来自 Team 或 Workflow，也按当前人工浏览状态处理。Ctrl/中键后台打开继续保留当前页，
Main 捕获的后台展示提示在 Agent 操作结束后迟到也不会升级为前台。侧栏“+”新建和主动
选择 Tab 继续切换；已有隐式默认选中项会写回当前显示状态，后台新增页不能改变它。

Native 正常释放明确要求保留的侧栏页继续供用户查看，普通元数据刷新不能将其误关。
这不保留旧 run 的操作权；新 run 重新核对来源，不继承保留标记。插件生命周期撤回、
删除或新运行改变同一资源的显示归属时，继续精确清理旧页。

同一 run 的并行首次工具调用可能同时等待来源解析。后完成的调用必须重新核对已成立
资源的完整作用域、原生插件及显示归属；归属不一致时只拒绝迟到调用，不能借用或关闭
另一调用刚成立的页面。跨 run 复用同一 incarnation 资源时，即使旧 run 已撤回、尚未
释放，也必须在显示归属变化时精确退役旧页，不能把旧页带入新的来源。

隐藏页面仍须完成精确资源、目标及操作的交互确认；查看另一页面不使确认失效。用户标注、
检查或录制的保护范围继续生效，某一成员的页面忙碌不遮罩另一个成员当前展示的页面。

已显式采用的原生子会话按其完整持久绑定解析，不能因它的 key 不属于普通聊天格式就
拒绝工具。独立群聊没有可定位的产品来源时，可以显式使用 `headless: true`；前台请求会
说明缺少来源，不能偷偷切成后台或抢占当前聊天。

下列共享行为仍然存在：

| 资源                        | 行为                                                              |
| --------------------------- | ----------------------------------------------------------------- |
| 不同页面                    | 可以并发执行，各自持有目标和元素引用                              |
| 同一实际页面                | 按页面串行执行命令；导航仍可能使先前元素引用失效                  |
| 同一浏览器配置              | 共享登录、Cookie 与站点存储；关闭一个 Agent 不清除共享账号        |
| 不同浏览器配置              | 使用现有独立 partition；是否有对应账号由用户配置决定              |
| 没有产品会话的子 Agent 页面 | 没有可安全复用的父会话停止/继续操作；不提供会误操作来源的接管按钮 |

浏览器配置和页面控制详见 [浏览器设置](../browser/browser-settings-design.md)。

## 问答与权限审批

不同原生会话可以同时等待问题。请求 ID 是回答的目标，同名问题、相同选项和相同来源
标题不能合并请求。界面逐个展示并保留每份草稿；来源信息只来自原生身份和已核实的
插件关联。权限审批优先展示，问答暂时隐藏后恢复已有输入。

普通问答按当前会话筛选，插件可将自己的问答定位到对应视图或窗口；同一可见来源下的
并发问题可以切换。没有产品来源的 Native-only 问题独立展示，不挂到用户当前聊天。

停止一个 Agent、取消一个问题或回答一个请求，都不能结算另一个 Agent 的请求。重连
读取成功的当前 pending 快照；读取失败不表示请求已消失。旧 incarnation、过期调用和
已撤回的业务来源不能通过旧弹窗恢复执行权。

同一道问题从多个窗口提交时，Main 在等待来源核验前取得该精确请求的独占答复权，
竞争提交明确失败，其他问题仍可独立提交。答复 RPC 的失败或非法回执不能证明 Native
没有收到答案：此时只读取一次 pending 列表，不重发答案。只有失败后发起的权威读取
确认相同请求、原始来源仍在等待，才允许用户再次显式提交；旧的在途快照不能解除该
保护。请求已消失时撤回弹窗，读取失败则继续保留未确认状态。下一次用户主动提交
会先重新只读确认；确认失败时不发送答案，不依赖后台轮询或重启恢复。

`exec` / 插件审批继续由原生 request ID、期限和允许的 decision 集合约束。单次批准不转给
另一个成员；权限模式也仍属于实际原生会话。关闭弹窗、停止确认和空闲快照都不表示批准
或全程完成。详见 [会话权限](openclaw-permission-management.md)。

部分 managed run 的原生 exec 审批不返回 session ID。这类请求仍可单次批准或拒绝，但
界面不会提供“本会话允许”，也不会拿另一工具或当前会话的 ID 补成授权证据。

审批列表和会话授权的自动批准绑定发起读取时的实际客户端、连接代次与响应上下文。
每次跨异步等待后的处理都重新核对这些绑定；旧连接的快照不能向新连接发送批准，
也不能把旧请求重新广播到界面。批准失败的文本不构成请求已终结的证据，界面只按
成功答复、原生 resolved 事件、成功读取的当前快照或真实期限移除请求。

## 同类实现对照

本轮参考本地 `hermes-agent` 的 `dce1e9b375` 源码，重点核对并发交互和资源归属。关键差异如下：

| 领域 | Hermes 的做法 | 本软件采用的边界 |
| --- | --- | --- |
| 子 Agent 问答 | 委派工具集默认排除 `clarify`；桌面问题状态按 session 存一份 | 保留子 Agent 问答，按 request ID、精确原生来源和调用代次分别保存、展示与结算 |
| 权限上下文 | 使用 `contextvars` 传递 session/turn/toolCall；避免多线程共享进程环境变量 | 只认原生工具调用身份与已核实来源，不从全局环境或当前前台聊天推导授权 |
| 危险命令 | CLI worker 回调默认拒绝，可配置为单次自动批准；Gateway 另走 session 队列。同文并发请求的一次批准只归请求 leader，followers 需重新审批 | 继续支持各成员独立人工审批；单次授权不转给另一成员，相同命令仍分别审批 |
| 浏览器资源 | 子 Agent 使用自己的 task/session 身份；创建、超时回收与控制交接重新核对资源对象及租约 | 独立资源、目标及操作租约；逻辑工具目标与用户当前侧栏选择分开，不互抢前台 |
| 停止与清理 | 取消按所属委派关系传播，资源按拥有者回收 | 精确取消本 run 的请求与资源，并保留实际全程终态及清理证据；不连带结算同伴 |

参考入口为 `tools/delegate_tool_toolsets.py`、`tools/approval_context.py`、
`tools/delegate_tool_config.py`、`tools/approval_gateway_wait.py`、`tools/browser_tool_session.py` 和
`apps/desktop/src/store/clarify.ts`。限制子 Agent 能力能够减少交互竞争，但不能代替这里
需要的并发隔离；本轮因此保留现有能力，补强等待期间的归属核验、答复互斥和连接围栏。

## 其他工具的边界

| 能力                           | 当前边界                                                                                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件、执行、MCP、技能          | 沿用调用者的实际原生策略、沙箱及工具配置；不会因为属于 Team/Workflow 而一律关闭                                                                                     |
| Workflow 规划、交付            | 业务明确使用 `disableTools` 的阶段继续保持该策略；不能为补子 Agent 工具而取消                                                                                       |
| 终端                           | 绑定实际子会话，重连使用 attach；不借用父会话 PTY 或重放不确定输入。尚未采用为产品会话的 Workflow/独立群成员没有单独打开 PTY 的产品入口，普通 `exec` 不受此入口限制 |
| 同一项目文件                   | Agent 可能共享路径；页面/请求隔离不等于文件内容无写冲突，需要任务本身协调                                                                                           |
| 电脑控制                       | 操作同一系统桌面时仍共享系统焦点、鼠标和窗口，不承诺物理桌面隔离                                                                                                    |
| `show_widget`                  | 原生要求真实 viewer 的 `inline-widgets` 能力；公开 managed-subagent 接口没有对应客户端能力传递，不能伪造客户端声明开放工具                                          |
| 跨会话发信、继续委派、管理工具 | 继续服从原生子 Agent 限制和插件自身范围，不通过来源映射放开                                                                                                         |

外部客户端提供的动态 MCP 仍需要该原生 key、session ID 的真实客户端租约与审批，不能
通过界面来源关联继承父会话的租约；静态 MCP 配置继续由 Native 工具策略处理。

## 验证

浏览器与问答的插件单元测试覆盖当前调用校验、独立请求、取消和 incarnation 撤回；宿主
边界测试覆盖来源冲突、插件准入撤回、资源与显示身份分离，以及审批暂停问答后的草稿。

`scripts/test/openclaw/multi-agent-tools.native-smoke.mjs` 是显式运行的隔离 Gateway 验证，
使用锁定产物自己的 Node、本地合成模型、独立配置/端口/项目 Git 仓库，拒绝公网访问。
它验证多个真实 managed run 的浏览器工具准入、同文独立问题、错源/重复/取消后答复
拒绝，以及单个 run 取消。A 的审批与 B 的待答问题同时存在；A 获批并达到真实全程
终态后，B 仍须先回答自己的问题，再取得相同命令的独立批准，才能执行。
其中浏览器使用确定性 Main 传输响应，不声称验证了真实网页操作或账号隔离；真实页面
资源归属由宿主浏览器边界测试单独覆盖。合成模型也不证明真实模型会选择正确工具。

显式浏览器验证使用 `node scripts/test/browser/verify-background-browser.cjs --sidebar-tabs`，覆盖真实 Electron guest 的独立输入、按键编辑与提交、隐藏页操作、当前 Tab 和用户焦点保留。它使用生产 Main 输入与焦点实现；工具事件入口、侧栏组合和初始 owner 文档焦点为合成边界。默认模式另覆盖后台输入、截图、共享登录、上传及精确清理。

以上入口与单元测试分别说明自身环境和边界。历史测试数量、逐轮审查与修复过程由 Git 历史追溯；真实模型、正式安装包、其他平台以及前述共享系统资源仍需在对应环境验收。
