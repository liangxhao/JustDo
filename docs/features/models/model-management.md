# 模型管理：能力目录与运行选择

设置中的模型页统一管理在线语言、决策、语音识别、语音合成、语音对话、图像生成和原生视频生成。实时转录属于“语音识别”，完整双向语音对话使用独立“语音对话”标签；流式音频输出仍属于“语音合成”，不按协议数量新增标签。语音识别、语音合成的供应商列表各有一个“内置模型”入口，集中列出对应离线模型及下载、安装进度、失败重试和删除操作；仅在用户手动点击下载后安装模型。设备和实际使用模型的选择留在语音设置或扩展齿轮设置。视频仅支持本地 OpenAI 插件中的兼容协议适配器，服务地址和模型由用户配置。

## 1. 目录不等于当前执行模型

Provider 目录描述可选择模型，应用默认决定新用户会话，session override 决定特定会话，专用助手可有独立模型。main 的旧档案 model 不再覆盖应用默认。

一次实际回复的模型以原生 progress/final 与历史为证据，不能用发送前选择覆盖 fallback 结果。model 字段可能含斜杠，必须保留 provider/model 身份，不能根据字符串前缀猜归属。

### 输入框选择与发送确认

输入框模型菜单展示用户已配置的模型，所有条目均可选择。应用模型目录只投影选择所需的身份、能力与认证信息，不接收或保存运行时重试等待状态及到期时间。选择立即更新显示，同一会话未发出的中间选择可被后续选择替代；不同会话独立切换，较慢的旧选择不会覆盖同一助手最新选择的默认值。语言模型切换使用原生会话模型热更新，默认偏好只发布模型字段，不重启 Gateway；后台默认值应用不阻塞当前会话发送的权限准入。选择阶段不弹切换错误或回退显示，用户可立即点击发送；未完成的原生模型确认在发送后等待并计入首 token 延迟，不能误用旧模型。默认偏好待应用不作为保存失败或重启失败，也不回滚已保存的选择。

首发与后续回合的选择绑定、发送失败和默认值保存遵循 [Cowork 生命周期](../../architecture/04-cowork-system.md#4-后续回合与设置修改)。

应用写入和读取当前 `provider/model` 身份，不在启动时遍历助手以猜测裸模型的 provider，
也不恢复旧 `custom_N`／`CustomN` 引用。用户在当前设置中改名时仍按稳定 provider 身份
同步更新引用；当前 Gateway 返回的合法 builtin 原生模型 ID 别名继续保留。
模型能力通过显式 `capabilitiesConfirmed` 确认，缺失时不根据旧默认参数推测已确认。

## 2. 用户配置流程

1. 在对应能力页添加 Provider，填写名称、端点和凭据；语音连接还需选择接口协议，下面所有模型继承这一选择。
2. 手工添加模型，或执行发现后与已有模型合并。
3. 配置能力所需选项；语音模型只配置模型标识、音色等参数，实时对话另需输入转录模型。不同协议分别添加连接，不在每个模型重复选择协议。
4. 支持默认选择的能力选择默认并保存，由 Main 应用到原生配置；语音识别、语音合成和语音对话页面只管理模型目录，不选择当前用途实际使用的模型。
5. 本地语音模型在“内置模型”列表下载，在语音页或扩展齿轮页各自的下拉框选择；两处均提供跳转到对应内置模型列表的“管理模型”按钮。语音页引用在线目录中的端点、凭据和模型，不再重复编辑 Provider；朗读模型和音色在保存设置后生效，试听当前新选择前须先保存。

### 默认模型的选择、取消与导入

决策、图像生成和视频生成共用紧凑的默认选择界面：顶部仅展示一行说明，目录为空时提示添加供应商和模型，有模型但未选择默认时提示在模型列表中指定。每类最多一个全局默认，供应商列表标记其来源，模型行标记具体默认；其它供应商保留的 `defaultModel` 只是目录内的模型记忆，不代表全局默认。首次打开优先定位默认供应商，显式指定的供应商定位优先；后续浏览不改变选择。模型行提供独立的“设为默认”和“取消默认”操作，修改仅更新草稿，统一“保存”按钮旁提示默认选择待保存。取消默认保留目录和凭据；新增、发现模型以及保存未选择的目录不会自动设默认，删除默认模型或供应商会清除全局选择，不自动替换。

导入这三类目录时，明确指定的默认选择按供应商名称映射恢复；没有指定默认时保留当前供应商与模型的完整选择。若导入覆盖后原默认模型已不存在，则清除全局选择，不使用导入条目中记忆的其它模型替换。

非语言能力目录初始为空，不预填公共厂商或猜测模型。名称遵循原生安全格式、保留名与大小写不敏感唯一规则；改名使用产品稳定身份识别。

### 内置语音目录与消费页面

STT、TTS 扩展齿轮与语音页共用在线模型目录；各用途分别保存模型引用、兼容选择 ID 和需要的音色选择。扩展选择与麦克风、回复朗读、实时对话互不覆盖。接口协议统一在模型设置中配置，消费页面只选择模型和必要音色，不提供接口下拉框。未选择模型时不显示接口行；已解析的接口只读展示，旧目录未配置或选择失效时提示前往模型设置。在线管理按钮定位当前服务，本地管理按钮定位内置目录，返回保留两种模式的草稿。输入框可使用录音 HTTP 或实时转录连接；附件 STT 只接受完整录音/文件转写连接，不能借用实时麦克风会话。在线 TTS 使用 HTTP 合成连接。目录存在和原生能力已注册都不等于目标服务已经连通。

语音设置的输入、朗读和实时对话选择均保留草稿，统一保存后生效，取消不改变实际配置。STT/TTS 齿轮通过各自独立保存事务应用；保存目录、下载模型或启用语音都不改变工具插件的明确启停选择。

设置中的“语音输入”统一包含“语音转文字”和“语音对话”两个编辑标签，共用麦克风选择与基础检测，各自保存启用状态及模型参数。标签切换不改变启用状态，两个用途可同时配置；实际采集互斥。转文字仍选择识别模型，对话仍选择独立的对话模型和音色，普通回复朗读仍选择合成模型，不因界面整合而合并模型目录或接口配置。

内置语音模型是固定目录视图，不写入在线供应商配置、默认选择或导入导出数据。下载不修改语音模型选择、扩展模型选择及其启停状态；语音页与扩展页继续分别保存原有选择。插件齿轮跳转期间隐藏对话框，返回后保留未保存的选择；语音页在同一个设置实例中切换页面，保留设置草稿。下载继续由 Main 持有，离开列表不会取消下载，回到任意消费页面时通过现有状态查询和事件更新就绪状态。

内置模型列表采用两行排版：第一行短名称与量化标记，第二行语言、完整音色数及下载大小。列表不重复显示就绪说明或完整模型 ID；下载、重试、删除使用带提示及无障碍名称的图标，下载时显示实际进度。点击名称打开详情，展示模型 ID、语言、运行引擎、大小及完整音色列表。完整音色目录、源编号与有依据的语言/性别/口音由[语音功能](../speech/voice-and-transcription.md#3-离线模型与安装事务)维护，模型详情、语音页和扩展齿轮共用，不推测缺失资料。详情提供名称/原名/原生编号搜索、按实际可用类别筛选及逐行试听；筛选保留原始顺序与原生编号。详情不保存模型或音色选择。

内置音色试听仅在模型和本地运行时就绪时可用，使用对应语言的固定短样句，不依赖回复朗读或插件启用开关。关闭详情、改变筛选、切换音色或模型失效时停止播放并取消未完成的本地合成；模型仍在下载时可以浏览完整音色资料。

### 语音接口绑定与已有配置

服务显示名是连接别名，不决定协议。旧目录的 `models[].bindings` 每项保存稳定 `id`、合法 `protocolId` 和必要模型参数。已有有效选择继续读取并只读展示，未明确的旧绑定需在模型设置中配置统一协议，消费页面不自动选第一项或唯一项。废弃兼容字段或未知协议不能作为旧 ID 别名继续执行，需要用户重新配置。新连接统一从供应商继承协议，不再逐模型配置接口。

支持的通用协议为 `openai-transcription-http`、`openai-speech-http`、`openai-transcription-realtime`、`openai-voice-realtime`。协议由用户显式选择，模型和音色 ID 由用户填写或来自服务实际目录；厂商名、域名或模型前缀不触发接口切换。未知协议和废弃兼容字段明确拒绝执行。

旧目录缺少 `bindings` 时按消费用途保留已有语义：输入框采用 Realtime 转录，附件工具采用 HTTP 转写，TTS 采用标准 Speech。显式空数组表示尚未配置接口；新目录没有所选绑定时不可执行。导入旧目录或移除绑定时，仍存在的模型保留失效的显式绑定 ID，避免清空后意外转为 legacy 协议；用户须在模型设置中修复配置。重复选择同一模型不重写已有别名或失效选择。发现模型只添加目录项，不为新模型推断接口能力。

本地 SenseVoice、Whisper、Kokoro、AISHELL3 VITS 和 Piper 继续使用现有运行时、模型身份、下载目录和音色 sid。增加网络协议不会重复下载模型、清空本地选择或在在线失败时自动回落本地；本机自行部署的 HTTP/WS 服务仍属于显式服务接口。

## 3. 原生配置落点

| 能力     | 运行入口/位置                                     | 隔离要求                                                             |
| -------- | ------------------------------------------------- | -------------------------------------------------------------------- |
| 语言     | models providers 与会话模型                       | builtin 与用户 provider 分开                                         |
| 决策     | agents.defaults.decisionModel                     | TypeSafe serviceUrl 与凭据独立于聊天；详见 [Jev](../../plugins/extensions/typesafe/decision-evaluation.md) |
| 录音识别 | Main 录音 HTTP 服务                              | 从已保存模型和绑定解析，窗口/frame/requestId 与配置代次隔离 |
| 实时转录 | openai.config.transcription、talk.catalog / session API | transcription-only Talk，不触发对话脑 |
| 实时对话 | openai.config.realtimeVoice、talk.realtime / session API | 独立模型/音色及输入转录模型，绑定已准备的原生助手会话 |
| 工具合成 | tts.providers.tts-local-cli、受管 persona         | 本地/在线模式及 voice 由插件齿轮独立选择                             |
| 在线朗读 | runtime-services.config.replySpeech、受管合成 RPC | voice 属于具体模型，请求内配置不覆盖工具                             |
| 图像生成 | agents.defaults.mediaModels.image                 | image-openai 配置域                                                  |
| 视频生成 | agents.defaults.mediaModels.video                 | video-openai 独立配置域，由 openai 插件提供                          |
| 图像理解 | agents.defaults.imageModel                        | 不等同图像生成                                                       |

原生 image 使用能力限定的配置视图，保留 manifest 的 canonical provider ID，不改写语言模型的 models.providers.openai。多个能力同用一种协议也不能互相覆盖 endpoint/key。

图像设置发布独立配置域时显式声明 `models: []`，满足原生自定义供应商校验；图像模型及其 fallback 引用仍由 `agents.defaults.mediaModels.image` 持有，不加入语言模型目录。保存使用原生配置合并，不清除独立域中已有的模型声明。

应用管理的语言模型供应商（包括内置和自定义）统一投影 `models.providers.<id>.request.allowPrivateNetwork: true`，允许其模型 HTTP 请求使用应用或用户配置的内网服务或代理 Fake-IP 地址。现有及以后新增的已启用供应商在启动、保存和认证同步时自动获得该策略，无需逐域名维护；手工修改原生配置不是持久设置入口。该授权覆盖对应供应商的模型传输及原生重定向，不是仅限初始域名的豁免；登录换证、模型发现、记忆检索、网页、网络工具及语音／图像／视频独立请求沿用各自策略。内置模型的 JWT、SecretRef、轮换和退出清理不变；供应商改名的唯一端点匹配忽略这一统一的允许值，仍保留其他请求选项和显式拒绝的差异。

### 内网请求与公共兜底

原生 cyber-refusal 模型兜底不属于企业内网模型目录。Main 在完整、最小、设置保存、登录/退出的最终管理配置中显式设 `agents.defaults.embeddedAgent.cyberFailover.mode = off`，保留其他 embedded 策略及已有 model/cooloff 配置；不因上游默认 auto 而触发公共模型服务。

## 4. 发现与端点规范化

发现先尝试 OpenAI-compatible /models，缺失或为空时检查服务根 /openapi.json 中对应请求 schema 的默认值/enum。新 ID 合并而不删除手工模型。完整能力 URL 粘贴后去除已知 suffix，避免原生再次追加造成重复路径。

语音规范化保留部署路径与版本前缀，并识别已知 audio / chat / realtime 端点后缀。HTTP 语音和实时对话不接受 URL query；旧实时转录只兼容唯一的 `intent=transcription`，不开放 signed URL、deployment 参数或 query 认证。模型、协议绑定和音色元数据在归一化、保存和密码加密导入导出中保真。

请求具有 timeout/cancel 和上下文 generation；切换 Provider 或模型后旧响应不能覆盖新表单。模型发现成功只能证明目录接口，不证明执行协议完全兼容。

## 5. 协议支持边界

语音按通用兼容合同接入，不维护逐厂商适配列表。完整协议字段、运行入口与验证边界见[通用语音接口](../speech/speech-protocols.md)：

| 能力 | 当前请求与结果 | 运行边界 |
| --- | --- | --- |
| 录音/文件识别 | `/audio/transcriptions` multipart → JSON 文字 | 输入框走 Main，附件工具走原生 STT 插件 |
| 语音合成 | `/audio/speech` JSON → 音频字节 | 在线回复和工具使用原生 Speech provider，配置互相隔离 |
| 实时转录 | Realtime transcription 会话与音频事件 → partial/final | Gateway Talk relay，保持实际支持的音频格式 |
| 实时语音对话 | Realtime conversation 双向音频、轮次及工具委托事件 | Gateway relay、VAD 和强制助手委托，首版不开放浏览器直连 WebRTC 或手动提交音频轮次 |

HTTP 识别和合成当前使用完整、受限的请求/响应缓冲。尚未接入 ASR/TTS 的 SSE 增量消费、逐块 TTS 播放、音色克隆或描述式音色设计；HTTP chunked、SSE、真实麦克风流和双向对话不能互相替代。

音色目录可从服务发现或手填。模型没有预置音色时仍可登记和保留；执行采用显式 `voiceSelection: {kind: preset, voiceId}`，不省略音色或填入任意默认 ID。标准 Speech 和实时对话要求有效音色，实时对话另要求所选绑定的 `inputTranscriptionModel`，不借用输入框识别或公共默认模型。旧的默认音色配置保持不可用，需要用户明确重选；克隆和音色设计未接入。

本地 OpenAI 扩展提供这些兼容 provider，服务地址、模型和凭据均来自用户显式配置，不要求访问 OpenAI 官方服务。Main 录音识别不依赖 Gateway 可用，真实实时转录/对话及在线原生合成仍依赖当前 Gateway 注册和准入。未知或缺失配置明确不可用，不自动切换接口、模型、本地路径或公共服务。

### 视频供应商配置

当前原生不提供上述兼容视频生成器；应用将 `video-openai` provider 整合在本地源码版 `openai` 插件中；provider ID 和独立配置域保留。保存默认视频模型后使用视频能力，清空选择不关闭共享插件。“视频模型”与图像、决策等类别共用同一模型编辑组件：左侧供应商列表和添加/删除入口，右侧依次为显示名称、凭据卡片、模型列表；使用相同的模型添加/编辑弹窗、默认标记和密码显示按钮。标题不附加协议名称。添加自定义供应商后，填写 API 基础地址（包含服务实际使用的版本前缀，例如 `http://127.0.0.1:8000/v1`）和可选 API Key，再添加模型 ID/显示名称并选择默认模型。不预填公网地址或厂商模型；打开、编辑或保存页面均不请求模型服务。

仅点击“自动识别模型”时查询所配置服务的 `/models`，空目录时再尝试服务根路径下的 `/openapi.json`，支持 Videos multipart 请求体中的模型枚举；不会提交测试生成任务。完整 `/videos` 地址在失焦和保存时规范化为基础地址。所有视频供应商条目均使用同一个 OpenAI 兼容适配器；添加时只填写名称，不提供厂商选择或固定模型目录。

### 视频请求与不确定结果

该适配器使用 OpenAI-compatible 异步 Videos API：`POST <baseUrl>/videos` 以 multipart 提交 `model`、`prompt`、可选 `seconds` 和 `size`；通过 `GET <baseUrl>/videos/{id}` 查询 queued/in_progress/completed/failed 状态，完成后从 `GET <baseUrl>/videos/{id}/content` 下载视频。

支持文生视频、单张 PNG/JPEG/WebP 参考图片（`input_reference`，最大 20 MiB），以及服务支持时的 fps、num_frames、num_inference_steps、guidance_scale、seed、negative_prompt 参数；服务端负责具体模型参数限制。不声明视频/音频参考、音频生成或水印能力。接口契约参考 [vLLM-Omni Videos API](https://docs.vllm.ai/projects/vllm-omni/en/latest/serving/videos_api/)，协议兼容不要求访问 OpenAI 官网。

生成继续使用原生 `video_generate` 工具、权限和素材读取。所有请求使用已配置地址、原生 HTTP 策略与有界响应读取；仅对该受管适配器允许私网访问，拒绝重定向，不读取环境或聊天凭据，不重试结果不确定的提交。提交、查询、下载共用总超时（默认 10 分钟），视频下载遵循原生媒体大小限制。

Kie、Z.AI、Novita 不在受支持的视频提供方中，即使安装对应插件也不会出现在视频设置里。配置保存、导入和同步仅接受 `video-openai` 标记，其它提供方会被拒绝。

### 视频配置发布与回滚

保存的视频条目带有 `nativeVideoProvider`，由应用配置同步器在启动、设置保存及登录状态变化时投影到 `agents.defaults.mediaModels.video` 和原生 `models.providers.<id>`，并启用所选插件。非空 API Key 通过权限受限的 `extension-secrets.json` 文件 SecretRef 提供给运行时；Gateway 配置不包含明文凭据。清空视频适配器的 API Key 会移除其运行时凭据引用。该适配器的地址和凭据独立于聊天和图像模型。浏览其他供应商不会改变默认选择；多个供应商条目可保存独立地址和凭据，但仅所选默认条目投影到运行时。

取消默认视频模型、删除最后一个默认模型或删除全部供应商会清除受管默认选择，并停止使用视频能力；共享 OpenAI 插件保持启用，聊天、图像及语音能力不受影响。它没有预设默认模型，取消默认后不会自动选择一个模型。视频设置回滚只恢复视频默认选择和独立配置域，不覆盖共享 OpenAI 插件的启用状态或其它能力配置。导入导出沿用加密凭据流程并保留原生服务商标记。

插件清单不完整时，不推断插件缺失，也不启用新的服务商或发布凭据；设置明确清空默认模型时仍清除受管默认选择，保持共享 OpenAI 插件状态，保留其他插件注册与权限。

视频服务通过本地 OpenAI 的原生 provider 注册和受管设置接入；不恢复 9.6 的旧自定义视频配置、兼容读取或迁移。旧 media IPC 的 OpenAI 视频 primary/fallback 和任意兼容端点写入仍被拒绝，图像生成的独立端点不受影响。

## 6. 凭据、保存与错误

在线配置通过 preload 到 Main，不让 Renderer 直接管理 Gateway secret。builtin 使用短期 JWT 和空 apiKey 投影；用户 provider 保留自身配置及派生 SecretRef，具体保护见[安全模型](../../architecture/11-security-model.md)。

保存本地目录、应用原生配置和连接测试是不同阶段。失败应保留可编辑数据并说明阶段，不能显示“成功”后实际仍用旧 endpoint。当前 catalog UI 不提供任意 fallback 策略编辑。

设置统一错误与通知使用紧凑弹窗，正文可滚动、选择和复制，支持确认、关闭及 Escape，关闭后恢复操作焦点，不再占用页面顶部的大块红色区域；成功通知使用中性标题。语言模型自动识别失败同时保留实际 HTTP 状态和服务端错误正文（包括非 JSON 响应），JSON 解析失败不能将已收到的 HTTP 错误归零。未收到 HTTP 响应时说明模型服务连接失败的实际原因并保留原始错误码，不将内部状态 `0` 展示为 HTTP 状态，也不推断为 404。

语言模型目录为空和非空时使用相同的 Gateway 固定监听配置。首次添加自定义模型以及清空后重新添加模型沿用原生配置热更新，凭据通过 `secrets.reload` 确认；不会因补写监听模式触发引擎重启。保存仍需取得当前进程、生命周期及认证身份下的实际应用确认，未知结果不作为成功。

模型配置导出使用 v5 密码加密格式并携带供应商协议，仍读取 v4 旧目录；旧客户端拒绝新版本，避免丢失协议字段后错误执行。机器本地 `providers_export_key` 密钥及其旧
加解密载荷不再读取；产品设置也不解密旧 OS 密文或旧 builtin 占位符。builtin 凭据继续
通过当前内存认证与 SecretRef 提供，并在产品设置持久化边界清空。

## 7. 回归检查

验证同名/改名、手工模型保留、过时发现响应、完整 URL 规范化、多能力凭据隔离、voice 缺失、main 默认与助手 override，以及真实原生请求。入口在 settings/models、providers、mediaGenerationModels 和 onlineAsr/onlineTts IPC 及其测试。

语音定向自动化已覆盖供应商协议继承、旧多绑定与用途语义、显式绑定失效不降级、废弃配置拒绝执行、严格音色校验、导入导出、草稿保存、插件隔离和五种离线模型的既有选择；Main HTTP 测试覆盖请求归属、取消、代理准备后的发送前复核与迟到结果，Realtime 测试覆盖原生配置、会话身份、取消和媒体清理。测试使用合成端点或锁定 SDK，不等于真实设备、目标内网模型、代理部署和端到端延迟已完成现场验收。
