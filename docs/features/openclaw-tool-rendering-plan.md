# Tool 与消息显示增强计划

状态：内网 PC 版的音视频、Read/Write 高亮和 Apply Patch 文件分组展示已实施。

## 1. 目标与范围

仅增强现有消息和 Tool 调用的显示效果。补齐消息中的音视频显示，为少数常用文件工具提供更适合阅读的展示，其余复用通用展示。不做全工具专项适配，不考虑远程节点、云端能力或第三方平台集成，不新增文件定位、会话跳转或其他业务入口。

不改变工具执行、模型输入、权限、任务状态或消息存储；OpenClaw 继续拥有原生 transcript。媒体加载是必要的展示能力，但不会重跑生成工具，也不自动播放音视频。后续改动独立提交，不再合并到此前的 feature commit。

## 2. 当前实际实现

核对入口为 `src/renderer/libs/openclaw-chat/components/`：

| 对象 | 当前效果 | 缺口 |
| --- | --- | --- |
| 消息 | 文本、Markdown、图片；代码块、JSON 树、Mermaid、表格及引用展示 | 音频仍按附件展示；视频没有内嵌播放器 |
| Edit | `active-turn-timeline.ts` 按参数生成 Diff，支持统一/并排查看 | 继续复用，后续可靠结果包含 diff 时优先展示实际结果 |
| Exec 等命令输出 | `tool-output.ts` + `terminal-output.ts` 提供终端外观、ANSI 和部分纯文本着色 | 保持现有风格，不重复设计 |
| 其他 Tool | 工具名、输入摘要、指示灯；展开后主要是格式化文本、复制和长输出分页 | 文件内容与 patch 可以更清楚 |

`message-render.ts` 当前将非图片媒体映射为 audio/document 附件，没有音视频播放器；不能把“已出现附件”视为“已支持播放”。Tool 结果当前统一进入 `justdo-tool-output`，已有源码解析辅助函数不等于已经接入专项渲染。

## 3. 要做的增强

### 3.1 消息音视频（优先）

- 音频在气泡内显示紧凑播放器，支持播放/暂停、进度和音量。
- 视频在气泡内显示有界尺寸的视频播放器，支持播放/暂停、进度、音量及全屏；适配窄窗口。
- 优先使用浏览器原生媒体控件，不增加波形分析、转码、字幕生成等能力。
- 保留文本与媒体的原始顺序；历史消息和实时消息展示一致。图片继续沿用现有展示。
- 加载现有消息提供的本地媒体，通过既有授权路径读取；先核对本地协议是否支持 MIME 和音视频拖动进度所需的 Range 请求，确有缺口才补最小桥接能力。
- 不自动播放；不支持的编码、文件丢失或读取失败显示明确提示并保留附件信息，不显示空白播放器。
- Tool 结果已经携带图片、音频或视频时复用同一媒体组件，不按生成工具名称另造卡片，不从普通文本路径猜测并读取文件。

### 3.2 少数常用 Tool

| 工具/能力 | 增强方式 | 范围限制 |
| --- | --- | --- |
| Read | 文件名、返回的行号范围、内容代码高亮；图片结果复用图片预览 | 只显示本次返回内容，不额外读文件；正确显示截断和文件不存在 |
| Write | 将写入内容作为代码展示；有实际结果 diff 时复用现有 Diff | 区分输入内容与执行结果，不把失败显示成已写入 |
| Apply Patch | 按文件分组，显示新增/修改/删除/重命名，展开查看 Diff | 复用现有 Diff 组件，不读取工作区或新增编辑入口 |

不新增 Tool JSON 树；普通参数和结果保持格式化文本与原文复制，不增加树形切换控件。

Edit 和 Exec 保留并回归验证。Read/Write/Apply Patch 是此次仅需新增的专项工具展示，不扩展为会话、调度、浏览器管理或第三方平台卡片项目。

`tool_call` 包装调用只在目标身份明确时复用以上展示；适配原生 `id/args`，不改变包装调用的顺序与身份。未知结构仍显示原文。

## 4. 实现边界与源码依据

继续使用现有 Renderer 展示链路，不新增 Main/Redux transcript 缓存。保留“指示灯 + 实际工具名 + 输入预览”，不增加重复状态文字或“其它操作”分类。新文案提供 zh/en。

OpenClaw 源码核对版本为 `2026.9.6`，提交 `eb377ac59e6c9fd6c7705028034812becf00271b`：

- [read-tool-contract.ts](../../../openclaw/src/agents/sessions/tools/read-tool-contract.ts)：text/image/truncated/not_found；offset 为 1-based，cursor 是行内偏移，不能伪造完整行。
- [tool-contracts.ts](../../../openclaw/src/agents/sessions/tools/tool-contracts.ts)：write/edit 的 changed、diff、patch 等结果信息；缺少字段时不推测成功或变更数。
- [apply-patch.ts](../../../openclaw/src/agents/apply-patch.ts)：核对 patch 操作与实际输出后适配；无法解析时回退原文。
- [tool-search.ts](../../../openclaw/src/agents/tool-search.ts)：tool_call 的 id/args 包装契约。

[工具契约目录](openclaw-tool-contract-catalog.md) 仅保留为前期源码调查资料，其中列出的远程和第三方工具不属于实施范围。目录不再作为待办清单。

## 5. 实施与验收

按三个小批次分别提交：

1. 消息音视频及 Tool 已有媒体的共享展示。
2. Read/Write 内容展示。
3. Apply Patch Diff，以及已有 Edit/Exec 的回归修正。

验收聚焦实际显示效果：

- 使用本地音频、视频、图片样例验证播放、暂停、进度拖动、全屏、窄窗口和加载失败；记录浏览器实际支持的编码，不承诺所有文件格式可播放。
- 同一消息在实时、历史重载后保持内容与顺序；切会话后旧请求不污染新消息，组件卸载停止播放并释放资源。
- 文件工具覆盖成功、失败、空内容、截断、大文件、多文件 patch；无法识别的结果始终可查看原文。
- 参数和结果的文本展示保留原文复制，不因解析而丢失重复键或大整数精度；代码、Diff 和媒体均验证浅/深色效果。
- 运行相关 Vitest、lint/build；使用真实 Chromium 样例检查视觉效果。实际 Gateway 未验证的部分明确记录，不以合成样例代替真实消息链路验证。
- 文档修改运行 `git diff --check`；架构或媒体读取链路确有变化时同步更新 `docs/architecture/15-chat-rendering.md`。
