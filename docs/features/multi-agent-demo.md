# 多 Agent 演示与验收

实施日期：2026-09-27。锁定运行时：OpenClaw 2026.9.6。

## 启动

```powershell
npm run electron:dev:isolated
```

隔离用户数据位于 `.work/multi-agent-preview/`。它使用独立的 SQLite、Gateway 状态和会话，不读取正式环境的会话历史。本次实测沿用本机已配置的默认模型及网络代理，案例内容全部为虚构数据。换一台机器需要在演示环境的设置中配置可用模型及网络；不要把此目录或其中的凭据、原始日志提交到 Git。

若运行时尚未准备好，先执行 `npm run openclaw:runtime:host`。修改本仓库扩展源码后，执行 `npm run openclaw:resources`、`npm run openclaw:precompile`，再重启 Gateway。首次冷启动受本机模块加载影响，实测一度超过 5 分钟；缓存建立后的启动约 22 秒。等待引擎就绪再开始展示。

## 演示顺序

### 1. 普通 SubAgent

新对话输入：

> 请实际使用 sessions_spawn 创建两个临时子任务，标签为演示-计算、演示-校验。两者独立核算：A 单价 120 元数量 3，B 单价 80 元数量 2，总价打九折。每个子任务给出计算与一个常见错误。不得联网或修改文件。等待两个原生子任务回报后汇总，必须实际调用工具。

预期结果：折前 520 元，折后 468 元。打开会话右上角“子任务列表”：可以看到两个任务；点击名称查看原生对话，点击信息图标查看详情。详情分别显示执行状态与结果回报状态，二者不能混为一谈。

### 2. 两级委派

在设置 → 配置 → SubAgent 中将最大拆分层级设为 2。输入：

> 请用 sessions_spawn 创建“演示-组长”。告诉组长：再用 sessions_spawn 创建“演示-二级核算员”，让他心算 (120×3+80×2)×0.9，不联网、不修改文件；等待二级核算员回报后，把结果转给主助手。你等待组长结果后简短总结。必须实际委派。

打开组长的任务详情，点击“查看下级任务”，进入二级核算员，再点击“返回父任务”。点击“打开任务对话”可以检查当前层级的原生记录。根列表先显示最近 50 条已结束记录，可继续展开；每层子任务使用原生分页按需读取。

### 3. Swarm 收集式任务

设置 → 配置新增独立 Swarm 区域，默认启用、组并发 8、存活上限 50、累计上限 200；后台 SubAgent 全局并发仍会限制实际运行数量。它不会启用平级 Team。

> 请真实调用 sessions_spawn 启动一个收集式子任务：collect:true，groupId:demo-batch，标签“演示-收集结果”。outputSchema 要求对象包含 total(number) 和 formula(string)。子任务心算 (120×3+80×2)×0.9，不联网、不写文件。你用 agents_wait 明确收集结果并汇总，不使用 sessions_yield。

预期结构化结果为 `total: 468`，formula 包含计算式。任务详情的投递状态为“不适用”，因为 collector 的结果由父任务显式收取，不走自动完成通知。

子任务列表在“进行中”和“已结束”各区内按原生 `swarmGroupId` 归组，组标题显示完整标识（过长时截断，悬停可查看）。跨状态的同一组会分别出现，已结束区的分组只覆盖当前已展示的任务；加载更多继续补充。普通子任务保持独立展示。任务详情、任务对话详情和下级任务显示所属 Swarm。分组仅使用 Gateway 返回的明确归属，不根据名称、父会话或消息正文推断；刷新后原生归属消失时，界面同步移除。当前没有独立的 Swarm 仪表盘或结果表格缓存。

### 4. 精确取消

> 请创建两个临时子任务：标签“演示-待取消”，要求写一篇不少于 3000 字的虚构旅行小说，直接生成正文、不调用工具；标签“演示-保留”，要求计算 7×8。主助手等待回报后报告两个任务状态，不要重建被取消的任务。长任务会由用户界面取消，这是预期行为。

长任务运行时，打开它的信息详情，点击“取消任务”。只取消所选 taskId；另一任务应完成并返回 56。原生拒绝、断线或结果不确定时，界面会要求先核实状态，避免盲目重复操作。

“重新投递结果”仅重试完成通知，不会重新执行任务。“忽略待回报结果”也不会删除原生对话。这两个入口只在可恢复状态展示；实际能否操作由原生接口裁决。

### 5. 长期助手平级交流

1. 在插件中启用可选 `agent-team`。
2. 设置 → 助手 → 新建助手，选择研究、实现、审查或写作模板。模板生成可编辑的职责和工作规则，保存通过原生 `AGENTS.md` 文件接口完成；失败可保留草稿并重试。
3. 为本案例准备“演示研究员”和“演示审查员”，均继承默认模型。
4. 新对话输入：

> 请演示长期助手平级协作，禁止 sessions_spawn。用 task_assistants 准备演示研究员和演示审查员；先只给研究员发任务：A 单价 120 元数量 3，B 单价 80 元数量 2，总价九折。请研究员核算并直接给审查员发结果；审查员复核后直接向研究员反馈一次，并显式向 main 汇报；研究员收到反馈后显式向 main 汇报，不再回复审查员。使用 task_assistants 返回的准确 sessionKey，不联网、不改文件。若发送被拒绝，直接报告错误并结束。main 收到双方结果后汇总。

检查协作图中的研究员→审查员、审查员→研究员两条边以及向 main 的回报；点击消息边读取原生消息正文。发送“已接受”不代表对方已完成，必须结合成员执行和最终回报判断。

不要将 `agents team create` 当成上述平级房间的替代物。当前 peer 发送仅支持省略 mode 或 followup；steer/notify/resume 不在本轮接入范围。

真实 Team 首轮遇到原生可见性拒绝。原因之一已实证修复：新版可将工具钩子和服务注册为不同插件实例，旧实现的临时授权保存在钩子实例内，服务侧检查不到。现在 Gateway 统一登记和撤销授权，仍限定源会话、准确目标 incarnation、运行身份与有效期；未放开 `visibility=tree`。修复后的同类任务出现双向 peer 消息且最终完成。

恢复检查中另外观察到一次 Gateway 无响应：生命周期事件后原生日志停止，多类 RPC 超时，重启后恢复；退出前没有正常 drain 日志。原进程退出后未取得 CPU 调用栈，尚不能认定具体插件或永久循环。该现象记录为待复现问题，不归为已修复问题。演示时如遇引擎无响应，可使用“重新启动 AI 引擎”，然后重新打开保留的会话。

本机截图及原生验收数据保留在 `.work/multi-agent-preview/`，不进入版本控制。失败投递重试/忽略、容量极限及所有故障组合尚未全部做真实模型压力测试；相关异常分支使用行为回归覆盖，不能等同于生产压力验证。

自动化结果：包含 SQLite 的相关回归 53 个文件、860 个测试通过；随后补充授权撤销 RPC 失败用例，扩展回归 45/45 通过。`npm run lint`、`npm run build`、`git diff --check` 通过。运行时本地扩展已重新同步并预编译。

### 后续稳定性优化（2026-09-27）

- 子任务刷新替换旧分页，避免已经消失的任务残留；刷新失败后重试仍从第一页开始。切换任务后忽略旧请求返回，操作状态核实同时校验 taskId 和 sessionKey。
- 用量暂不可用时保留上次统计并标明未刷新，提供独立重试；不会将可正常读取的任务状态标为失败。
- Team 停服后拒绝迟到的准入结果回填授权；结果回执必须匹配真实准入身份。撤销 RPC 失败及授权到期后的迟到回报均有回归覆盖。
- 本轮相关回归 13 个文件、128 个测试通过（含 Team 扩展 52 项）；lint、build、diff 检查通过。本地扩展已重新同步、预编译并重启。
- 对运行中的 Gateway 进行 CPU 采样并切换 Team 插件，55 次健康探测均成功，采样主要为空闲。之前的无响应未复现，仍不能视为已修复；采样文件仅保留在本机演示目录。
- 更新后的运行时真实完成第三轮 `13+29=42` 互审：仍为原来的 3 个成员，新增 6 次 accepted 发送，双向 peer 交流及双方向 main 汇报均可读取原生正文（6/6），最终全部空闲。本轮 main 催取了审查员的单独回报，因此不能声称模型完全按初始指令一次完成所有发送。

### 提交前独立审查

三路 Agent 分别审查 SubAgent 后端、Team 扩展与前端交互，并对照本地上游源码。修复了会话元数据读取失败遮蔽已验证任务详情、详情响应未精确核对 taskId，以及子任务对话抽屉缺失用量恢复入口的问题；新增对应行为测试。原生分页游标失效可通过当前层“刷新”从第一页恢复。

完整 `npm test -- --maxWorkers=2`：571 个文件通过、2 个跳过；5655 项测试通过、42 项跳过。独立审查后的定向测试另覆盖后端 75 项、前端 111 项、Team 扩展 52 项，均通过；lint、build 通过。此前 Gateway 无响应仍作为未复现问题保留，不因代码审查或测试通过而标为已解决。
