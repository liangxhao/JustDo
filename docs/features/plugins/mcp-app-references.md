# MCP Apps 引用接入约定

本约定配套 [MCP Apps 桌面宿主](../chat/mcp-apps.md)，说明通用侧栏引用及插件可选增强的最小接入边界。这里的内容关联是本产品受审查的本地集成，不是 MCP Apps 标准，也没有新增动态注册 SDK。普通外部插件通过标准 App 即可使用基础引用。

## 1 基础展示无需业务改造

基础引用指向已经由原生准入的当前 App 视图。宿主保留同一 iframe 和 AppBridge，管理标题、引用 Tab、定位、取消固定和会话暂停。插件继续使用标准 App SDK 和既有原生工具／资源接口，不需要实现侧栏组件或新增业务工具。

位置切换不要求新增 sidebar displayMode；插件继续消费原有模式和标准容器尺寸通知。宿主不能把应用自身的关闭、文件保存或其他业务动作解释成引用操作。

支持共用标题行的 App 可以声明可选展示能力
`experimental['ui/shared-header'] = { version: 1 }`，并消费同名 host context。
非空值 `{ height, left, right }` 表示顶部工具栏的高度及左右避让像素：隐藏重复标题，
把自身按钮和必要状态保留在中间区域；这些留白只影响工具栏，不应缩小画布。
`null` 或不支持该约定的宿主使用 App 自己的完整标题栏。不得据此推断来源、固定状态、
文件权限或业务成功，也不需要了解宿主侧栏、Tab 或菜单的实现。
按钮保持在原 iframe，通过既有标准 App SDK 完成操作；不向宿主发送任意方法名或 DOM。

宿主从认证原生描述取得服务、UI 资源、原始工具调用和所属会话，从原生目录取得图标和应用名称。插件不提供文件解析、snapshot/apply、撤销、自动保存或 AI 编辑能力，也能接入基础展示。

没有稳定业务身份时，只复用同一有效 native view；不能按相同标题、相同 URL、文件扩展名或相同 HTML 把不同视图合并。视图过期后的重新打开沿已有能力处理，固定偏好本身不能恢复内容。

## 2 可选的稳定内容身份

需要把多次工具结果或不同恢复视图关联到同一内容时，插件提供业务 contentId。它可以代表图表、工作簿、看板或结果集，不要求统一内容模型。

| 信息         | 提供者和约束                                                             |
| ------------ | ------------------------------------------------------------------------ |
| 来源命名空间 | 宿主从真实原生插件／MCP 服务及 UI 资源准入事实取得，不能由模型指定所有者 |
| contentId    | 插件在自己的来源命名空间内签发；持续修改保持不变，新业务内容使用新 ID    |
| title        | 插件的业务标题；只用于显示，不作为去重或授权依据                         |
| originViewId | 可核实的原始 native view 关联，不是任意可访问视图                        |
| 所属原生会话 | 从认证上下文和真实来源核对，保持 agent、sessionKey 和物理 sessionId 隔离 |

内容键由来源命名空间、原生会话与 contentId 共同构成。同一插件的不同服务或资源是否共享内容命名空间，必须由受认证的接入映射明确声明；宿主不自行跨服务归并。

viewId、连接 generation 和当前操作代次继续用于调用校验。身份恢复可能产生新 viewId，但只有原插件证明它仍对应同一内容时，才能沿用 UI 名称和序号。

同一内容的入口归并不等于替换旧实例中的数据。插件若没有实际更新协议，宿主只定位原实例，不能把另一个工具结果自动重新 load 进去或宣称已经同步至最新版本。

## 3 可选的操作关联和历史回执

插件若需要“已更新”等业务回执在历史接管后继续显示，应返回一份紧凑关联记录。原生实际工具结果是载体，完整内容仍留在该插件现有结果或存储路径中。

| 信息               | 用途                                               |
| ------------------ | -------------------------------------------------- |
| 关联类型标识       | 使用明确版本的本地约定，区分业务正文和宿主关联数据 |
| contentId 和 title | 关联目标与显示名称                                 |
| originViewId       | 关联已准入来源或已有认证恢复入口                   |
| operationId        | 标识该次业务操作，防止重复展示或误配回执           |
| 操作含义与确认状态 | 区分打开／更新等事实；更新成功必须已有实际确认     |

真实 toolCallId、run 身份、来源工具与所属会话从原生结果及认证上下文核对，不能由上述字段替代。仅看到一个 `success: true`、同名工具或 JSON 内容不构成授权。

对于原生历史会过滤的自定义 details，关联记录放在其可保留的有界可见工具结果正文中，并采用可严格解析的完整结构。它是定位索引，不含 HTML、完整 XML／工作簿、文件字节、秘密或宿主临时令牌。首期沿已审查的插件适配解析有界记录，再映射成通用展示类型；不新增动态注册 SDK 或任意正文 JSON 准入。

宿主只处理真实原生工具角色或既有严格准入的原生活动结果。必须核对实际工具来源、精确调用、当前会话和关联的原视图；有原生 run 身份时还须完全匹配。助手正文、Markdown 示例、用户粘贴、任意资源链接和 App 自报能力不会获得引用准入。

原生 MCP 结果核对真实 server／tool／resource 准入；独立插件工具由明确的受审查适配核对其真实工具名称、精确调用与来源，后续恢复再由原认证接口核验。正文自报的 pluginId、serverName、contentId 或 RPC 方法不能授予跨视图归并、恢复和成功声明。真实工具角色本身也不能证明输出属于另一个插件。

原生标准 MCP App descriptor 仍由原有准入路径产生。插件关联记录不能伪装 descriptor、凭空创建 native view，或恢复旧工具／文件／上下文权限。无法核实的记录保留普通结果显示，不创建交互入口，也不隐藏正常预览。

## 4 可选的恢复能力

需要失效视图恢复时，插件继续使用自己的认证只读适配或原生既有恢复功能，核对可见原生记录，再返回实际获准的预览。只恢复已经证实的原始或确认内容；具体是原始快照还是最新确认内容，由插件契约说明。

宿主引用不增加通用“重新创建内容”或任意 RPC 执行能力。没有合法恢复入口就显示不可用状态；不会为恢复而重放创建、打开文件、查询提交、保存或更新操作。

外部插件需要的可选映射必须通过受支持的原生结果、资源或已审查的认证插件能力接入。不得要求插件导入应用 src、访问私有 view registry、注入宿主脚本、增加第二个 MCP transport，或由模型填写方法名获得权限。公开能力不足时保留基础引用范围，不通过绕过准入实现增强功能。

## 5 插件接入步骤

1. 使用标准 MCP App，确认当前界面通过真实原生来源准入，布局变化和隐藏不会重置自己的状态。
2. 只需要固定当前界面时，接入到此为止，由宿主完成引用展示。
3. 需要跨消息同内容关联时，提供稳定 contentId、标题和可核实来源；明确哪些新建操作产生新 ID。
4. 需要稳定业务回执时，提供紧凑关联记录，并说明成功确认、冲突和未知状态的语义。
5. 需要恢复时，复用已有认证只读能力；明确不支持恢复的本地草稿和旧权限。
6. 运行通用接入测试及自身状态测试，确认实际 Gateway 历史和原生恢复路径，而非只测试完整模拟 details。

每个插件只实现自己确实需要的增强项。宿主不要求普通查看器实现编辑工具，也不要求查询结果实现版本或业务文档库。

## 6 draw.io 首个接入映射

draw.io 既有业务契约见[当前画布](../chat/drawio-current-canvas.md)。接入通用宿主时：

| draw.io 现有信息                | 通用引用用途                                           |
| ------------------------------- | ------------------------------------------------------ |
| diagramId                       | 映射为来源命名空间内的 contentId，不改现有图表 ID      |
| title                           | 内容标题；宿主负责默认名称、序号和位置文案             |
| 已核实的 source 与 originViewId | 提供内容来源关联，保持原生会话隔离                     |
| 实际应用 ACK 和成功更新收据     | 映射为已确认的更新操作，不依赖模型文字                 |
| 现有恢复 RPC                    | 沿公开 SDK 与原生记录恢复；宿主不解析 XML 或恢复旧授权 |

`drawio_diagram`、`details.diagramUpdate`、内容戳、XML 校验、单步撤销和冲突检测留在 draw.io 的业务适配与测试中。通用 Tab、标题、宿主实例容器和引用关闭逻辑不判断这些字段，也不要求其他插件实现它们。

现行宿主使用通用 `app-reference` 条目、`McpAppAnchor` 和引用 Tab，已移除专用 DiagramReference 展示分支。draw.io 业务工具和来源校验保持原契约。

稳定记录的类型为 `drawio.diagram-reference.v1`，放在成功工具结果的单个文本块中，JSON 最多 4096 字符；含 diagramId、title、operationId、toolCallId、runId 和已核实 source。完整 XML、内容戳和原收据仍在原生 details／插件存储中，紧凑记录不复制业务正文。插件只在真实应用 ACK 后返回该记录。

`update-result.ts` 拥有插件格式及校验；宿主 `native-app-reference.ts` 仅接纳真实 `drawio_diagram` 调用并映射通用字段，`plugin-content.ts` 从已准入 payload 核对内容身份、连接既有画布协议并执行已有认证恢复。新增增强插件应在该明确适配边界接线，不能向通用 Tab／布局添加业务判断。

恢复以原始 content/originViewId 和精确原生会话关联，同内容并发恢复共享一次读取。新 viewId 不改原内容来源，不与另一个原始来源猜测合并。恢复 preview 的别名只存在于当前认证绑定的弱关联中；返回原历史卡片定位同一恢复实例，不将它升级为原来的消息、文件或上下文权限。恢复界面不注册旧模型编辑目标；进一步模型编辑仍遵守插件独立的新准备规则。

## 7 接入验证与文档

至少验证：标准 App 无稳定 contentId 也可固定；同来源同内容关联正确；不同插件同 ID 不合并；消息和 Tab 名称一致；固定往返内部文档及本地状态保持；原生历史能保留关联；伪造／失败／未知记录拒绝；旧会话和连接代次拒绝；恢复不复活授权。

宿主用不包含 draw.io 字段的合成 App 验证基础能力，draw.io 用真实离线编辑器验证编辑器状态。后续表格、看板等插件以自己的业务状态增加测试，不复制 draw.io XML fixture。

通用实例与 Tab 测试归宿主；业务身份、结果和恢复测试归插件；实际原生边界测试归 integration。外部分发插件维护自己的实现和测试，不作为主工程运行依赖。

用户流程与生命周期维护在 MCP Apps 功能文档；本文件维护通用接入边界；插件专属文档只维护自己的业务映射与限制。
