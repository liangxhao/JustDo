# Plugin Hub：现行管理体验与能力边界

Plugin Hub 已整合插件管理，本文按当前行为重写。早期设计中的候选能力不再混在现行交互中；原生安装与事务见[插件系统](../../architecture/07-plugin-system.md)，市场合同见[市场适配](../../architecture/16-skill-marketplace-adapter.md)。

## 1. 页面如何组织

PluginsView 组合 skills、mcp、hooks、extensions、marketplace，各域服务、类型和组件就近维护。页面统一视觉与操作反馈，但保留每种类型不同 owner，不要求所有卡片都能启停、删除或更新。

系统与内置、用户安装、当前项目等归属用于展示；运行管理 scope 决定动作。例如 Extension 提供的 Skill 可属于用户安装，但删除仍需操作父 Extension。
启用状态由开关或加锁状态图标表达，卡片不重复展示“已禁用”文字；系统内置分组不重复展示“系统提供”来源标签。
Skill 的启停入口仅保留在列表卡片上，详情页不重复显示启用按钮或加锁状态图标。
系统内置扩展与用户扩展在实际目录可用时，都在详情页左下角提供打开文件夹的图标；系统托管的启停、配置和删除限制独立保留。
扩展来源标签统一使用“扩展”（英文为 “Extension”），MCP、Skill 与 Hook 共用同一无底色的紫色小字角标，放在头像右下角，适配深浅主题；MCP 与 Hook 角标保留进入所属扩展的入口。

用户安装与系统内置组内按名称固定排序：使用 `zh-CN` 比较规则，忽略大小写、数字按自然顺序排列，
名称等价时按唯一 ID 排列。该规则适用于扩展、技能、MCP 和 Hook，不随接口返回顺序或界面语言变化。
用户自建与用户扩展附带的 MCP 合并后排序；系统内置扩展保留可切换项在前、加锁项在后的优先级。

MCP、Hook 和 Skill 共用卡片容器：与扩展卡片一致，默认无边框、无阴影、背景融入页面，悬停或键盘聚焦时显示浅底色。MCP 使用紧凑排版，缩小内边距与行间距，描述放在名称下方并与名称左对齐；其它类型保留现有内边距与卡片间距。
统一图标和标题行、两行描述区；MCP 点击卡片直接打开参数编辑或只读查看界面，不再显示独立编辑／查看图标。测试与开关集中在标题右侧，测试只显示蓝色图标，与状态图标保持一致大小和点击区域，保留提示、无障碍名称及忙碌反馈，测试结果在提示与详情中展示。测试、启停和所属扩展链接独立处理点击，不会同时打开参数窗口。
Skill、Hook 与扩展卡片无描述时保留描述区高度；MCP 卡片按实际描述高度展示，无描述时不保留描述区，避免信息较少的连接清单出现大片留白。长描述最多显示两行；MCP 同行卡片等高，各行高度由该行内容决定，其它类型仍在同一分组内等高。管理动作仍由各自来源决定。没有底部内容时不保留空标签行。
MCP 的传输方式和其他信息标签、Hook 的事件和依赖标签仅在详情展示，不再占用卡片底部；Skill 的非扩展归属、版本和依赖提示仍按需显示。
MCP 卡片右上角按 Main 返回的能力提供独立启用/停用，参数编辑或查看由卡片点击进入；受应用保护、名称冲突或当前无法确认原生归属时显示加锁状态，并保留参数查看。图标表示清单中的有效启用状态，不表示进程正在运行或连接测试通过。
手动测试与 MCP 启用开关独立：关闭的自建或扩展 MCP 也可单独测试，并纳入全部测试；测试使用临时连接，不自动开启 MCP、不修改保存的配置。未支持的连接方式及正在执行的操作仍限制测试，扩展归属或连接定义不可用时显示实际失败。
自建 MCP 的编辑与扩展 MCP 的参数查看窗口在页脚“取消”或“关闭”旁提供蓝色“测试”文字按钮，提示明确测试已保存的配置；卡片仍使用图标入口。结果在独立窗口中展示，关闭或按 Escape 仅退出测试结果，保留后方编辑窗口与未保存内容；测试不会代替保存，也不在新建表单中测试尚未保存的条目。

Hook、Skill 详情与 MCP 参数窗口使用相同宽度、背景和圆角；长描述及依赖信息在窗口内滚动，标题、关闭按钮和底部操作保持可见。扩展 Hook 的无底色来源标签与底部文件夹图标放在同一行，展示原生扩展 ID，并可进入对应扩展详情；触发事件使用便于阅读的等宽标签。文件夹操作只显示图标，保留悬浮提示和无障碍名称；托管说明使用轻量提示，不单独占用大块面板。扩展 Skill 与其他 Skill 一样可经原生 `skills.update` 独立启停，状态以 `skills.status` 回读确认为准；删除和文件配置仍由父扩展管理。扩展 Hook 按原生限制保留状态加锁展示，不开放独立启停。两类条目都不为此新增配置存储。

扩展详情也沿用同一窗口排版，正文保留介绍、实际配置和必要的依赖/错误反馈，不新增重复的状态面板、安装路径或标识区。扩展、Skill、MCP 和 Hook 的详情标题使用与所点击卡片相同的图标渐变配色，并适当放大图标、统一标题对齐和留白，适配深浅主题；配色仅为当前弹窗的展示状态，不写配置。描述统一使用已有的安全 Markdown 渲染，优化列表、代码块和表格的排版；自建 MCP 的描述编辑框提供默认折叠的预览，避免编辑内容与渲染结果同时占据页面。命令、参数和原始 JSON 继续按文本展示。

扩展 MCP 的开关和连接参数以 OpenClaw 原生 `mcp.servers.<name>` 为唯一持久权威，不写入产品 SQLite、KV 或另一份配置文件。
关闭默认连接仅写入 `{ enabled: false }`，重新启用时移除该禁用覆盖；已有完整连接覆盖只修改其 `enabled` 字段。
扩展 MCP 的详情整页只读，沿用自建 MCP 编辑表单的宽度、标签、输入框与按钮样式。名称、传输类型、命令、逐行参数、工作目录、地址和请求超时（秒）均可查看和复制，不提供保存或恢复默认值。自建 MCP 保留正常编辑。
参数窗口读取选中连接的完整原生定义；只有禁用标记时也展示扩展默认定义，并保留显式禁用。下方“原始参数”折叠展示完整脱敏 JSON，禁止编辑；没有完整定义时保留原生摘要，不从摘要重建配置。既有原生连接覆盖保持原样，不自动清理或恢复。
扩展默认定义由原生 schema 和脱敏函数处理后才返回 Renderer。扩展参数写入通道及 preload/Renderer 方法一并移除，Main 管理能力固定为不可配置；只保留原生启停接口和只读查看、测试入口，不新增配置存储。
连接配置变化会同时清理旧测试结果与忙碌状态，迟到测试回包不得恢复旧结果。原生配置语法损坏仍走既有恢复路径；其它归属读取失败保留配置并停止未经确认的运行时，注销也不能绕过该保护。
删除或重命名自建 MCP 时，当前串行操作会向配置投影传递已撤销的旧名称，即使扩展也声明同名连接，也先移除旧产品投影，恢复扩展默认来源；该撤销集合只在本次操作内存中存在。
自建或市场 MCP 新建、改名时，Main 在同一操作队列内、修改产品记录前，拒绝使用已被扩展声明或原生非产品条目占用的名称（包括独立禁用标记）；扩展连接的参数窗口仅供查看。现有同名产品记录可以保留原名编辑，但不能制造新的跨来源重名。回滚同时撤销本次同步曾引入的新产品名称。

OpenClaw 2026.10.4 的扩展开关继续表示配置的启用意图；原生报告的注册错误或服务失败以红色警告进入详情，不把仍未加载的扩展自动判为失败或关闭开关。原生 `needs-setup` 状态即使没有缺失环境变量，也展示配置警告。

## 2. 操作从能力而非名称推导

| 条目          | 列表依据                     | 操作依据                                              |
| ------------- | ---------------------------- | ----------------------------------------------------- |
| Skill         | skills.status 的当前有效赢家 | 原生状态与文件来源                                    |
| 用户 MCP      | Store + 原生配置             | 产品 CRUD 与 probe                                    |
| Extension MCP | 原生清单与配置覆盖           | 精确归属、应用保护、原生配置版本；不复制成用户 server |
| Hook          | 包与产品开关                 | 受管文件/同步规则                                     |
| Extension     | 原生 plugins inventory       | 原生 removable 与产品保护                             |
| 市场卡片      | Provider metadata            | catalog kind、安装身份与原生对账                      |

不能用“名称包含 builtin”或某个目录存在决定安全动作。Main 同样验证能力，隐藏按钮不是唯一防线。

## 3. 同名 Skill 的真实行为

主列表显示 Gateway 解析后的有效来源。关闭赢家不自动换到下一份；删除赢家目录可能触发 fallback。操作完成后比较 name/source/path，来源变化应明确提示。

当前没有 authoritative variants contract，UI 不显示猜测的 shadowed 数量或逐来源开关。文件服务只能管理用户文件，不能越过原生解析器列举并认定全部可用变体。

## 4. 本地导入的用户流程

选择目录或支持的压缩包 → 安全检查和格式识别 → Extension 能力审查 → 提交当前 reviewToken → 受管安装 → 原生 inventory 回读。失败必须标明阶段，不能只提示“安装失败”而留下成功卡片。

原生 openclaw.plugin.json 包进入原生安装器；异构格式转换尚未交付，会明确停止。上游能识别 Codex/Claude 等 bundle 不代表产品已经提供可用转换。

安装期间的进度属于当前操作，不因关闭页面重复触发安装。临时源按原生提交阶段和结束证据清理；Windows 文件夹隔离副本在原生安装已发起但结果不明时保留，不能以超时认定未安装或安全删除。文件锁/链接错误如实报告，不停止 Gateway 重放破坏性操作，也不指引用户任意杀进程。具体事务见[插件系统](../../architecture/07-plugin-system.md)。

## 5. 市场查询、推荐与更新

仓库默认没有 Provider，页面显示未配置，而不是虚假热门插件。最小 SDK 可只支持搜索与下载；无详情或类别接口时不渲染无效操作。

空关键词推荐可按稳定 categoryId 查询，进入关键词搜索后清除类别。安装后记录 source/catalog/runtime 身份，更新候选与已安装列表共同对账；同名系统项不开放市场覆盖。

Marketplace 只接入 extension/skill/mcp 三种类型。Hook、Agent、Command、CLI 等需要完整生命周期后才能添加，不能只加一个筛选标签。

## 6. 可选与受保护扩展

agent-team 默认关闭，启用后提供协作工具与 Skill；禁用保留历史。stt-local-cli 尊重显式关闭，附件转录独立于麦克风。原生 browser 与 embedded-browser 由浏览器模式互斥管理，不能在插件页分别开启导致出现两个 browser Tool。

Runtime Services、必要审批和产品桥接的保护由后端检查。配置同步必须保留用户明确的可选开关，不以“恢复默认”覆盖。

draw.io 是默认开启、可关闭的系统内置 MCP。其完整编辑资源随运行时打包，说明见[离线绘图](../chat/drawio-offline.md)。支持 MCP Apps 的服务在名称旁显示轻量纯文字“APP”标签，悬停或键盘聚焦可查看含义；标签不单独占行，不增加新的 transport 类型或新增时的分类选项。普通服务不额外标注“普通 MCP”。

通用服务从连接测试返回的 `_meta.ui.resourceUri`（兼容原生 `ui/resourceUri`）识别；不因服务名称、stdio/HTTP 或存在 resources 推断。尚未识别的外部服务可通过单项测试或“全部测试”确认。测试只投影有界 `ui://` 字段，不复制无关 tool metadata。确认结果仅保留在当前 Renderer 运行内存中，切换页面或重复读取同一配置不会丢失；配置修改、启停、同步或父扩展变更会使结果失效，迟到测试不恢复旧标识。内置 draw.io 可在尚未连接时使用已审查的能力声明；连接定义被覆盖时撤回该提示，成功测试的实际工具目录优先。打开列表不会为了标识额外启动用户服务器。标识不代表已连接、已启用或所有资源已经过离线认证；实际渲染仍要求原生 MIME 和身份准入。

## 7. 错误和刷新

MCP 配置同步成功后保持静默，不展示服务器或工具数量；同步失败或等待超时使用可关闭的错误弹框，不在列表中插入同步结果提示，避免页面布局跳动。

列表读取失败保留错误状态，不能把空列表解释成全部卸载。安装/更新成功后重新 inventory，界面与市场身份一致才展示最终状态。启停失败不得仅回滚按钮而隐瞒原生状态不确定。

父扩展变更会刷新已打开的扩展详情和 Skill/MCP/Hook 清单；扩展被卸载后关闭其详情。MCP 的连接配置修改后不复用旧测试结果，迟到结果也不覆盖新配置。市场安装已确认保存、后续应用失败时，页面明确保留该错误并提供状态刷新，同版本安装不会被再次提交。卸载超时或断线时先核对清单，结果不明则提示待确认，不自动重复卸载。

## 8. 验收

检查来源分组与管理 scope、同名 fallback、父插件托管动作、受保护项、取消审查、换包 token 失效、更新后市场/原生双列表收敛、市场与本地导入同名冲突、无 Provider 和 Windows 锁/链接失败。产品只接入一个业务市场，不将协议保留的 sourceId 解释成已支持多市场。行为测试分布在插件服务、installation、marketplace 与 Renderer 各领域。
