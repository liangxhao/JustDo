# Plugin Hub：现行管理体验与能力边界

Plugin Hub 提供技能、MCP、Hook、扩展及市场的管理入口。各类型保留独立的来源、权限和生命周期；原生安装与事务见[插件系统](../../architecture/07-plugin-system.md)，市场合同见[市场适配](../../architecture/16-skill-marketplace-adapter.md)。

## 1. 页面如何组织

PluginsView 组合 skills、mcp、hooks、extensions、marketplace，各域服务、类型和组件就近维护。页面统一视觉与操作反馈，但保留每种类型不同 owner，不要求所有卡片都能启停、删除或更新。

系统与内置、用户安装、当前项目等归属用于展示；运行管理 scope 决定动作。例如 Extension 提供的 Skill 可属于用户安装，但删除仍需操作父 Extension。
启用状态由开关或加锁状态图标表达，卡片不重复展示“已禁用”文字；系统内置分组不重复展示“系统提供”来源标签。
Skill 的启停入口仅保留在列表卡片上，详情页不重复显示启用按钮或加锁状态图标。
系统内置扩展与用户扩展在实际目录可用时，都在详情页左下角提供打开文件夹的图标；系统托管的启停、配置和删除限制独立保留。
stt-local-cli 和 tts-local-cli 卡片提供独立的模型设置齿轮，关闭状态下也可先配置。

弹窗支持本地／在线模式：本地模型复用下载、进度、安装状态和重试，在线模式引用已配置的语音模型，TTS 另选音色。两种模式保留各自草稿，模型选择与语音页分别保存，操作不改变扩展开关；完整规则见[语音功能](../models/local-tts.md)。弹窗打开不同时触发卡片详情，扩展从清单移除后关闭对应弹窗。
确认该扩展当前所选的默认模型未就绪时，齿轮旁显示黄色三角感叹号，悬停或键盘聚焦提示扩展暂不可用，点击直接打开模型设置。提示跟随模型下载、安装、移除及已保存的模型选择实时更新；模型就绪后自动消失，状态读取中或读取失败时不推断模型缺失。

扩展来源标签统一使用“扩展”（英文为 “Extension”），MCP、Skill 与 Hook 共用同一无底色的紫色小字角标，放在头像右下角，适配深浅主题；MCP 与 Hook 角标保留进入所属扩展的入口。

### 列表排序与卡片

用户安装与系统内置组内按名称固定排序：使用 `zh-CN` 比较规则，忽略大小写、数字按自然顺序排列，
名称等价时按唯一 ID 排列。该规则适用于扩展、技能、MCP 和 Hook，不随接口返回顺序或界面语言变化。
用户自建与用户扩展附带的 MCP 合并后排序；系统内置扩展保留可切换项在前、加锁项在后的优先级。

MCP、Hook 和 Skill 共用卡片容器：与扩展卡片一致，默认无边框、无阴影、背景融入页面，悬停或键盘聚焦时显示浅底色。MCP 使用紧凑排版，缩小内边距与行间距，描述放在名称下方并与名称左对齐；其它类型保留现有内边距与卡片间距。
统一图标和标题行、两行描述区；MCP 点击卡片直接打开参数编辑或只读查看界面，不再显示独立编辑／查看图标。测试与开关集中在标题右侧，测试只显示蓝色图标，与状态图标保持一致大小和点击区域，保留提示、无障碍名称及忙碌反馈，测试结果在提示与详情中展示。测试、启停和所属扩展链接独立处理点击，不会同时打开参数窗口。
Skill、Hook 与扩展卡片无描述时保留描述区高度；MCP 卡片按实际描述高度展示，无描述时不保留描述区，避免信息较少的连接清单出现大片留白。

长描述最多显示两行；MCP 同行卡片等高，各行高度由该行内容决定，其它类型仍在同一分组内等高。管理动作仍由各自来源决定。没有底部内容时不保留空标签行。
MCP 的传输方式和其他信息标签、Hook 的事件和依赖标签仅在详情展示，不再占用卡片底部；Skill 的非扩展归属、版本和依赖提示仍按需显示。
MCP 卡片右上角按 Main 返回的能力提供独立启用/停用，参数编辑或查看由卡片点击进入；受应用保护、名称冲突或当前无法确认原生归属时显示加锁状态，并保留参数查看。图标表示清单中的有效启用状态，不表示进程正在运行或连接测试通过。
手动测试与 MCP 启用开关独立：关闭的自建或扩展 MCP 也可单独测试，并纳入全部测试；测试使用临时连接，不自动开启 MCP、不修改保存的配置。

未支持的连接方式及正在执行的操作仍限制测试，扩展归属或连接定义不可用时显示实际失败。
自建 MCP 的编辑与扩展 MCP 的参数查看窗口在页脚“取消”或“关闭”旁提供蓝色“测试”文字按钮，提示明确测试已保存的配置；卡片仍使用图标入口。结果在独立窗口中展示，关闭或按 Escape 仅退出测试结果，保留后方编辑窗口与未保存内容；测试不会代替保存，也不在新建表单中测试尚未保存的条目。

### 详情窗口与托管状态

Hook、Skill 详情与 MCP 参数窗口使用相同宽度、背景和圆角；长描述及依赖信息在窗口内滚动，标题、关闭按钮和底部操作保持可见。扩展 Hook 的无底色来源标签与底部文件夹图标放在同一行，展示原生扩展 ID，并可进入对应扩展详情；触发事件使用便于阅读的等宽标签。文件夹操作只显示图标，保留悬浮提示和无障碍名称；托管说明使用轻量提示，不单独占用大块面板。扩展 Skill 与其他 Skill 一样可经原生 `skills.update` 独立启停，状态以 `skills.status` 回读确认为准；删除和文件配置仍由父扩展管理。扩展 Hook 按原生限制保留状态加锁展示，不开放独立启停。两类条目都不为此新增配置存储。

扩展详情也沿用同一窗口排版，正文保留介绍、实际配置和必要的依赖/错误反馈，不新增重复的状态面板、安装路径或标识区。扩展、Skill、MCP 和 Hook 的详情标题使用与所点击卡片相同的图标渐变配色，并适当放大图标、统一标题对齐和留白，适配深浅主题；配色仅为当前弹窗的展示状态，不写配置。描述统一使用已有的安全 Markdown 渲染，优化列表、代码块和表格的排版；自建 MCP 的描述编辑框提供默认折叠的预览，避免编辑内容与渲染结果同时占据页面。命令、参数和原始 JSON 继续按文本展示。

## 扩展配置与 MCP 连接

通用扩展表单支持扩展显式声明为可编辑的普通文本，包括 URL：字段须为 `configSchema` 中的 `string`，并具有 `uiHints.configurable: true`。普通文本显示当前值或默认值，只保存实际编辑过的字段；清空可选字段删除其配置覆盖，有有效默认值的必填字段可以恢复默认。Main 校验声明的必填、长度、正则、枚举和 URI 格式，密码继续隐藏已保存值，留空不修改。TypeSafe 的本地 `baseUrl` 与内网 `serviceUrl` 均提供入口，切换地址模式时需清空旧地址；两者互斥及服务协议限制仍由插件校验。配置保存不改变启停状态。

TypeSafe 只在决策模型设置具有有效默认选择时加锁；取消默认或删空供应商后，保留当前扩展配置和开关并恢复手动管理。启动、登录退出和其它设置保存不覆盖无默认期间的手动改动，设置保存与补偿结束后再准入扩展操作。

### MCP 原生配置与只读查看

扩展 MCP 的开关和连接参数以 OpenClaw 原生 `mcp.servers.<name>` 为唯一持久权威，不写入产品 SQLite、KV 或另一份配置文件。
关闭默认连接仅写入 `{ enabled: false }`，重新启用时移除该禁用覆盖；已有完整连接覆盖只修改其 `enabled` 字段。
扩展 MCP 的详情整页只读，沿用自建 MCP 编辑表单的宽度、标签、输入框与按钮样式。名称、传输类型、命令、逐行参数、工作目录、地址和请求超时（秒）均可查看和复制，不提供保存或恢复默认值。自建 MCP 保留正常编辑。
参数窗口读取选中连接的完整原生定义；只有禁用标记时也展示扩展默认定义，并保留显式禁用。

下方“原始参数”折叠展示完整脱敏 JSON，禁止编辑；没有完整定义时保留原生摘要，不从摘要重建配置。既有原生连接覆盖保持原样，不自动清理或恢复。
扩展默认定义由原生 schema 和脱敏函数处理后才返回 Renderer。扩展参数写入通道及 preload/Renderer 方法一并移除，Main 管理能力固定为不可配置；只保留原生启停接口和只读查看、测试入口，不新增配置存储。
连接配置变化会同时清理旧测试结果与忙碌状态，迟到测试回包不得恢复旧结果。原生配置语法损坏仍走既有恢复路径；其它归属读取失败保留配置并停止未经确认的运行时，注销也不能绕过该保护。

### 来源名称冲突与配置撤销

删除或重命名自建 MCP 时，当前串行操作会向配置投影传递已撤销的旧名称，即使扩展也声明同名连接，也先移除旧产品投影，恢复扩展默认来源；该撤销集合只在本次操作内存中存在。
自建或市场 MCP 新建、改名时，Main 在同一操作队列内、修改产品记录前，拒绝使用已被扩展声明或原生非产品条目占用的名称（包括独立禁用标记）；扩展连接的参数窗口仅供查看。现有同名产品记录可以保留原名编辑，但不能制造新的跨来源重名。回滚同时撤销本次同步曾引入的新产品名称。

### 启用意图与实际运行

扩展开关表示配置的启用意图；原生报告的注册错误或服务失败以红色警告进入详情，不把仍未加载的扩展自动判为失败或关闭开关。原生 `needs-setup` 状态即使没有缺失环境变量，也展示配置警告。

### 技能工坊

技能工坊沿用当前技能、保存版本和最近变更三个区域：标题与刷新／关闭操作在弹窗滚动时固定，
不展示没有对应管理入口的后台自动整理状态，原生配置及后台机制保持原样。
标题使用简短说明及带名称提示的刷新／关闭图标，列表、详情及变更记录不叠加卡片边框。
首次清单读取成功后仅自动预览第一个当前技能，不自动选择历史版本；后续刷新及变更对账仍清空选择。
左侧列表通过浅底色标记当前选中的副本或具体历史版本，右侧以文件工具栏和正文区展示内容，
切换技能、版本或文件时保留已显示的正文及其身份，最新读取成功后一起替换；正文视口保持稳定，
加载提示不挤占布局，读取期间禁用归档、恢复及文件选择。读取失败保留原内容和身份并显示错误，
刷新及变更对账仍清空选择，不复用未经核对的详情。变更记录分别呈现技能名、动作、操作者和时间，
技能描述在列表最多显示两行，悬停可查看完整描述；历史版本采用短日期与彩色动作图标，
完整时间、动作及精确版本 ID 保留在提示和无障碍名称中。当前副本与归档状态以不同形状的
状态图标表示。最近变更使用彩色动作图标与操作者图标，记录上限以短标签展示并保留完整提示；
原有的变更前版本入口以查看图标及“变更前”文字展示。并发修改及替换副本的说明在归档／恢复确认区展示；
页面排版不增加学习、试用或其它管理能力，原生读写规则保持不变。

## 2. 操作从能力而非名称推导

| 条目          | 列表依据                     | 操作依据                                              |
| ------------- | ---------------------------- | ----------------------------------------------------- |
| Skill         | skills.status 的当前有效赢家 | 原生状态与文件来源                                    |
| 用户 MCP      | Store + 原生配置             | 产品 CRUD 与 probe                                    |
| Extension MCP | 原生清单与配置覆盖           | 精确归属、应用保护、原生配置版本；不复制成用户 server |
| Hook          | 包与产品开关                 | 受管文件/同步规则                                     |
| Extension     | 原生 plugins inventory       | 原生 removable 与产品保护                             |
| 市场卡片      | Provider metadata            | catalog kind、安装身份与原生对账                      |

不能用“名称包含 builtin”或某个目录存在决定安全动作。Main 同样验证能力，隐藏按钮不是唯一防线。

## 3. 同名 Skill 的真实行为

主列表显示 Gateway 解析后的有效来源。关闭赢家不自动换到下一份；删除赢家目录可能触发 fallback。操作完成后比较 name/source/path，来源变化应明确提示。

当前没有 authoritative variants contract，UI 不显示猜测的 shadowed 数量或逐来源开关。文件服务只能管理用户文件，不能越过原生解析器列举并认定全部可用变体。

## 4. 本地导入的用户流程

选择目录或支持的压缩包 → 格式与声明检查 → 受管安装 → 原生 inventory 回读。选择安装包后直接执行，不再要求接受人工能力审核；普通原生扩展优先通过现有引擎热安装、热卸载。涉及应用 Main/UI 代码的包变更仍在同一次冷流程内完成校验和信任登记。只有原生无法热应用或实际启动环境变化时才安排必要重启，不因存在请求头策略文件就重启。失败必须标明阶段，不能只提示“安装失败”而留下成功卡片。

原生 openclaw.plugin.json 包进入原生安装器，运行入口须符合其编译格式。其他
格式在安装前明确停止，错误说明当前 `productName` 的扩展格式要求，不再提示
未来转换功能。合法文件名、显示名称或路径含中文、空格时仍可导入，不能据此拒绝。

安装期间的进度属于当前操作，不因关闭页面重复触发安装。临时源按原生提交阶段和结束证据清理；Windows 文件夹隔离副本在原生安装已发起但结果不明时保留，不能以超时认定未安装或安全删除。文件锁/链接错误如实报告，不停止 Gateway 重放破坏性操作，也不指引用户任意杀进程。具体事务见[插件系统](../../architecture/07-plugin-system.md)。

## 5. 市场查询、推荐与更新

仓库默认没有 Provider，页面显示未配置，而不是虚假热门插件。最小 SDK 可只支持搜索与下载；无详情或类别接口时不渲染无效操作。

空关键词推荐可按稳定 categoryId 查询，进入关键词搜索后清除类别。安装后记录 source/catalog/runtime 身份，更新候选与已安装列表共同对账；同名系统项不开放市场覆盖。

热门推荐和分类推荐的安装按钮在未安装时只显示加号，悬浮提示和无障碍名称为“安装”；已安装插件保留市场卡片，按钮只显示勾选图标并禁用，悬浮提示和无障碍名称为“已安装”。卡片上的市场操作统一只显示图标：安装／更新中用旋转图标，更新入口用向上箭头，待确认用时钟，冲突用警告，不可用用禁止符号；状态说明通过悬浮提示、无障碍名称和独立操作反馈表达，更新提示同时保留版本变化。详情窗口的操作按钮保留图标和文字。插件同时出现在用户安装分组，配置、启停和更新沿用本地卡片。关键词搜索仍按已核验的市场安装身份去重，市场命中已安装项时保留一张可管理的本地卡片，不按显示名称合并不同来源。

热门推荐、分类筛选与关键词搜索结果沿用用户安装、系统内置列表的自适应列宽规则：宽屏保留空列，少量卡片不拉伸占满整行；窄屏按可用宽度收为单列。

Marketplace 只接入 extension/skill/mcp 三种类型。Hook、Agent、Command、CLI 等需要完整生命周期后才能添加，不能只加一个筛选标签。

## 6. 可选与受保护扩展

agent-team 默认关闭，启用后提供协作工具与 Skill；禁用保留历史。Swarm Workflow 默认关闭，配置同步保留已有的明确启停选择，助手名单更新不重新开启插件。stt-local-cli 和 tts-local-cli 的启停仅由扩展页控制，设置同步只更新运行参数，不写入启用状态；首次安装使用扩展清单默认值，附件转录独立于麦克风。原生 browser 与 embedded-browser 由浏览器模式互斥管理，不能在插件页分别开启导致出现两个 browser Tool。

语音扩展的模式、模型、音色及失效处理独立于麦克风和回复朗读，完整规则见[语音功能](../models/local-tts.md)。下载或保存选择不启用扩展；禁用后对应本地与在线工具能力都退出执行。

Runtime Services、必要审批和产品桥接的保护由后端检查。配置同步必须保留用户明确的可选开关，不以“恢复默认”覆盖。

draw.io 是默认开启、可关闭的系统内置 MCP。其完整编辑资源随运行时打包，说明见[离线绘图](../chat/drawio-offline.md)。支持 MCP Apps 的服务在名称旁显示轻量纯文字“APP”标签，悬停或键盘聚焦可查看含义；标签不单独占行，不增加新的 transport 类型或新增时的分类选项。普通服务不额外标注“普通 MCP”。

通用服务从连接测试返回的 `_meta.ui.resourceUri`（兼容原生 `ui/resourceUri`）识别；不因服务名称、stdio/HTTP 或存在 resources 推断。尚未识别的外部服务可通过单项测试或“全部测试”确认。测试只投影有界 `ui://` 字段，不复制无关 tool metadata。确认结果仅保留在当前 Renderer 运行内存中，切换页面或重复读取同一配置不会丢失；配置修改、启停、同步或父扩展变更会使结果失效，迟到测试不恢复旧标识。内置 draw.io 可在尚未连接时使用已审查的能力声明；连接定义被覆盖时撤回该提示，成功测试的实际工具目录优先。打开列表不会为了标识额外启动用户服务器。

标识不代表已连接、已启用或所有资源已经过离线认证；实际渲染仍要求原生 MIME 和身份准入。

## 7. 错误和刷新

普通启动在应用外壳就绪后开放插件页，搜索与分类导航可用；首次引擎准入完成前，
扩展、Skill、MCP 和 Hook 管理器及其原生清单预加载延后挂载，准备提示复用右下角
进度反馈区，不在内容区或“用户安装”列表上方插入横幅。
Main 确认当前引擎的执行准备、配置与权限后才加载清单，不能仅凭进程 `running`
提前开放，也不以空清单或插件操作失败弹窗表示正常启动等待。真实引擎失败时在
右下角显示标题栏状态入口的恢复指引，不使用进行中的旋转样式。
全局扩展启用状态共用同一就绪订阅，首次准入及引擎恢复后
只读刷新，准备期间保留此前观察值并丢弃已失效读取，不为恢复自动提交插件变更。

首次准入后，插件自身重启引擎时保留已挂载管理器、操作 owner 和编辑草稿；列表及
工具栏及已有弹窗暂时不可交互，分类切换暂停，避免重启中重新挂载另一原生管理器。
交互边界同时覆盖挂载在页面之外的弹窗事件；后台清单失效通知合并到就绪后读取。
已开始变更仍沿用各自确认与结果流程；此门禁不替代 Main 的原生权限、归属和操作
排队校验，也不取消或重发已开始的变更。

### 操作进度、排队与文件占用

扩展、Skill、MCP 和 Hook 的导入、更新、卸载、启停及配置保存期间，插件页在
右下角统一显示插件名称、操作、当前步骤和已用时；切换分类后继续显示，详情和
删除确认窗口打开时也可见。排队、获取信息和下载安装包、校验、文件安装、保存
配置、应用运行时、重启、确认状态、刷新清单与回滚只在真实发生时展示，不用
倒计时模拟下载或转换进度。必须等待原生确认的操作继续保持忙碌，不能重复提交。
市场适配器没有更细的回调时显示完整准备阶段；安装失败保留失败步骤和实际错误
分类，不能用成功进度覆盖待确认状态。
列表读取、市场加载及 MCP 桥接同步的临时提示也复用同一右下角容器；这些只读
活动不生成原生操作编号、虚构步骤或百分比。独立管理页面的多个提示共用同一个
展示容器，避免叠在相同坐标。列表上方只保留实际内容和必要的空态／错误说明，
不再插入加载或重启横幅。MCP 同步继续保留原有全窗交互拦截与超时清理，进度文字
和动画移入右下角；按钮忙碌态与字段验证保持各自的交互语义。

原生明确表示另一项插件或配置操作正在执行、当前请求尚未开始时，进度切换为排队，
按原生建议间隔等待，最多 30 秒；获得准入后恢复当前步骤。等待不重新打开能力确认，
也不重复下载。连接身份变化、超时或结果未知时停止自动提交，沿原有错误流程提示。

Windows 原生扩展安装发布目录时遇到短暂占用，会在同一次安装的“安装文件”步骤
内等待恢复，最多五秒，不重复提交安装；右下角进度继续显示该步骤与累计耗时。持续占用
或原文件发生变化时停止恢复，沿原生旧版本保留与错误流程反馈，不能提前显示成功。

安装和更新不会仅因资源管理器正在浏览目录就被预检阻止；是否能发布由实际原生事务
确认。真正的文件操作失败仍显示原始原因、占用程序，以及原生返回的备份或恢复说明，
不能只剩“扩展目录／占用程序”。卸载的操作前检查保持独立；不会为绕过目录占用而关闭
Explorer、重启引擎或自动重新提交结果未知的安装。

### 失败、未知结果与后续刷新

变更失败统一进入插件页的结果弹窗，不依赖当前分类仍挂载；并发结果依次展示，
批量导入只弹一次汇总。弹窗突出插件名称、简短原因和一条下一步建议；原始错误、
已知失败步骤、耗时与操作编号收进可展开、可复制的脱敏详情。已安装后续失败、原生结果待确认与清单刷新失败
使用各自说明和下一步，不把它们当作未安装，不提供通用的再次提交按钮。
错误层位于详情、确认和编辑窗口上方，关闭或 Escape 仅关闭当前错误，保留后方
表单草稿；未读结果不因切换分类消失。字段格式与必填验证仍就近显示。
显式启用的能力确认和用户取消不算操作失败，后续刷新失败不会覆盖最初的业务失败阶段。
明确完成的安装／卸载使用右下角成功提示，不再弹出确认窗口。Main 对原始成功回执之后
的运行环境恢复单独分类：准备被替代、运行代次变化或仍在启动时，以有类型的待确认
证据透传，右下角保留“已安装／已卸载”和简短的引擎状态说明，可关闭或展开详情，
不误报安装／卸载失败。实际引擎错误仍展示具体原因；原生结果未知、启用未确认、
原有校验或清理错误不被降级，也不因卡片存在或进程运行就推断操作成功。
待确认提示与错误队列分开选择，不能挡住后来真正失败的操作；关闭只影响展示，
不释放重复提交保护、不重发变更。成功提示和市场反馈共用右下角容器，同一结果不重复展示。
恢复待确认提示订阅同一份引擎就绪投影，并先只读重取 Main 准入和引擎状态；确认
当前引擎完成准入后，结束历史提示中的“AI 引擎状态待确认”。没有补充信息时，
保留简短成功提示三秒后关闭；另有清单刷新等补充错误时继续显示该信息并允许复制，
不能随引擎恢复一起吞掉。此变化仅结束展示，不更改原生回执或解除市场版本保护；
后来的引擎错误也不会反向改写已经完成的操作。
市场安装失败不再把安装器已返回的原因统一替换为通用安装失败；弹窗展示经凭据、
控制字符清洗后的具体原因，并保留完整多行说明。扩展的本地错误保留实际安装、占用
及备份目录，便于定位资源管理器窗口和恢复文件，不再显示 `[REDACTED PATH]` 占位；
凭据、请求头值和 URL 继续脱敏，其他来源的原始 SDK 错误不直接展示。安装服务未返回原因时明确
说明原因缺失，提示复制错误详情与操作编号排查，不把最后已知步骤当作根因。
安装／更新存在明确提交证据时，标题说明内容已保存，并写出实际返回的未完成步骤；
状态确认失败直接说明无法确认插件状态，不笼统称“后续步骤未完成”。具体原因保持
服务返回的原文，缺少步骤或原因时明确说明缺失，不能从最后进度或错误关键词补造。
处理建议按步骤和动作区分：包校验／依赖错误核对安装包与资源，配置仅在提供可编辑
入口时指导修改。运行环境问题指向标题栏（最小化、最大化按钮旁）的 AI 引擎状态，
启动失败时查看原因，仅在实际提供启动按钮时建议手动启动；不指向隐藏的设置入口。
状态读取问题才指导只读刷新。关闭或卸载失败不能建议启用，未知结果只指导核对、
不重复提交。
批次标题与阶段按逐项结果展示，每个失败项保留自己的原因与处理建议；复制详情
包含建议。结果待确认时不因列表出现条目推断本次成功；后续只读刷新失败仍保留
待确认说明，不改称更改已保存。
内容已保存与安装后启用结果未知可以同时成立。安装服务转发激活的待确认标记，
展示记录保留这两项事实：标题说明已保存但最终结果待确认，步骤作为最后已知步骤，
处理建议仅只读核对，不建议再次启用或重启来替代丢失的原生回执。
扩展包变更包装器在恢复运行环境时失败，不覆盖已正常返回的原生回执：安装成功
后恢复失败保留已提交事实；卸载成功后恢复失败明确说明插件已卸载，无需再次卸载，
并清理对应市场身份。原生失败的阶段、待确认状态和源占用标记继续保留；回调未
正常返回时不能根据清单或磁盘推断成功。显式启用的能力确认仍可继续，但不能遮蔽同时发生
的环境恢复错误。
启用／关闭也保留已正常返回的原生结果：后续伴随组件刷新或清理失败时，明确说明
启停设置已保存、后续状态确认失败，不能宣称整个插件已可用或已完全关闭。原生
失败、结果待确认和能力审查不改写为成功；未知变更不自动重发。更新复用安装的
结果保留流程；配置保存、同步和只读刷新保持各自事务与回滚规则，不进入包替换流程。
启停命令与后续恢复同时失败时，先展示命令的原始原因，再追加恢复错误；恢复
不能替换首个失败原因或阶段。
卸载同样保留最初原因，不以引擎恢复错误覆盖原生拒绝或命令详情。已确认卸载
完成后，策略同步、允许加载列表清理和引擎恢复失败分别说明实际未完成环节，
明确无需再次卸载；引擎问题通过标题栏状态及“查看原因”处理。未知卸载结果
继续只指导核对，不因正常停止状态、最后一条进度或列表显示推断结果。
包变更后的引擎准备即使以失败状态正常返回，资源适配器也先保留该次启动原因，
不继续用清单读取错误替换它；只转换本次结果，不借用旧诊断或重试原操作。
扩展出站请求头声明支持明确的 HTTP/HTTPS 地址，包括内网 HTTP 服务；保持原有
协议、主机、端口和路径边界匹配。地址校验错误指出声明文件、原始组与地址序号
以及具体原因，不回显可能含凭据的原 URL；不把所有条件笼统归成 HTTPS 错误。
扩展、Skill、MCP 和 Hook 的卡片均不展示操作产生的成功、失败、重启、待确认或
刷新提示文字。失败步骤与错误详情在结果弹窗展示；市场操作的待确认、已安装后续
失败、重启及清单刷新提醒复用右下角进度反馈区，并保留只读状态刷新入口。
该区域随操作记录展示，不依赖当前搜索结果或筛选中仍存在对应卡片。

### 技能发现与安装后启用

进入技能页或收到父扩展变更后，后台在 45 秒窗口内核对原生清单，读取逐步退避到
每 5 秒一次，以覆盖 Windows 较晚的技能发现；切换页面会取消补读。断线恢复沿用
剩余窗口，删除项不会因为短暂的旧清单重新出现，明确重新导入后可立即显示。

市场首次安装默认启用，升级保留用户的启停选择。Skill 需要先由原生发现准确的
安装来源再开启；缺少程序、凭据或其它依赖仍按原生结果提示，开启不代表已满足
运行条件。已安装但无法开启或确认时保留安装事实并提示错误，不重装同一版本。
带 App companion 的扩展保持禁用安装，安装时在同一包变更流程中校验、保留并登记
本次确切 Main/UI 代码的信任，不再要求安装后点击“审查应用扩展”，也不为此再次重启。
代码校验或登记失败保留已安装事实并给出具体原因；显式启用仍独立进行，安装成功不等于已启用。

### 清单与测试结果失效

MCP 配置同步成功后保持静默，不展示服务器或工具数量；同步失败或等待超时使用可关闭的错误弹框，不在列表中插入同步结果提示，避免页面布局跳动。

列表读取失败保留错误状态，不能把空列表解释成全部卸载。安装/更新成功后重新 inventory，界面与市场身份一致才展示最终状态。启停失败不得仅回滚按钮而隐瞒原生状态不确定。

父扩展变更会刷新已打开的扩展详情和 Skill/MCP/Hook 清单；扩展被卸载后关闭其详情。MCP 的连接配置修改后不复用旧测试结果，迟到结果也不覆盖新配置。市场安装已确认保存、后续应用失败时，页面明确保留该错误并提供状态刷新，同版本安装不会被再次提交。卸载超时或断线时先核对清单，结果不明则提示待确认，不自动重复卸载。

### 卸载时的模型与插件数据

卸载确认窗口默认保留数据，可勾选“同时删除插件数据”，并显示预计释放空间。
大小读取失败或目录无法安全清理时禁用此选项，仍可保留数据卸载。只清理已确认归属的
`state/plugin-data/<plugin-id>/`，不删除用户文档、原生历史或旧版插件自定义目录。
更新、关闭插件均保留这些数据。清理在相关任务停止、原生卸载确认完成之后执行；
结果未知时不清理。若插件已卸载但数据清理失败，明确报告这两项事实，不要求重复卸载。

### 成功后的卡片状态

四类插件的卡片只保留名称、描述、元数据和操作图标，不写入操作结果文字；市场推荐区通过勾选图标和禁用按钮表达已安装状态。市场安装／更新在清单确认安装身份且刷新结束后，右下角短暂显示成功结果 3 秒；更新筛选中的已完成卡片也在此期间保留，再自动收起。Hook 的导入、删除成功与重启提醒也复用右下角区域。结果弹窗与右下角进度反馈区不受卡片文字限制；隐藏卡片提示不会清除已提交版本或操作锁，不能因此再次提交同版本安装。

## 8. 验收

检查来源分组与管理 scope、同名 fallback、父插件托管动作、受保护项、取消审查、换包 token 失效、更新后市场/原生双列表收敛、市场与本地导入同名冲突、无 Provider 和 Windows 锁/链接失败。产品只接入一个业务市场，不将协议保留的 sourceId 解释成已支持多市场。行为测试分布在插件服务、installation、marketplace 与 Renderer 各领域。
