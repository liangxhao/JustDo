## 目标与用户已确认的约束

在已经完成的 OpenClaw v2026.9.6 升级基础上，将适合公司内网使用的能力接入现有产品界面。
本轮按顺序实施三项：**技能提炼与审核 → 浏览器实时查看与人工介入 → 会话归档与存储管理**。
先完成每项的最小完整流程及验证，再推进下一项。

- 软件部署在公司内网。除浏览器可以访问公司外网外，应用、Gateway 和其他执行组件只能连接公司内网服务。
- 模型调用复用现有公司内网模型配置；不新增公网模型、外部账号或在线下载的运行时依赖。
- 浏览器可访问外网，不代表应用后台有公网访问能力，也不代表后台拥有浏览器中的登录身份。
- 公司 MCP 涉及内部身份与业务权限，没有确定的客户端接入规范；本轮不做 MCP 接入、登录或诊断改造。
- 不提取浏览器 Cookie、令牌或证书来替代正式的服务认证，不把浏览器作为后台请求的通用公网代理。
- 本计划约束新增功能的网络依赖，不授权顺带重构整个软件的网络策略或移除既有插件。

### 2026-09-26 实现记录

- 设置 → 统计与存储提供“使用统计”和“会话存储”两个 Tab，默认显示原使用统计；会话存储从“配置”页移入，切换离开时卸载并停止轮询。会话存储卡片包含：原生统计、助手明细、自定义正整数期限、独立保存、手动检查及维护结果；中文和英文完整。
- `sessions.storage.status({})` / `sessions.storage.run({})` 已按 v2026.9.6 标签核实，参数均为空。run 是全局后台一轮检查，要求 `session.maintenance.coldStorage.enabled=true`，不支持单会话或单助手操作；没有临时切换策略模拟单次归档。
- 策略通过 `config.get` / 带 `baseHash` 的 `config.patch` 保存，仅写 coldStorage。缺省关闭、30 天；已有自定义值保留，不在产品数据库另存策略。原生 config write flow 对 coldStorage 热应用等待生效；失败/断连重新读取核对，不自动重放写入。
- Main 会话存储服务封装四个窄 IPC，剔除数据库路径，只返回页面需要的统计、策略和错误分类。写入互斥，能力读取失败时不继续保存。
- 普通和最小配置同步保留现有 coldStorage 及非产品拥有的 maintenance 字段。现有 365 天 / 500 条清理配置保持原样；冷归档不保证永久保留。
- 页面可见时空闲 15 秒、运行中 2 秒刷新；窗口隐藏、关闭或切换设置页释放轮询，聚焦重新读取，失败保留过期统计，不用 0 冒充真实值。关闭卡片不取消原生维护。

### 2026-09-26 面板误禁用修复
