# 内网功能接入：剩余验收

本页记录 OpenClaw 2026.9.6 接入后的未完成验证。技能学习与审核、内置浏览器人工介入、会话冷归档的产品入口均已实现；真实内网环境和冷历史恢复尚未完成验收。现行机制分别见[插件系统](../architecture/07-plugin-system.md)、[浏览器介入](browser-intervention.md)、[数据存储](../architecture/10-data-storage.md)及[聊天渲染](../architecture/15-chat-rendering.md)。

## 环境约束

- 应用、Gateway 和其他执行组件只使用公司内网服务；浏览器可访问外网，不代表后台可访问外网或拥有浏览器登录身份。
- 模型调用复用公司内网配置，不增加公网模型、外部账号或运行时在线下载依赖。
- 不读取浏览器 Cookie、令牌或证书来替代正式认证，也不把浏览器作为后台通用公网代理。
- 公司 MCP 的身份与权限规范未确定，暂不增加接入或诊断流程。

## 技能学习与审核

聊天中使用原生 `/learn`；插件页的“技能提案”弹窗只审核 main 的提案。列表、检查、批准和拒绝使用原生 `skills.proposals` API，写入绑定 agentId、proposalId 与 expectedRevisionHash。冲突或结果不确定时重新读取，不自动重放。审核入口不创建学习会话，也不更改自主学习或发布策略。

每周“技能库自动整理”是另一个原生任务：按 Agent 的 `skill-collection-review:<agentId>` declaration key 聚合，保留各 job 身份与历史。它不等于用户主动从历史学习，也不应因多条成员任务而被当作重复任务删除。完整调度语义见[定时任务](../architecture/08-scheduled-tasks.md)。

待在真实公司模型与账号下验证：

- [ ] `/learn` → 查看提案 → 审核 → 技能列表刷新形成完整闭环。
- [ ] 拒绝不改变已安装技能；重复批准、冲突、草稿缺失和断线均有可恢复状态。
- [ ] 重连或重启后从原生恢复提案，不跨 Agent 读写，也不自动重放写操作。

## 内置浏览器人工介入

首版停止、人工操作和明确继续已实现，范围限于任务使用的内置真实网页。入口、保护状态、原始操作排空和继续语义统一见[浏览器介入方案](browser-intervention.md)。

待在真实企业页面与模型下验证：

- [ ] 登录、人工修改、多页面和后台任务不串目标；停止确认前不放行人工输入。
- [ ] 断线、重载与重复停止或继续不自动重发结果未知的操作。
- [ ] 继续前重新观察当前页面，保持登录状态并避免重复提交。

## 会话冷归档与存储管理

“设置 → 统计与存储”已提供原生统计、策略保存和一轮手动维护。`sessions.storage.status({})` 与 `sessions.storage.run({})` 都是全局接口；run 要求 `session.maintenance.coldStorage.enabled=true`，没有单会话或单助手参数。策略通过带 `baseHash` 的 `config.patch` 保存，默认关闭、期限 30 天，并保留已有显式设置。有效配置可显示和编辑；只有确认 applied revision 后才允许手动运行。读取失败保留过期统计，不用零值冒充真实占用。

历史仍由 `chat.startup` / `chat.history` 读取。首次读取失败与读取完成分别记录；失败时禁止发送、侧聊和导出，保留已显示正文并提供只读重试。归档不改变产品会话、分组、置顶或助手映射；导出仅覆盖当前已加载快照，不是原生完整备份。

**发布阻塞：**隔离运行时测试中，近期热历史可读，过期历史可归档，但有效冷历史在重启后多次于 `chat.startup` / `chat.history` 出现 30 秒 `CLIENT_TIMEOUT`。损坏归档能够返回读取错误，没有被误报为空历史。无损坏样本、bundled 与未合并入口均复现超时；当前证据尚不能确认最终根因。使用隔离数据复现：

```powershell
node tests/openclaw/runtime/session-storage-smoke.cjs vendor/openclaw-runtime/current --skip-corruption
```

不要通过产品重试循环、直接读原生数据库或建立正文缓存掩盖恢复问题。待完成：

- [ ] 定位并修复冷历史恢复超时，在锁定的最终运行时重跑隔离 smoke。
- [ ] 统计 → 归档 → 重启 → 打开历史 → 继续会话完整通过；文本、附件引用及会话身份按原生语义恢复。
- [ ] 活动任务、磁盘写失败、断线与中断恢复不误报成功，不触发产品删除流程。
- [ ] 关闭自动归档后，已归档历史仍能按原生能力恢复。

真实内网模型、企业网页和归档恢复的验收结果需分别记录；自动化或 mock 模型检查不能代替这些结果。
