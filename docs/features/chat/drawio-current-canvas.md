# draw.io 当前画布连续编辑设计

状态：已实施。2026-10-21。解决已打开画布的继续修改、侧栏复用和重复展示；完整历史版本功能不在本期范围。

设计取舍：原地更新同一张图，保留撤销和必要的防覆盖检查。轻量内容代次用于判断修改是否过期，不建设面向用户的版本库。编辑通道使用锁定运行时的公开插件 SDK 与标准 AppBridge；手动 App 与模型执行的工作目录一致性由下述原生缺口修复保证，不改变 MCP Apps 生命周期。

## 1 当前范围

| 保留                         | 原因                                                 |
| ---------------------------- | ---------------------------------------------------- |
| 稳定图表身份                 | 将后续修改关联到同一张图，不按标题或最后一条消息猜测 |
| 读取并更新指定当前画布       | 补齐原来只能创建新图的缺口                           |
| 侧栏已有目标时优先复用       | 直接解决重复创建消息内图表的问题                     |
| 一次 AI 修改可撤销           | 改坏后可退回，优先使用 draw.io 自身撤销栈            |
| 发送前取得当前内容           | 包含尚未提交的节点文字，避免按旧 XML 修改            |
| 应用前的内容代次检查         | 用户在模型生成期间手工改图时不被覆盖                 |
| 精确应用回执与未知结果不重放 | 避免超时后重复应用或假称侧栏已更新                   |
| 有根据的重复展示收起         | 一张图只保留一个活动编辑器，原生历史不删除           |

首期不建设历史版本列表、版本比较/恢复界面、独立文档资产库、版本配额与垃圾回收、跨会话共享文档、分支版本图、多窗口编辑接管、自动三方合并或通用第三方 App 文档平台。这些不再是发布前置条件。

保留现有保存/导出、沙箱、权限、会话隔离和历史恢复契约。未保存手工草稿仍不承诺跨重启恢复；完整历史与草稿自动保存是两个独立功能。

## 2 用户交互

用户明确引用图 A 时优先修改 A；没有明确引用时，修改发送时当前会话选中的画布。侧栏已有同一目标则在其中更新。多个候选无法确定时提供目标选择；“另画一张”明确创建另一张图。

不增加输入框图表标签。发送准备冻结当时的目标，模型用 `drawio_diagram` 读取后修改；多个候选无法确定时，工具返回名称和身份供模型询问用户。内容冲突时不应用，本轮返回失败，由后续明确请求重新准备。

| 场景                            | 首期行为                                                                                                      |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 侧栏打开空白 draw.io 后要求画图 | 在这张空白画布生成内容，不再开第二个编辑器                                                                    |
| 侧栏已有图，要求加节点或改颜色  | 原地更新；回复仅显示“已更新”及定位画布入口                                                                    |
| 已有内嵌图，没有侧栏目标        | 在原文档中的编辑器继续编辑；用户可经通用引用固定到侧栏，后续消息定位同一图                                    |
| 明确另画一张图                  | 新图身份独立，原图仍保留                                                                                      |
| 只问图的含义                    | 只读取，不改变内容                                                                                            |
| 同一聊天内切换标签后原请求完成  | 原绑定仍有效时更新发送时目标，不改到新标签，也不抢回焦点                                                      |
| 切换聊天后原请求完成            | 暂停旧 App 接口并撤销当前 token；未派发候选拒绝，已派发结果保持未知；切回不应用旧候选，下一次明确发送重新准备 |

消息引用的是可继续编辑的当前图，而不是承诺保存了当时的不可变历史快照。界面应明确显示“当前图/打开画布”，不展示不存在的“第 N 版”按钮。原生工具记录仍保留当次真实输入和结果。

对于之前提出的“后文修改后，第一次的图取消渲染”，首期收窄为“取消重复展示”：不为修改再新建一份完整图表。旧卡片只有已确认是同图的重复展示时才收起为当前图入口，不能销毁唯一仍承载未保存输入的编辑器。已有内嵌编辑器留在原文档，可避免搬动 iframe 造成重载。

## 3 最小身份与状态

当前已有 viewId、toolCallId、MCP 服务/工具/资源、原生 sessionKey/sessionId、agent 和连接代次，用于来源和权限校验。viewId 在恢复后可能改变，不能直接作为跨视图恢复的长期图表身份。

首期只需补齐以下信息，不引入面向用户的版本实体：

- diagramId：稳定图表引用，由可信插件路径签发并通过真实结果或认证 RPC 返回。修改保持不变，新建另一张图使用新 ID。
- baseContentStamp：发送时的 XML 指纹及必要的本地内容代次，写回前核对。它是防覆盖标记，不是可浏览历史。
- 操作引用：优先复用原生 toolCallId 与精确会话身份，关联本次待应用内容和回执，不另建通用版本操作账本。

创建来源只需保留模型生成、手动打开或文件导入等既有事实；展示位置由现有宿主条目持有；是否作为本轮参考或编辑目标由发送准备持有。三者不互相推导，也不需要新增统一来源注册中心。

模型可引用 diagramId，但不能通过填写 sessionKey、owner 或授权布尔值获取权限。插件仍从可信原生调用上下文校验目标归属；加入模型上下文也不自动扩大写权限。

## 4 一次修改的最小流程

1. 发送前提交当前节点文字，导出真实 XML，捕获目标、内容标记、编辑器实例及原生绑定。准备失败保留草稿并明确未发送。
2. 模型读取这份当前内容，调用针对同一 diagramId 的修改能力；新建与修改使用不同操作语义。
3. 插件验证目标、调用权限、XML 和大小。宿主在应用前再次核对原生绑定、目标实例和内容标记。
4. 内容未变化时，在同一个 draw.io 编辑器中以可撤销事务应用修改，等待实际应用回执，再返回带内容与关联引用的真实工具结果，交由原生写入历史。
5. 应用已确认后更新当前图引用，收起确切重复卡片。失败或结果未知时不宣称更新成功，也不重放同一修改。

应用期间对同图写入做短时串行控制即可。首期不实现多窗口编辑接管：无法确认唯一可写实例时拒绝自动写入，其他窗口保留查看能力，不建设跨窗口租约协议。

如果模型生成期间用户又改了内容，停止应用，保留用户当前图，工具返回冲突。后续明确请求可基于当前内容重新修改或另做一张；不增加候选恢复界面。不能仅检查持久结果 ID，因为手工草稿可能尚未保存。

一次 AI 修改通过锁定 draw.io 的 `replaceFileData` 形成一个撤销事务，保留先前手改和多页撤销栈；不使用重新加载路径。实际编辑器由离线浏览器探针验证。

应用成功、工具结果持久化和整轮执行终态是不同事实。画布 ACK 仅证明已应用，不证明原生结果已持久化；两者之间崩溃，重启只能恢复最近一份原生可核实内容。应用后回执丢失时保持待核实，不因超时或关闭而假定未执行。后续模型请求失败也不能自动撤销已确认修改；整轮结果仍只依据原生 executionSettled 终态。

## 5 数据与恢复

优先沿用原生工具结果保存模型确认的 XML 和少量图表关联元数据，历史读取沿公开 SDK 的当前可见记录。宿主不直接读 transcript 文件，不在 Main/Redux 新建图表正文缓存。

插件认证只读适配读取精确原生来源和当前分支真实工具结果，不从助手文本或短码猜测关系。恢复最新已确认修改不要求新增历史版本浏览界面。

插件仅持有绑定当前会话和编辑器的必要路由、待应用操作和有界候选状态。原生记录无法核实的结果保持未知；不为了展示最新图而把失败或未确认候选当成成功。

重启继续沿既有原生身份和视图恢复路径，不能假定旧 viewId、连接代次或写授权继续有效。只有认证记录支持的已确认内容可以恢复；未确认操作不自动重新应用。

文件导入和写回仍沿现有宿主权限与保存对话框，修改画布不自动覆盖源文件。跨会话、fork 或借用历史的写入不在首期支持范围，不能因此放宽原有身份检查。

## 6 必须通过的验证

### 实现通道与边界

沿用 MCP `create_diagram` 创建新图；为创建、空白打开和文件打开的真实结果补充插件签发的 `diagramId`。连续修改使用独立的 draw.io 插件模型工具，不将插件工具结果伪造成 MCP App descriptor。模型工具采用公开 v2 调用上下文，从可信 `sessionKey/sessionId/agentId` 和 `assertInvocationCurrent` 校验原生归属。

宿主在发送准备时，经标准 AppBridge 的插件浏览器工具提交节点编辑并取得 XML、内容戳和图表身份。认证插件 RPC 先以同一调用者读取 `mcp.app.view` 核验真实视图，再沿同一视图核对插件签发记录，将当前编辑器绑定至捕获的原生会话、视图、连接和随机令牌。令牌不进入模型上下文。仅保留有界内存路由和当前准备快照，不建设文档存储。

模型修改通知只携带刷新提示；宿主必须通过原绑定的认证 RPC 读取待应用内容。应用使用标准 AppBridge 调用浏览器工具；画布再次导出并核对内容戳、以单个撤销事务修改，返回精确操作回执。插件仅在核对同一绑定和回执后返回带 XML 的独立成功工具结果。重复通知、ACK、超时、断线及旧连接均不能使候选再次应用。

发送准备选择当时的活动画布；显式图表引用仍须精确匹配已准备的同会话实例。模型的读取操作返回当前准备内容，修改必须提交读取时的内容戳。目标不明时返回候选名称/身份供模型询问，不能按标题猜测。正常发送与首页首发均需经过准备；准备失败必须在真实发送之前结束。

普通桌面 `chat.send` 不支持 browser-copilot 专用的 `toolBindings`。有画布准备时改经插件认证 `drawio.chat.send` 包装：先将准备快照冻结到确切 `idempotencyKey`（即本轮 `runId`）、会话和原连接，再沿同一认证调用者只派发一次原始 `chat.send`。工具自有 `prepareBeforeToolCallParams` 接收的真实 `runId/toolCallId/sessionId` 与 v2 工具上下文配对，执行前再次检查调用仍有效。模型参数和提示文字均不参与授权。缺少字段、返回 run 不匹配或发送结果未知时安全拒绝，不做后缀匹配、重试或换绑；新的准备不能替换旧轮次快照。锁定运行时探针验证这一精确关联，不新增通用 run 绑定能力。

已有恢复视图的原生工具授权保持为空，宿主恢复载荷中的消息、上下文、文件等能力关闭。公开 preview helper 没有原生 readOnly 租约参数，不能将这些宿主限制表述为原生租约标志。恢复后可本地编辑、保存；继续通过模型修改须经过新的发送准备与独立插件绑定，不能恢复旧 MCP 工具权限或假设原生 `updateModelContext` 可写。最新图恢复核对初始来源与成功插件工具结果的关联链；无回执候选不纳入恢复。

侧栏空白和文件入口的 app-only 启动不保证出现在聊天工具历史中。首次成功修改的真实插件结果必须附上已认证的来源收据（图表、精确会话、原视图及入口类型），允许恢复从这份结果开始；不能强制依赖此前存在 `create_diagram` 记录。宿主传入的 descriptor 或 XML 中的 ID 不是来源证明，绑定必须另核真实原生来源。

成功修改的可见工具结果同时包含有界 `drawio.diagram-reference.v1` 记录（最多 4096 字符），只有标题、来源与调用关联；完整 XML 和原收据继续保留在 `details.diagramUpdate` 及原生记录中。实际 `chat.history` 会过滤自定义 details，因此历史定位不再依赖 details 存活。宿主沿通用 [MCP App 引用接入](../plugins/mcp-app-references.md) 校验真实工具、精确调用与已有 run 身份，再投影紧凑入口。失败、未知及模型示例不产生成功回执，也不扩大正常预览抑制范围。

用户固定消息图只改变位置，保持同一个 iframe、AppBridge、未提交节点文字和撤销栈。已有侧栏空白／文件图仍定位原 Tab；引用 Tab 关闭只移回消息，原应用自身关闭保持真正关闭。只读恢复保留原内容来源，同内容历史回执不重复创建恢复视图，不注册旧编辑授权。

来源声明沿用现有桌面宿主信任边界：只有持有 operator.admin 的宿主内部适配能声明已原生准入的来源，App 沙箱与模型不能访问该入口。适配仅接受 `isNativeMcpAppPreview` 准入对象，立即捕获不可变的服务、工具、资源和原生绑定，防止 WeakSet 对象后续变更。RPC 的 `mcp.app.view` 只证明真实视图和会话，不独立证明 serverName；另沿该 view 的原连接读取 `diagram://origin/<id>` 核对服务器曾签发此图表。不能换用可能属于另一 harness 连接的静态 MCP manager。恢复来源锚点明确标为经认证宿主声明及真实插件结果，不冒充原生 MCP descriptor。

原生宿主文件订阅不等同 MCP server 的 `resources/subscribe`，不可据此设计 server 推送。使用公开插件 Gateway 事件和认证查询；若事件漏失，只允许重新查询状态，已经派发的修改不得重新应用。

宿主按注册时不可变的会话、连接代次和 agent 筛选画布，实时可用状态由保留视图提供；不能用切换后的当前聊天身份重新标记旧注册。暂停会话使本地操作代次失效并发出精确 owner 清理，即使准备响应未知也可清理。RPC 在首次 await 前建立有界准备闸门；后来的准备或 owner 清理使旧准备失效，不能在清理之后重新建立孤立绑定。下一次明确发送可以退休同一连接与视图的未知准备，不允许跨视图或连接接管。首次发送在异步准备结束后复核取消、client、连接代次、key 和物理会话，再发真实请求。

实际锁定运行时和标准 AppBridge 分别验证可信绑定、当前内容、同编辑器写入、应用回执和原生恢复。插件工具不能冒充 MCP 结果来绕过准入。

2026-10-21 回归发现：`sessions.create` 将项目目录保存在 `spawnedCwd`，模型执行使用原生 ingress workspace resolver；手动 App 准备却只检查 `spawnedWorkspaceDir` 或角色 home。两者不同时，后续模型运行替换同会话的 MCP runtime，导致原视图交互来源与离线资源服务失效，但已经加载的 iframe 和插件画布 token 仍在。现象是第一次准备可成功，下一次继续发送报 `Diagram operation unavailable`。原探针将角色目录与项目目录设为相同，遗漏了这个条件。

运行时补丁 `031-mcp-app-session-workspace.cjs` 让手动 App 复用模型执行已有的 `resolveIngressWorkspaceOverrideForSessionRun`，按原生规则选择有 lineage 的 inherited workspace、持久 cwd 或角色 home；将这些持久事实加入当前准备的 fingerprint，异步过程中变更则拒绝旧准备。公开 App API 没有 workspace 覆盖参数，插件无法替代原生 owner 的目录选择。修复不跳过同视图来源证明，不复活旧工具授权，不延长租约，不实现新的取消或释放协议。上游手动 App 与会话执行采用同一规则后可移除此补丁。

准备读取还有独立的原生暂态：membership/session facts 刷新时，原生明确返回 `UNAVAILABLE`、`SESSION_ACCESS_REFRESHING` 并标记可重试；当前公开 SDK 只保留 code/message。插件仅对准备阶段的 `mcp.app.view` 与原连接来源读取、且 code 和固定刷新消息完全匹配时等待，每项查询最多读取五次、等待合计最多 1.5 秒；每次读取前后及等待结束均核对原 owner 与准备闸门。其他错误直接失败，清理或断线不允许旧准备复活，发送、启动和应用操作不重放。此处完全由插件实现，不增加原生补丁。

首期验收覆盖：侧栏空白图直接生成、连续两次修改不新建编辑器、单步撤销、未按 Enter 的文字、用户并行手改的冲突、两个同名图、显式引用优先、切换聊天后的迟到结果、重复/过期 ACK、断线未知状态、已确认内容重启恢复，以及原生历史和外部预览不被误改。

编辑器和模型工具实现归 plugins/extensions/drawio；宿主只接入必要的标准桥、目标准备、标签与历史投影。插件不导入应用 src，必需 Runtime Services 不依赖可选 draw.io。继续满足离线资源、CSP、导航和中英文文案要求。

对应验证：插件 `canvas-state`、`editing`、`current-canvas`、`update-result` 测试覆盖授权、幂等、冲突与恢复选择；`tests/drawio/current-canvas-navigation.test.ts` 联合真实会话适配与插件 RPC，覆盖本地请求已取消但后台继续准备的顺序；普通/首发 controller 测试覆盖取消与旧绑定失效。

## 7 后续增强的触发条件

用户实际需要“找回前几轮修改”，再增加有限 AI 修改快照或版本卡；需要跨重启保留任意手改，再设计草稿自动保存；需要多人/多窗口同时修改，再设计写入接管与合并。每项独立评估，不将完整历史版本系统重新设为连续编辑的先决条件。
