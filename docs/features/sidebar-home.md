# 侧边栏首页与页面能力评估

## 当前首页

侧边栏首页以“新标签页”呈现：首次打开空侧栏时自动创建一个浏览器空白标签，使用顶部地址栏输入网址或搜索，下面是工具与最近访问。页签栏加号直接新增并切换到另一个“新标签页”；工具为审阅、终端、文件、侧边聊天、浏览器，从页内选择，各入口沿用原有上下文与容量限制。新会话首页只展示可用能力。关闭所有标签且侧栏仍打开时恢复一页，切换会话或重新展开侧栏时复用已有标签。

首页地址栏旁仅保留常规浏览器导航与菜单，录制、标注和注释入口在打开网页后显示；切回空白标签时隐藏相关工具与标注界面。

工具区使用侧栏宽度作为布局依据：440px 起两列，更窄时单列；最近访问对应四列/两列。工具高度统一为 40px，图标、文字与快捷键对齐，使用已有主题 token，支持中英文、键盘焦点和长标题省略。快捷键取自用户设置；审阅没有现成快捷键，因此不显示占位提示。

最近访问使用现有浏览器历史，最多展示四个不同页面，支持加载、空状态和失败提示；首页打开时刷新，不后台轮询。站点图标优先使用网页声明并随历史保存的真实 favicon，旧记录或加载失败时尝试该站点的 `/favicon.ico`，仍失败则显示通用网页图标。图片请求不带 Referer，不依赖第三方图标查询服务；清理历史也会删除关联的图标 URL。点击网页在当前会话的内置浏览器打开，浏览器新标签页则导航当前空白标签；新标签页复用工具区和最近访问，搜索仍使用其原地址栏。

## Codex 的“新建页面”是什么

调研日期：2026-10-03。

OpenAI 官方 [Work with pages](https://learn.chatgpt.com/docs/space/pages) 将 Page 定义为可由用户或 ChatGPT 编辑的文档，适合笔记、计划、研究和长期参考资料；提供块编辑、子页面、引用、选区改写及协作等能力。文档中的 New page 是创建这种文档的入口。

官方 [Browser](https://learn.chatgpt.com/docs/browser) 另将 New tab 定义为浏览器标签入口。结合截图中已有浏览器标签、“新建页面”的文档图标以及当前桌面 Page 能力，判断截图入口很可能对应上述 Page 文档；公开文档没有明确说明该工具区按钮的具体绑定，不能仅凭截图把这点写成已实测事实。本次没有点击入口创建用户页面。

## 是否需要做

建议：后续考虑轻量的“新建文档”，当前首页不增加“新建页面”入口。

项目已支持 Markdown/文本文件的编辑、预览、保存以及 HTML 的浏览器预览。用户沉淀任务结论、手写笔记和继续修改助手产物的需求有价值，现有缺口主要是从界面直接创建文档及把选中的对话内容保存为文件。可以先在项目目录内创建 `.md`，再直接打开现有编辑/预览标签；产物保持为普通工作区文件，便于助手读取、备份和版本管理。

完整 Page 系统还涉及块编辑、页面树、引用关系、版本冲突和共享权限，明显超出这次侧栏优化。当前本地优先架构没有必要为一个按钮先引入独立云端文档体系。

若推进轻量版本，建议范围为：选择保存位置和文件名、排他创建防覆盖、复用已有文件编辑授权与冲突检测、打开预览，以及用户明确触发的“保存选中内容为文档”。创建内容由用户指定或助手正常执行文件工具；不额外扫描、复制或持久化聊天记录。入口命名为“新建文档”更清楚。多人协作与页面关系管理等真实需求出现后，再评估专门的页面能力。
