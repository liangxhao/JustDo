# 协作展示优化实施计划

> 阶段性实施记录：测试数量与展示方案属于当时提交。当前协作入口、消息读取与成员限制见[协作机制](multi-agent-collaboration.md)。

状态：已实施。17 项定向测试通过，整体 ESLint 与生产构建通过；未进行新的真实模型端到端验证。

本轮范围：复用已接通的协作房间和真实投递记录，优化关系图、时间线和节点导航。原生 sessions_send 替换、右键菜单整体语义改造仍按各自设计分期，不在本轮混入执行协议变更。

1. 保留一个协作标签：上方小型关系图，下方倒序事件时间线。节点进入现有原生消息详情；连线筛选准确方向，再次点击或清除筛选返回全部。事件只使用投递元数据，不生成未经证实的内容摘要。
2. 时间线标识发送/回复、日期时间、收发助手与投递状态。失败和确认未知有文字及颜色；已接收不等于已完成。保留按事件打开原生消息的能力。成员运行结束显示空闲，避免当成业务完成。
3. 图在窄面板横向滚动而非无限缩小，成员名字截断但可查看完整名称；保持键盘节点/连线操作。节点位置不随投递更新改变。
4. 首次成功加载房间列表只建立基线。之后新出现的当前任务房间自动展开一次；后台任务只更新入口，切换任务期间的迟到响应不能抢焦点。刷新和追加成员不重复展开，因此手动关闭后不打扰。
5. 回归验证：初始历史不展开、新协作只展开一次、后台/切换不抢焦点、乱序响应、定向筛选与清除、倒序及状态、节点消息回退。运行定向测试和类型/lint/build 检查。

无需新增工具栏按钮、流程编辑器或 transcript 缓存。当前数据没有任务内容摘要/审批全量投影，不虚构这些信息；时间线显示“发送消息/回复消息”及实际状态。
