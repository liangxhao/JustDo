# 模型自主使用多助手：接入规划

> 本文保留创建助手功能的初始规划及实施记录。当前工具随默认关闭的 agent-team 扩展启用，不在普通 turn 自动注入协作指令；现行档案和创建路径见[助手管理](multi-agent.md)。

状态：已接通模型发起协作与长期助手创建。以下保留设计原则及验收范围，实施结果见文末。

## 原则与完成目标

模型自主决定是否查询、创建、选择助手，以及何时发送消息和继续工作。产品不制定固定的“查询→创建→加入→发送”状态机，不实现第二套任务分配器、团队规划器或自动接力循环。

软件负责三件事：让适用的原生工具对模型可见；让原生助手和会话正确映射到产品；把真实执行与通信呈现在现有界面。原生已有能力只接入，确认缺口后才补最小适配。

用户可在主会话说“请审查助手检查这次修改”或“创建一个审查助手参与工作”。模型自主选择调用；用户不必离开聊天设置目录。主会话不切换，成员列表、协作图与节点消息按真实事件更新，不增加顶栏按钮。

## 职责边界

| 事项                                                 | 负责方                               |
| ---------------------------------------------------- | ------------------------------------ |
| 是否需要其他助手、选择谁、如何分工、何时结束         | 模型                                 |
| Agent 创建、配置工作空间、原生会话与执行、跨会话消息 | OpenClaw                             |
| 当前会话参与者关联、设置页记录、状态和图展示         | 产品                                 |
| 工具参数、已有权限、成员范围和并发一致性校验         | 原生与产品边界各自校验，不替模型决策 |

助手配置、参与本次协作、执行一次任务是不同概念。不要将创建等同于开始工作，不用 sessions_spawn 代替长期助手创建。Agent 专属指令在独立配置空间，项目 cwd 默认沿用主会话，不相互覆盖 AGENTS.md。

## 第一步：确认模型实际能调用什么

在本产品锁定且打补丁的运行时进行工具可见性与调用验证，不仅检查 ../openclaw 的源码。分别检查无协作房间的主会话、已有协作的主会话和成员会话，记录工具名称、输入契约、配置过滤、实际结果。

| 能力           | 已发现的原生入口                          | 需要验证                                                     |
| -------------- | ----------------------------------------- | ------------------------------------------------------------ |
| 查询助手       | agents_list 工具、agents.list Gateway API | 实际是否暴露、是否按 Subagent 允许目标过滤、能否满足协作查询 |
| 创建长期助手   | agents.create Gateway API                 | 是否已有合适模型入口；若有直接启用，否则才加薄适配           |
| 配置与专属指令 | agents.update、agents.files.get/set       | 是否满足新助手初始化，不开放无关管理权限                     |
| 会话通信       | sessions_send 工具                        | 跨 Agent 策略、目标会话解析、确认与回复语义、事件关联        |
| 派生任务       | sessions_spawn 工具                       | 保持原有 Subagent 语义，不混入平级成员关系                   |

交付一份能力核对表，每项结论为“直接可用 / 配置接入 / 缺少适配 / 尚需验证”。先验证一轮原生查询和通信，再决定新增工具；不预设 assistants_list 或固定数量的管理工具。

## 第二步：补最少的接入缺口

### 工具暴露

原生工具满足需求时只调整注册或配置。创建仅有管理 API 时，提供一个窄范围适配，接受名称、职责、专属指令和可选模型，调用原生创建接口。工具名称在能力核对后确定；不提供任意 Gateway RPC 执行器，不实现原生已有的创建目录或生命周期逻辑。

提示词只说明工具能力、何时适合复用助手，以及平级协作与 Subagent 的区别；不强制调用顺序。用户明确要求创建时才新增长期配置，日常协作优先复用；模型根据结果自行决定下一次调用。

### 会话与协作界面关联

先验证能否通过可信的原生会话/通信事件自动登记本次参与者。可以可靠关联时，参与者自然出现，不要求模型额外调用只为刷新界面的“加入”工具。

若原生无法表达目标助手在当前任务中的独立会话，才增加“确保当前协作成员会话”的最小操作，返回可供原生发送使用的目标。必须保留当前主会话，在运行中只准备新成员，不重置主会话。关联键至少包含房间、Agent 和原生会话；同一 Agent 在别的任务中的会话不能误归入本房间。

原生 `sessions_send` 已验证可支持停止、接收确认、回合范围和消息关联，因此新任务只使用原生发送链路。产品继续维护成员关系与派发保护，并保留旧 `collaboration_send` 历史的只读展示兼容。

### 配置与界面同步

原生创建成功后，产品设置页必须看到同一个 Agent，后续产品配置同步不得将其覆盖。复用共享 Main 业务服务协调设置入口与模型入口，保持一个 agentId，不复制原生管理逻辑。

现有配置写入有空闲限制，原生创建是否需要重载必须验证；不直接移除保护。若暂时不能立即生效，返回真实 pending/unavailable，不中断主会话、不谎报成功、不让工具等待发起它的运行结束。仅当验证表明必要时，设计最小的持久恢复记录；它服务于一次工具操作的一致性，不负责自动调度后续任务。

原生创建当前由 name 推导 ID，需验证中文显示名与稳定 ASCII ID 的映射。模型不填写工作目录、凭据或提升权限字段。重投与 RPC 超时先确认原生结果，不盲目重复创建；部分成功保留真实结果，让模型决定重试或继续。

## 第三步：呈现真实调用，不新增复杂交互

- 主聊天：模型回复、原有工具调用与成果。
- Agent 列表：本次实际参与的助手及运行状态。
- 协作图：可信事件对应的发送方向和消息数量，不把配置关系画成通信。
- 节点详情：复用 ChatController / ChatMessageDisplay，读取该成员原生历史。
- 创建结果：沿用工具消息反馈并刷新设置列表；准备中和失败以简短状态表达。

Renderer 读取原生历史与实时事件，不新增 Main/Redux 消息正文缓存。原生管理接口成功、消息已接收、Agent 工作完成分别展示，不能混为同一状态。

## 实施批次与验收

### A：能力核对与原生最小验证

输出实际工具清单和策略差异；验证主会话在运行中查询/发送，并验证创建接口的运行影响。结果决定 B 的具体改动，避免提前造通用管理框架。

### B：接通已有助手协作

补工具可见性或目标关联缺口。用户请求协作后，由模型自主调用已有助手；双方真实消息出现在图中，主会话继续保留，成员详情可查看。若当前已有路径满足条件，只补必要映射，不重写执行链。

### C：接通自然语言创建

有原生模型入口就复用，否则添加薄工具适配。验证中文名称、默认模型、专属指令及产品配置一致性。用户只要求创建时不自动派发；要求创建并协作时模型可自行继续调用通信能力。

### D：回归

覆盖工具重复投递、超时结果不确定、并发创建/成员上限、配置同步、重启恢复需求、跨任务误关联、停止与既有权限。原有手动设置、Subagent、搜索、主会话草稿和原生历史不回归。测试验证结果与边界，不锁死模型调用顺序；用隔离模型夹具检查工具协议，另做真实模型手动验收。运行相关 Vitest、lint、build；存储或运行时架构变化时同步对应 architecture 文档。

## 本轮不做

不新增固定调度器、强制先查询再创建的编排、临时助手体系或自动 worktree。连线详情与通信时间线后续独立完善。除非第一步证明必要，不新增重复的查询工具、加入工具或持久化操作框架。

## 已实施：模型发起协作与界面关联

主会话首次调用 `task_assistants({ agentId })` 时，产品为已配置且启用的助手准备独立会话并登记成员；随后模型使用返回的精确 `sessionKey` 调用原生 `sessions_send`。用户无需勾选或先建立房间。已有房间可由主会话继续准备成员，同房间成员之间也使用原生通信。创建长期助手通过 `assistants_create` 接通原生管理 API，详见下文。

源码核对发现 agents_list 按 Subagent allowAgents 策略过滤，不能为平级协作扩大该权限。已有 collaboration_members 因此补充 available 字段，仅向当前主会话返回产品中可参与的助手，不增加重复查询工具。原生工具调用身份、Plan 模式限制、回合预算和停止语义保持有效。

界面取消勾选和开始协作按钮；参与者变化沿用 sessions-changed 通知刷新。节点和成员列表显示会话状态；连线筛选双方往来的投递记录；点击记录以原生 idempotencyKey 和可信来源定位消息并复用聊天渲染。查看投递正文时按需翻阅原生历史；尚未投递或原生历史中不存在的消息明确提示不可用，不展示无关会话内容。

## 自动协作接入后的交叉审查

执行、界面、消息详情三个方向独立审查并交叉复核。发现并修复的边界包括：

- 扩展请求超时后，慢速原生准备仍继续派发：请求携带统一截止时间，宿主在异步边界复核，过期则清理；不同主会话的准备不再共用全局串行锁。
- 旧成员列表响应覆盖新快照：只应用最新刷新请求的结果，保留新加入成员与协作入口。
- 旧通信记录缺少分页路径：复用原生历史翻页定位，保留精确来源匹配，游标停滞或请求失败时结束搜索。
- 切换消息短暂混入旧内容：消息数据关联会话、receipt 和来源身份，在效果清理之前即阻止错误归属的展示。
- 加载错误与执行错误混淆：已有会话的执行错误不阻止查找历史消息，真正分页失败单独显示错误。

这些修改只修复协议与展示边界，不增加模型调度流程或用户操作步骤。

另补充成员查询的精确来源身份校验，并将界面通知失败与已提交的成员关系隔离，避免窗口销毁导致成员回滚或房间残缺。此次相关回归共 59 项通过，覆盖执行、存储、扩展协议和界面。

## 已实施：自然语言创建长期助手

模型入口为 `assistants_create`，接受名称、职责、AGENTS.md 指令和可选 provider/model；用户不填写工作目录。锁定运行时提供 `agents.create` 管理 API，但没有对应的原生模型创建工具，因此由现有 collaboration 扩展暴露这个窄入口，Main 调用原生管理能力。创建成功后只刷新现有助手列表；模型可继续用 `task_assistants` 准备它并通过 `sessions_send` 派发工作，不增加按钮、向导或固定编排。

原生工具钩子提供 session/run/toolCall 身份，Main 校验当前用户运行、所属主会话和截止时间，Plan 模式禁止创建。创建与产品配置同步共用配置写锁。稳定 ASCII ID 与中文显示名分离：agents.create 建立受管配置空间，等待 agents.list 的运行时快照可见，再以 agents.update 设置显示名、agents.files.set 写入指令，并读回核验后启用产品档案。不为创建重启正在工作的 Gateway。

SQLite 现有 kv 保存 assistantCreation:<agentId> 的参数摘要及 preparing/ready 状态，不保存指令或消息正文。原生操作结果不确定时保留停用档案并返回 incomplete；相同参数重试可继续，同名已完成助手只返回 existing，不覆盖原有配置。后续产品同步保留启用档案与原生配置空间，重启不丢失指令。

自动验证使用本地确定性模型夹具驱动真实 Electron、OpenClaw Gateway 和原生工具链，覆盖创建中文助手、立即双向协作与持久化；它验证工具协议，不替代真实模型对自然语言意图的手动验收。
