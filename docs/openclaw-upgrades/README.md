# OpenClaw 升级记录

本目录按目标版本保存差异、产品接入决策、审查和当时的验证范围。记录只适用于对应版本与提交，不替代当前架构，也不是最新补丁清单。

- [v2026.10.4 升级记录](v2026.10.4/README.md)：目标包、补丁与 SDK 适配，以及已验证和待人工验收的范围。
- [v2026.9.8 升级与验收索引](v2026.9.8/README.md)：主要升级决策、关键修复与合并后的验收摘要。
- [v2026.9.6 历史升级审计](v2026.9.6/README.md)：从 9.2 升级的历史记录；该应用构建未发布。

当前版本以 `package.json.openclaw.version` 为准；操作规范见[补丁指南](../openclaw-runtime-patches.md)，能力、原生处置及移除条件以[当前补丁总账](../../scripts/patches/v2026.10.4/README.md)为准。

## 目录结构要求

每个目标版本使用独立的 `vYYYY.M.D/` 目录，且统一只使用以下三个文件；专项内容使用文件内章节，不另起主题文件或重复使用版本号命名。

```text
openclaw-upgrades/
  README.md
  vYYYY.M.D/
    README.md
    upgrade.md
    validation.md
```

| 文件 | 必须记录的内容 | 内容边界 |
| --- | --- | --- |
| `README.md` | 本版本范围、历史适用边界，以及另外两个文件的入口 | 保持简短，不堆放升级正文与测试流水 |
| `upgrade.md` | 来源与目标版本、源码/发布包依据、上游变化、产品接入与不接入的决策、补丁和 SDK/依赖适配 | 解释改了什么、为什么改；验证结果链接到 `validation.md` |
| `validation.md` | 自动化测试、构建与产物身份、独立复审、真实界面/设备/安装版验收、失败及修复复验、未完成项和复验入口 | 按阶段或专题分节，明确提交、日期、环境与证据边界；没有证据的项目写明未记录或未验收 |

三个文件在每个版本目录中保持一致。历史记录按实际内容归位，不补造缺失的测试或验收结论；不同阶段的结果不可累加或冒充最终产物证明。专项验证统一加入 `validation.md` 的具名章节。

移动内容时同步修正仓库内引用、相对路径与章节锚点。当前契约仍维护在 `docs/architecture/`、`docs/features/`，逐项补丁清单在 `scripts/patches/<version>/`，下载信息在 `docs/offline-downloads.md`；这里保存升级历史，不提交原始日志或凭据。
