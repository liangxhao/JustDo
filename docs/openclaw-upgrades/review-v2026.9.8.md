## 结论与证据口径

**后续范围调整：9.6 未发布，用户要求删除本次新增的旧数据兼容。9.6→9.8 SQLite 迁移桥接、启动门禁、测试与构建资产已撤回。本文旧数据演练及其辅助入口修复仅为历史证据，不再代表现行能力，也不能使用已删除脚本复跑。其余功能与运行时测试证据保留；既有全量数字属于当时版本，不能当作删除后的再次测试。**

本报告记录升级后的第二轮独立审查。四个并行方向分别核对消息／权限、浏览器／插件、任务／记忆／模型、运行时／补丁与上游能力。既检查应用和原生源码契约，也执行针对性测试、实际 Gateway 离线测试及原始包重建。

## 第二轮发现的问题

| 问题 | 影响 | 处理与验证 |
| --- | --- | --- |
| 浏览器原生扩展未完整同步 | 缺少 9.8 严格 JSON 认证模块，旧哈希表只能证明旧文件彼此一致 | 刷新 8 个原生文件并新增 strict-json，26 个交付原生文件对齐原包；修正协议常量所属模块校验，实际扩展构建通过 |
| ACP 默认状态目录未对齐 | 启用外部助手会在角色工作区创建旧 state 目录 | 跟随原生使用 stateDir/acpx；显式用户目录继续生效，不自动移动旧文件 |
| skipped 工具状态未投影 | 被跳过的工具可能显示“已完成” | 同时处理实时事件和历史活动，增加中英文状态与回归 |
| queued／旧运行状态提前结算 | 列表事件可能把仍在排队或执行的新运行标为结束 | queued 不作为终态，原生 sessionId／lastRunId 与当前执行匹配后才结算，保留明确 reset/delete 边界 |
| 配置检测被提前视为应用成功 | 动态字段异步发布失败或 reload 被禁用时，设置仍可能显示已生效 | 所有字段等待原生完成或失败；修正 dynamic reads 日志关联；插件加载规则按新版热加载处理 |
| Windows 编译缓存保护被启动器绕过 | 深层用户目录可能在 Node 启动或显式启用缓存时挂起 | 子进程启动前及两种 CJS 启动器均执行原生 200 字符保护；保留用户显式禁用，短路径正常缓存 |
| 定时任务清理误用导航父级 | 可能删除已改挂控制归属的子会话 | 只沿 spawnedBy 建树；删除前复核会话身份和控制归属，继续传递原生条件删除约束 |
| 旧 SQLite 数据库升级演练（方案已撤回） | 曾验证 shared18／agent23 到新版 schema | 9.6 未发布，按用户要求移除本次新增迁移；历史通过不构成当前兼容承诺 |
| 迁移入口打包检查（随方案撤回） | 曾发现 Vite 主 bundle 旁缺少独立入口 | 当时修复并验证；入口及对应 Vite 资产现已一并移除 |

第一轮还修复了新版 worker 打包定位、异步 metadata 读取、编译后补丁验证及 Windows namespaced 路径导致的会话创建失败。第二轮发现说明只检查版本号和构建通过不足以判定升级完成。

## 上游新增能力：应接入什么

9.7 是主要功能版本，9.8 官方声明没有刻意新增能力，主要修复可靠性。判断是否接入时须区分 Gateway 原生能力、应用已有入口和另一个产品的界面；交付运行时并不意味着复制了上游 Control UI。

| 新能力或重要变化 | 决策 | 原因与后续工作 |
| --- | --- | --- |
| 统一 decision_evaluate，Boolean／Choice／Score | 本次必须，已接入 | 替代移除的 TypeSafe 专用工具；保持内网服务、默认决策模型及凭据边界 |
| Kie／Z.AI／Novita 视频 | 本次必须，已接入 | OpenAI 视频提供方被移除；新增原生设置与插件；按用户要求移除旧自定义兼容展示，非空配置必须选择受支持原生提供方 |
| 通用 Tasks 注册表移除 | 本次必须，已适配 | 子代理和工作看板改用原生会话／运行身份，不重建替代 ledger |
| Worker 化历史／写入／文件／元数据 | 本次必须，已适配 | 更新打包入口、metadata 异步读取与生命周期检查；性能收益由原生执行提供 |
| 流式 append delta、快照恢复、工具 skipped | 本次必须，已适配 | 自有 Renderer 必须理解新协议，不能依赖上游 UI 自动获得支持 |
| pendingInput 收据和逐输入取消、state contention 状态 | 原生输入恢复已补齐；独立队列管理仍为后续增强 | 主聊天与浏览器侧栏恢复原生 pendingInputs、分页与取消／中断状态，并按回执与原生身份去重；队列数量／逐条取消入口尚未接入。停止仍遵循现有 sessions.abort(clearQueued:true) 语义 |
| Windows session、cron、只读技能和缓存修复 | 本次必须 | 保留原生修复并核对应用启动器与 MXC 是否绕开；新增会话路径修复和缓存保护 |
| 原生插件热加载与保留工作结算 | 本次必须，已适配 | 应用等待原生完成，不抢占重启，不在开关／配置操作后提前报告成功 |
| 新插件 capability／setup／tool 预览 | 建议后续界面增强 | 原生目录数据可用不等于应用已展示全部字段；优先增加能力和配置要求说明 |
| 插件账户／凭据状态 | 建议后续界面增强 | 可减少“已安装但不能用”的误解；需要统一凭据状态和账户选择产品语义 |
| 管理 Git worktree 会话 | 现有流程承接 | 使用已有 sessions.create(worktree) 入口，原生负责绑定、取消和清理 |
| 子代理按发起会话限流、queued 与完成唤醒 | 原生继承并验证显示 | 无需在应用建立新的子任务调度器 |
| cron.history | 原生可用，暂不重复接 UI | 现有 run/sessionId 结果历史与分页已满足应用；若增加原生专用历史入口再适配 |
