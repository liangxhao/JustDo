# v2026.9.8 浏览器、插件与外部工具复查

## 结论与证据范围

本轮在升级检查点 `98bc2299d` 后独立复查，发现并修复两处遗漏：浏览器扩展仍使用旧原生快照；本地 ACPX 分支未采用 9.8 的默认状态目录。没有修改已验证运行时、manifest 或补丁证明，也没有操作用户实际插件、浏览器配置与账号。

依据是相邻源码仓库的 `v2026.9.6..v2026.9.8` 标签差异、锁定 npm 原包的 `dist/extensions/browser/chrome-extension/`、应用实际配置及 IPC 入口。不能用已生成的旧主运行包证明新版正确；主工作区运行包仍因外部文件句柄占用停留在 9.6，新版隔离产物由主审查流程重新构建。

## 修复一：浏览器原生基线遗漏

升级说明曾将“浏览器扩展”和两个保留技能一起记为无变化。实际标签比较显示，浏览器目录有 24 个源码／声明／测试文件变化，其中交付的 JavaScript 有 8 个修改文件，另增加 `modules/strict-json.js`。原来的校验和清单与旧快照彼此一致，因此旧测试无法发现版本遗漏。

本轮从锁定 npm 9.8 原包刷新 `resources/browser-extension/openclaw/`，同步构建脚本的完整文件／哈希清单；26 个上游交付文件逐一比较通过，文本仅统一换行，二进制逐字节比较。本软件保留的第三方许可说明另行保留，没有伪装成 npm 原包文件。

9.8 将严格 JSON 对象解析提取为独立模块，并移除 relay-core 中不再使用的协议／颜色帮助函数。原构建验证把 v2 协议常量限定在 relay-core，会拒绝正确的新版快照。现按原生所有者验证：relay-auth-v2 拥有协议常量，relay-core 拥有配对持久化字段。新增测试验证交付目录包含严格解析模块，并验证重复键、嵌套重复键、非对象与非法 JSON 被拒绝。旧版已有重复键防护，此修复不宣称发现或修复了新的认证漏洞。

`conversation-overlay/` 未混入原生配对、认证或标签授权代码。现有构建接点仍仅负责品牌、侧栏入口、应用 native host 与配对提示；全部接点在新版快照上通过唯一锚点检查。真实执行 `prepare-browser-extension.cjs` 已生成并逐文件验证 `build/browser-extension/chrome-extension`，不是只运行模拟构建。

两个保留技能另行比较：`skills/coding-agent/` 与 `custodian-skills/diagnose-gateway/` 在 9.6 和 9.8 标签间无差异。升级说明已将这两项结论拆开。

## 修复二：外部工具默认状态目录

9.8 原生 ACPX 将缺省状态目录从 `workspace/state` 改为原生状态根下的 `acpx`。本地分支的 `config.ts` 仍保留旧默认值，`service.ts` 也未传入服务上下文的 stateDir。应用生成的 ACPX 配置未显式设置该字段，因此启用或测试外部工具时仍会在角色工作目录创建 `state`，并从该目录进行历史 session 文件名扫描。

现在服务将 `ctx.stateDir` 传入配置解析，默认采用 `stateDir/acpx`；无服务上下文的独立调用使用公开 SDK 的 `resolveStateDir()`。显式配置的 stateDir 继续优先。测试覆盖更换 workspace 后状态根保持稳定、显式覆盖和 SDK 缺省值。没有搬迁或删除旧目录、旧 transcript，也没有新增历史兼容读取器。真实持久化会话所有权仍由现有原生 plugin keyed store 管理；本次不把目录扫描误称为会话数据库迁移。

## 历史记录：旧状态升级方案已撤回

9.6 版本未发布，用户已明确要求移除本次新增旧数据兼容。旧状态演练曾发现 agent23/shared18 与新版 schema 的差异，并曾验证窄原生维护桥接；该桥接、启动门禁、测试和构建资产现已撤回，不属于当前功能。

历史测试曾使用两个全新合成状态，各报告 1 个 agent、2 份备份，重复执行不再变更，配置哈希保持一致；当时21项桥接测试通过。这些仅说明已撤回方案的验证经过，不是现行兼容承诺，也不再提供该流程的复跑入口。其余浏览器、插件与 ACP 测试证据不受此范围调整影响。
