# OpenClaw v2026.9.6 → v2026.9.8

升级后第二轮并行审查的修正、完整功能验收表和新功能接入决策见
[最终复核总报告](review-v2026.9.8.md)。该轮补齐了浏览器原生快照等验证缺口；
9.6 未发布，之后按用户要求撤回了本次新增的旧数据兼容迁移及其测试、构建资产。
相关旧数据演练只作为历史证据，不属于当前能力。本页保留第一轮升级背景。

## 审计依据与范围

对照相邻源码仓库的 `v2026.9.6..v2026.9.8`、两个版本的原生
`CHANGELOG/2026.9.7.md` / `CHANGELOG/2026.9.8.md`，以及 npm 发布的原始
`openclaw@2026.9.8`。运行时和 Windows MXC 插件均锁定 2026.9.8；Node
24.21.0 满足版本要求。原包 integrity 与 SHA-256 在
[source-lock](../../scripts/patches/v2026.9.8/source-lock.json) 中。

9.7 是功能与架构更新；9.8 明确为可靠性修复版本，没有刻意新增能力。
升级不能只换版本号：9.7 删除了旧任务注册表 RPC、TypeSafe 专用工具和
OpenAI 视频提供方，并改变模块划分和部分异步执行边界。

## 不自动引入的新产品入口

OpenAI Agents API、ChatGPT 登录 Beta、Gemini Interactions、Telnyx、
Lightpanda、云 worker/Portal、会议/FaceTime、多用户角色和移动端/Apple 原生 UI
需要各自的认证、配置、权限或产品界面，不能通过升级本地 Gateway 声称已完整接入。
新出现的 `agentsapi` 纳入显式裁剪审计。Kie 保留于运行包，Z.AI / Novita
官方插件分别锁定 `@openclaw/zai-provider@2026.9.8` 和
`@openclaw/novita-provider@2026.9.8`；视频服务由用户配置后启用。
Codex Ultrafast 和原生 harness Ultra 的选择也不等同于应用的推理等级。

上游 Control UI 的时间线、在线成员、桌面音频、会话筛选、表格布局等属于另一套
前端；本软件继续使用自己的 Electron/React 界面。原生 updater 的备份和回滚改进
不会取代本软件锁定原包、补丁、打包验证的更新流程。

## 补丁与打包

重写并保留 22 个补丁模块，另新增 032 修复 Windows 会话创建，共 23 个；逐项功能、重写接点及移除条件见
[当前补丁总账](../../scripts/patches/v2026.9.8/README.md)。008 的旧 task-registry
部分、021 的 OpenAI-video 部分退役；此前已经退役的补丁不重新引入。

新版多出 activation-recovery 内嵌副本。源码模块、两个 worker、该 recovery
入口及最终 Gateway bundle 按实际可达职责检查，不能沿用旧目标数量。
历史或部分 marker 拒绝原地升级，失败从原包重建，不能重写 manifest 伪造证明。

真实 Gateway 验证发现，Windows SQLite 返回 namespaced 路径，而原生会话发布
守卫使用普通路径比较，导致 `sessions.create` 被拒绝。032 仅将比较两侧统一为
原生 namespaced 路径，保留大小写、数据库、agent、session key 与当前所有权检查。
打包还适配了新版共享进程工厂及 53 个原生进程入口（较 9.6 新增 12 个），
确保 worker 和动态运行时模块从各自原始模块位置加载。

MXC 仍使用 SDK 0.8.0，四个 Windows 二进制哈希与上版一致；外部技能路径、
能力 SID 检测和 native lifecycle 配置缺口仍需独立构建补丁。

## 验证边界

验证涵盖 pristine 契约、补丁行为和语法、构建证明、产品配置／消息／子代理回归，
以及隔离状态下的最终 Gateway 启动。真实账户推理、付费媒体生成与 macOS/Linux
安装包需要相应凭据或平台，不能由本机 Windows 单元测试代替。

- `npm run lint`、`npm run build`、`npm run compile:electron` 通过。
- 受影响测试集中运行：43 个测试文件，571 项通过，1 项按条件跳过。

  23 个补丁证明和 frozen runtime 校验通过，9 个本地扩展编译零错误。
- 最终产物的实际 Gateway 检查通过：协议 4、480 个方法、进度刷新、ACP
  诊断及会话创建；决策模型 file SecretRef 的读取、轮换、所有者失效阻断与恢复通过。
