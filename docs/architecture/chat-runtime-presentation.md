# 聊天运行状态与内容呈现

本页维护 timeline 上的运行阶段、失败、工具详情和富内容阅读。所有呈现都消费已准入的原生事实；工具失败、可见 final 和空闲提示均不建立整轮执行结果。事件身份和恢复主线见[聊天渲染](15-chat-rendering.md)，真实执行准入见[执行引擎](05-agent-engine.md)。

## 1. 运行活动：阶段、进度与等待

运行中的时间线尾部使用现有 `runActivity` 展示启动、排队、准备、等待模型、思考、回复、工具和重试阶段，并复用每秒更新的界面时钟展示耗时；不另建计时器或猜测进度。带 runId 的状态只附着于匹配的当前运行，结束后移除动态指示，耗时回归终态页脚。明确重试立即提示，慢响应仍遵循已有静默时长与活动确认规则。常规运行中提示的星芒和文字流光始终保留动画，作为持续执行的状态反馈，不受系统 `prefers-reduced-motion` 影响；警告文字仍使用静态警告色，思考、阅读、等待及工具状态动画同样不受系统关闭动画影响。读屏只播报阶段变化，不播报每秒计时。

### 原生阶段与两类活动项

原生 `run_status` 直接投影工作区准备、上下文准备、记忆整理、模型启动和模型重试；
重试次数、上限和倒计时只采用原生已给出的元数据，不发起额外重试。原生 `compaction`
显示上下文整理阶段；公开 `item:tool` 的 `progressText` 和已知运行工具的 `command_output`
补充当前工具说明、当前输出字符数及距最近更新的时间。输出可能为有界快照，不当作总量。

长工具参数通过普通 `item` 状态信封补充无正文活动：精确
`itemId:run-stream-progress`、`kind:status`、`phase:update`、`status:running`，嵌套 `progress`
只包含 `kind:model|tool-input`、UTF-16 字符数，以及工具输入的原生 toolCallId、name、complete。
参数块开始与结束即时更新，其余更新最多每 250ms 一次。

原生既有通用 item 快照负责重连恢复，
该计数在同一运行复用一个状态 item，不增加 IPC、RPC、产品持久化或消息缓存。原生观察点及其公开
扩展替代审计见 [032 补丁说明](../../scripts/patches/v2026.10.7/README.md)。

原生 Completions 对旧格式 `function_call` 等片段可能先缓冲，到模型终态才发布正式工具
事件。此时不能从没有 Tool delta 推断模型停止，也不能把未完成的片段作为可执行工具。
032 在原生既有请求活动回调补充独立的 `run-request-activity` 状态项：仅在实际模型
进展为 `true`、当前请求未取消或结束时，最多每秒发布一次；SSE 保活和空帧不算进展。
该项仅含 `progress.kind:model-activity` 与原观察时间 `at`，没有正文、工具身份、字符数
或百分比。请求间的节流状态独立，不改变原生 timeout、signal、迭代器或执行准入。

两个状态项分别由原生既有有界快照保留，通用活动不会覆盖详细参数计数。Renderer
按来源时间刷新活跃提示；已有思考、回复、参数生成、准备工具及真实工具执行阶段继续
保留原阶段和详细信息。通用活动不是工具开始或执行成功的证据，也不重建动画节点。
公开 Provider 包装接口仅适用于对应 Provider 所有者，通用插件 hook 没有实际请求 signal；
不能为观察活动而替换用户 Provider。原生诊断时间戳更新也没有对应的公开实时事件。
该观察只覆盖调用原生活动通知的 embedded transport，不覆盖未通知的自定义执行器。

隔离回归必须分别覆盖相同长参数的现代 `tool_calls` 与旧格式 `function_call`：后者在
终态前没有正式工具事件时仍有真实活动提示；保活、取消、旧请求迟到和异常发射不产生
虚假更新。还需验证真实 Gateway 传输、两项快照恢复、主聊/侧聊及动画节点保持。
合成模型通过不能证明某次历史会话使用旧格式，也不能替代真实内网模型现场验收。

既有隔离 Gateway 分别验证现代与旧格式长参数、两项 in-flight 状态和精确终态；SDK 与 DOM 用例另验证嵌套 show_widget 参数、阶段及节点连续性。SDK 用例不执行嵌套工具，DOM 用例使用注入事件，不能外推真实内网模型的完整链路。

### 阶段切换、静默和可访问性

参数未结束显示“正在生成工具参数”，块结束显示“正在准备调用工具”，只有真实 Tool start
才能显示执行状态；原生 `tool:input_delta` 是参数差异预览，不创建运行工具。所有活动先通过
现有 run/session/sessionId/lifecycleGeneration 与序列校验，稀疏重连快照可补正文而不能倒退较新
活动；切换会话时后台视图沿用同一活动投影规则。没有更多事件时只显示真实的更新时间及既有
慢响应提示，不伪造百分比、剩余时长或运行结局。星芒和流光节点在计数更新期间保留，阶段文字
与不参与 live announcement 的计数说明分开，避免持续打断读屏。

无正文进度不能唤醒可能最终返回 `NO_REPLY` 的静默通知；仍由原有公开内容准入决定显示。
重连恢复的是原生快照中最后保留的观察，沿用原时间戳。锁定版本在已有任意 `item` 后会省略
后续启动阶段，因此模型回退准备期间可能暂时恢复较早阶段；下次真实事件会更新。公开快照
没有暴露被省略阶段或完整序列水位，应用不能推断它们，也不为此增加快照补丁。

工具格式纠正沿用同一原生运行的 lifecycle progress，原因码为 `tool_call_format`。
仅接受成对的 `retryAttempt: 1 | 2` 与 `maxRetries: 2`；计数缺失或不合法时展示通用纠正提示。
进入其它阶段或重试原因即清理旧计数，显示状态不授予重试权限。
过程正文继续使用原生消息及分段身份，中间失败不替代整轮 execution-settled 终态；
不复制旧正文、不重发用户输入。恢复准入与收口契约见 [Agent Engine](05-agent-engine.md)。

运行提示的星芒使用固定尺寸 SVG，占用头像列，文字与消息正文左边缘对齐。阶段和慢响应/重连提醒复用同一个状态文本节点，恢复活动即替换提醒；耗时保持独立且不随提醒换行。后台工具历史补取刷新工具状态时保留较新的思考、回复或重试阶段。静默计时从最近模型活动或阶段切换中较晚者开始，明确排队/准备阶段不显示模型慢响应提醒。

等待提示优先反映可观测状态：断连与重连分别显示；明确重试按限流、超时、服务繁忙、认证失败或未知原因区分，且不被通用长等待文案覆盖。回复中途静默区别于尚未收到响应；只有近期 Gateway 确认运行仍活跃时才宣称任务仍在运行。收到新的模型内容后清除静默提醒，不凭等待时长猜测失败原因。

## 2. 失败：详情补取与实时/历史接管

### 错误行和文本清洗

实时及历史失败共用错误行：左侧错误头像承担状态图标，正文展示时移除开头重复的警告符号，原生诊断和完整复制内容保留。摘要与首段补充详情用冒号连接，其余详情换行保留；默认最多显示实际三行，仅在当前宽度下超出三行时显示“错误详情”按钮，窗口缩放后重新测量。展开在同一文字节点显示完整内容，支持键盘操作和再次收起，不重复摘要；搜索命中被裁剪的诊断时先展开再滚动定位。

原生 `LLM request rejected:` 摘要只有在其载荷完整符合上游 Markdown 转义格式时才解码一次，原始详情和真实路径中的反斜杠保持原样，不渲染 HTML 或 Markdown。详情沿消息正文对齐，保持与错误提示一致的文字颜色和字号；展开入口使用文字与方向箭头，不添加分隔线或文字下划线。支持复制完整的显示诊断；不复制已移除的终端日志指令提示。

日志引导语过滤只覆盖锁定 OpenClaw 源码中的现行完整句式：`For details, open Settings → Logs in the Control UI or run …`（带或不带 `in your terminal`）、`If it continues, open Settings → Logs in the Control UI or run …`，以及后台检查失败的 `Troubleshooting: run … in a terminal.`；其中命令均为 `openclaw logs --follow`。

流式输出中的匹配前缀同样隐藏，文字分歧后恢复正常展示。不兼容旧版 `To view logs, run …`，不再按独立命令或 `Log:`／`Logs:` 行删除内容。错误行及其复制内容将独立名称 `OpenClaw` 替换为共享产品元数据中的 `PRODUCT_NAME`，保留 provider 原因等具体诊断；这些处理只作用于展示副本，不改写原生消息、日志或运行身份。

错误摘要以 Gateway 实际提供的显示文案为准，不在 Renderer 添加固定模板。
经原生详情证实为空失败源时，在恢复空 content 前将 Gateway 显示摘要保留在该原生消息的
内存展示元数据中，公开 `errorMessage` 仍只保存具体原因；历史归一化据此动态拼接。
摘要和原因各保留一份，不借用其它来源的摘要，也不持久化另一份错误缓存。
没有可靠摘要时只展示原因；实时与历史的原生文案可以不同，不为统一措辞生成摘要。
追加详情时仅去掉摘要末尾的句号，再以冒号连接，避免出现 `reply.:`。

### 受限详情读取

普通 `chat.history` 会移除原始错误字段。Renderer 通过已有
`runtimeServices.historyDetails`，按原生消息 ID 读取有界、脱敏的 `errorMessage`；
原生历史仍是权威，不直接访问 transcript 或日志、不新增错误缓存或运行时补丁。
生成的通用失败文案不能覆盖接口返回的具体原因；实际存在的部分回复继续保留。
错误详情仅说明对应模型消息的失败，不替代整轮执行终态或触发自动重试。

实时聊天流使用原生 `errorDetail` 的公开脱敏字段；无法提供具体原因时，
再由现有历史详情读取补齐。终结文案只在展示副本上追加同一 run、具有稳定原生
消息身份的诊断，已分类的错误指引保留并换行附加详情，不修改 controller 的运行状态
或原生终态。部分回复后的错误可独立
显示；仅思考或工具内容也保留失败详情，每条原生消息的详情在其最后一个可见分段后
展示一次，已有同轮错误行包含该详情时不重复展示。完整消息补全路径带回的错误同样
受展示长度限制。

### 失败部分正文的恢复

失败消息的原生 `commentary` 正文即使已经入库，也可能在 `chat.history` 中与 Thinking
一起被替换成通用失败文案。聊天历史详情读取显式请求 `includeFailurePartialContent`，
Runtime Services 通过原生可见分支 SDK 按精确 entry ID 补充受限的 text/thinking 展示块，
逐块脱敏且不返回签名、工具参数或原始 provider diagnostics；不读取 transcript 文件或建立正文缓存。

补充仅接受整个源内容由 text/thinking 组成的失败助手消息；含原生 `openclawDisplayContent`
替代内容、混合工具／媒体、activity 或已附着工具／投递附件的显示行保持原生展示投影，
不因文本补全覆盖或删除这些产物；
隐藏消息、缺少原生 runId、查询期间发生会话替换时不返回正文。

恢复正文沿用原生控制回复的过滤语义，不展示 `NO_REPLY`、`ANNOUNCE_SKIP`、`REPLY_SKIP`
及其重复片段（包括跨文本块的片段）或正文后的控制后缀；Thinking 中讨论这些标记不按控制回复过滤。
原生流错误占位前缀不作为实际部分回复恢复；没有真实内容时按空失败记录处理。
每条最多 128 块／200,000 字符、每批最多 1,000,000 字符，截断同时保留现有历史截断元数据
和可见的 `...(truncated)...` 文本后缀；后缀也计入字符预算。

Renderer 再次核对同一消息 ID、runId 和当前历史世代，以一份完整源投影替换同源显示分段，
保留 `stopReason:error`，由现有错误行在部分内容后展示原因。实时运行仍独占自己的正文，
不会因补全历史再显示第二份 Content；这一展示补全不修复、不重放被拒绝的工具调用。

### 实时错误何时交给历史

错误终态的实时投影仅在历史实际包含同一次 runId 且原因一致的失败记录后退役。
具有非空原生消息 ID、精确同 runId 的模型错误来源（包括空失败归一化得到的 `system` 行）
与实时错误组成一个展示组。组内保留实时终结原文、各来源的实际 Gateway 摘要与公开原因，
不按英文句子判定“通用错误”，也不据同 run 推断同 attempt 或同一原因。
仅省略完整出现在当前展示副本里的重复文字；某来源的实际摘要与原因均已完整覆盖时，
它不再另画错误头像。超出合成详情预算、未被完整覆盖的来源继续保留。
原始终结文案、来源身份及 controller 状态不变；这只是展示分组，不放宽退役或执行结论。
不同运行、缺少原生 ID 和独立 custom 失败回执仍沿原规则保留。
原生 `role: custom`、`customType: run-failed-before-reply` 的公开失败回执直接复用
终态错误行和红色错误头像；识别同时适用于直接消息与 `session.message` 解包后的消息，
不依赖本地错误缓存或英文正文。保留原生消息、身份和正文；相同精确 runId 的回执
阻止追加本地重复提示，并可在原因匹配时接管实时错误显示。该展示识别不建立整轮执行结论。

原生回执与实时终态原因不同且具备稳定原生身份时，两者均保持可见；运行中、乐观消息
和缺少原生身份的同轮提示不能借此绕过实时输出所有权。失败回执的耗时、结束时间、
模型选择及运行状态只采用精确 runId 匹配的产品计时，不借用前一用户轮次的计时。
`state_contention` 回执保留 Gateway 白名单公开的 `details.diagnostic`，经既有错误详情
限长及去重后追加；不读取私有 `details.error` 或其它 custom 类型的任意详情。

若公开终结错误与原生 provider 诊断不同，保留确定的整轮终结原因，并同时展示相同 runId、具有稳定原生身份的历史错误行。
原生 sessionInfo 的 failed/timeout 状态只能证明整轮结果，不能证明较早 attempt 的错误是最终原因；不据此退役实时错误投影。
助手部分正文仍由实时投影独占，无原生身份的本地提示不额外展示。

仅有部分助手输出、工具失败、同轮可恢复的模型错误或另一轮错误不能取代整轮失败原因；原生终态写入失败时，普通历史刷新仍保留当前 Renderer 中已收到的错误提示。
该投影不建立 Main／Redux 消息缓存，也不放宽会话切换、物理身份和历史世代的校验。

会话右键诊断同样遵循 2026.9.8 的历史展示契约：Main 按需读取 `chat.history`，
通过消息 `__openclaw.id` 和工具调用身份关联独立 `activity` 中的失败/阻止状态，
不能依赖已被展示投影移除的原始工具执行字段。回复前失败读取原生
`run-failed-before-reply` 公开回执。只将有界脱敏节选与闭合诊断字段交给 Renderer，
不建立消息缓存；步骤证据和全局 stability 背景都不能替代整轮 lifecycle 结论。
扫描缺口与建议的具体规则见 [会话诊断](../features/chat/session-diagnostics.md)。

## 3. 工具：身份、嵌套和输出阅读

Code Mode 继续使用相同的原生工具事件与历史投影。仅当工具为 `exec` 且输入包含字符串
`code` 时，摘要显示原生 `title`（缺省为工具编排说明），展开后按原始换行展示 JavaScript。
普通 shell `exec({ command })` 不按代码推断或重新解释。工具名称保持上游显示名称。
`wait` 和内部工具调用继续由原生事件驱动，不另建任务状态、等待轮询或结果缓存；
实时与刷新后的失败状态、输出及代码详情使用同一渲染路径。

工具展示继续消费同一套原生事件和历史，不增加 transcript、Main 或 Redux 消息缓存。
`ToolItem.presentation` 只保存展示所需的可选字段：原生 title、parentToolCallId、activity
分类标记、结果退出码、结果 entry identity 与截断标记。实时 tool/item 和持久 toolResult
使用同一投影函数；`chat.history.activity` 按 messageId 绑定。

旧记录缺字段时显示工具名和
有界参数摘要，不调用模型补标题。工具名后的预览优先取命令、路径等具体输入，
其他工具回退完整参数的有界预览；原生 title 不覆盖输入，action 不单独遮蔽其余参数。
Browser 提取动作、元素与输入文字，tool_call 提取目标工具，read 保留 offset/limit。
长工具名限制宽度，名称和预览提供悬停提示。非零退出码沿用执行结果原文，
不在参数上方额外插入退出码提示，避免可选展示字段变化导致重复提示闪现；受阻提示仅放在展开详情。

### 工具嵌套与结果状态

过程组沿用 Thinking / Tool 数量摘要，避免未覆盖的工具都显示为“其它操作”。
工具状态由原有指示灯和无障碍标签表达，不重复显示状态文字。
非零退出码、受阻、取消与结果未知是展示结果，不改写执行状态。嵌套仅使用同 run 明确父
身份，缺父、重复、循环或超深链回退平级；用缩进表达关系，保持原生段顺序。工具展开状态
按调用身份保留，过程组仍使用原有 takeover tracker。

### 输出分页和受限补取

普通工具保持直接展开输入、输出的原文布局，edit 保留 Monaco Diff。共享阅读器对短内容
仅在内容气泡右上角显示复制图标，保留键盘操作和复制反馈；长内容或部分输出增加下载/分页/补取操作。分页优先沿换行边界，
不拆分 UTF-16 代理对或 CRLF，每页最多 16,000 字符。空参数与等待参数单独提示。复制/下载使用已取得的
完整字符串；部分输出明确标记并禁用完整下载。

按需补取复用 `chat.message.get` 和现有
有界 historyMessage 路径，仅接受唯一匹配的 toolResult，验证 entry/run/call identity。
会话、连接、读者身份变化或关闭详情使请求失效；失败允许重试。无法恢复的原生 capture
截断不会伪装为完整输出。edit 的 Monaco Diff 来自调用参数，不代表实际 checkout Diff。

### 终端文本的安全着色

Exec/命令工具结果在两种应用主题中均使用深灰底的 Monokai 风格终端卡片，左上角三个
红黄绿装饰点不提供窗口操作，右上角保留复制图标。ANSI 16 色和语义高亮统一配色，
等宽终端阅读样式保留列对齐并横向滚动。基础 ANSI 前景色和加粗
转换为安全文本 span，OSC/其他 CSI 控制序列不执行；无 ANSI 样式时对 Windows 路径、
表头/分隔线、日期时间及 PowerShell 文件行做主题适配高亮。分页基于显示文本，复制/下载保留原文。

### 子任务归属与启动入口

子任务列表从原生 `sessions.list/describe` 的 `swarmGroupId` 投影 Swarm 归属，经共享子任务契约传到 Renderer，不另建持久化关系表。列表在各状态区及当前展示范围内将同组成员相邻呈现，普通子任务独立显示；下级任务与两处详情入口同样显示归属。归属随原生快照更新并遵守现有快照新旧顺序，不从聊天正文、普通 `groupId` 或父子关系推断 Swarm。

历史子任务通过分页读取 `sessions.list(archived: 'all')` 并按返回行的 `spawnedBy` 精确筛选。原生请求参数 `spawnedBy` 使用有保留期限的运行控制关系，不能用于完整历史发现，否则已完成任务会在控制关系过期后从面板消失。直属任务与后代遍历每次读取一份原生会话清单；下级分页跳过无匹配项的原生页面。这里只处理会话元数据，不读取或缓存消息正文，原生删除仍会使任务从下一份完整快照中消失。

sessions_spawn 保留通用参数和结果展示，仅在成功回执包含 childSessionKey 时在标题旁显示右上箭头（含 core tool_call 包装）。点击通过 getSubTaskStatus 刷新当前会话的子任务列表，按 childSessionKey 匹配完整原生任务（含任务 ID），再复用现有子任务详情 Tab，不从参数猜测目标，不改变执行流程；查询失败显示提示，离开当前会话后的旧查询不会打开 Tab。sessions_yield 保留通用展示。

## 4. Markdown、文件链接与富内容控件

### Thinking 和处理过程的披露

Thinking 在流式输出和已完成的过程详情中默认最多显示正文的 10 个行高，按实际换行后的布局检测溢出；短内容不显示开关，长内容在气泡底边居中提供向下／向上箭头展开与收起。
展开后正文自然增高，不增加内部纵向滚动。用户选择随准确过程身份保留，跨流式追加、完成和同作用域重新挂载继续生效，原生会话身份或历史 generation 变化及源内容替换时重置。
展开／收起沿用外层阅读锚点，不恢复跟随；搜索命中隐藏文字时先同步展开，再定位现有命中标记。

Thinking 内的普通代码默认换行并自然增高，不再复用普通消息代码块的 640px 限高或工具文本的 420px 滚动区；表格和需要保留排版的图形仍可横向滚动。
输出跟随与向上阅读统一由外层 `ChatScrollController` 管理；过程展开/收起仍只改变本地展示状态。

Thinking 的正文由专用展示入口拥有，不交给全局 Markdown 增强器替换成工具输出卡片。
普通内容分开提交稳定 Markdown 前缀和正在生成的尾部，追加文字不重建未变化的前缀。
思考不再提供分段阅读或分页导航；展开显示完整原文。沿用通用 Markdown 解析预算，超过 40,000 字符时安全回退为完整转义纯文本，不截断原生内容。
展开选择只作为 Renderer 展示元数据按准确过程身份有界保留，不保存另一份 transcript；无法证明原生身份连续时不按文本相似度继承。

2026-10-27 的隔离 Electron 夹具覆盖短内容无开关、10 行裁剪、底边箭头、展开／收起、流式追加、窄窗、历史深色样式及 70,000 字符完整展示；焦点揭示另以合成事件核对。
组件及聊天生命周期回归覆盖展开状态、源替换与作用域重置、搜索命中和阅读锚点；这些检查不连接真实 Gateway 或模型。

已完成处理过程、Thinking/Tool 过程摘要和工具详情使用原生 details 的高度与透明度
过渡，关闭时不立即移除内容；chevron、工具状态和新工具/等待提示有轻量反馈。
过程入口使用统一按钮、强调色及层级导线；高度、透明度和位移共同过渡，关闭保留
原有节点。按产品要求，这些聊天执行反馈在 Windows 请求 reduced-motion 时仍生效。
普通正文立即显示准入文本，不播放积压文字、不对每个 token 重播动画。调度与滚动
仍使用实际 ownerDocument 所属窗口。

### 富内容阅读器

代码块的展开、换行、下载，表格 TSV/放大查看，JSON 树/原文和 Mermaid 复制/放大/缩放
由 `RichMessageControls` 在共享 Lit 消息面上增强。状态以会话和消息内块 identity 为界。
JSON 树保存原文范围，保留重复键、数字拼写和转义，节点分批展开；非法、过深或过大 JSON
回退原文。TSV 对包含 tab/newline/双引号的单元格加双引号，并将内部双引号重复。
扩大视图里的链接关闭弹层后复用原链接动作。大段纯文本回退也使用分页阅读器。

Mermaid 保持 strict 模式，限制源码、行数和边数，禁止外部图片/点击指令/初始化覆盖，
主题变化后重绘。所有增强只改变阅读 UI，不改变原 Markdown 复制内容。

聊天正文的文件链接由 `markdownPathLinks.ts` 识别、`markdown-file-links.ts` 接入 token。
只启用显式文件目标与高置信 Windows 裸路径；含空格裸路径和不完整流式尾行不猜测。
`fileLinks` 以 true/false/undefined 区分有打开能力的聊天、无能力的聊天及非聊天消费者，
缓存同时区分模式和流式状态。受信 anchor 通过本次渲染的一次性 nonce 进入清洗后的 metadata；
原始 HTML 不能伪造文件能力，DOMPurify 仍阻止直接 `file:` 导航。

`CoworkView` 通过 React Context 向消息阅读面传递工作区打开回调，Lit 点击入口保持同步
boolean，内部启动异步准备。Main 的 `FilePreviewIpc.PrepareMessageLink` 通过最小 preload
只校验普通文件和真实路径，不读取正文、授予编辑或启动 App。相对路径按点击时所属工作区
的当前工程根解析，Main 对比产品会话绑定与期望根，Worktree 使用当前检出目录。

Renderer 的 owner、请求代次与共享预览计数贯穿准备、HTML、图片、App 和预览读取；
关闭侧栏、换会话/工程或后续导航使旧结果失效。新文件打开不通过无 owner 的窗口事件广播。
URI 单次转换、旧 HTML 适配、支持/排除案例和验证限制见
[消息文件链接](../features/chat/message-file-links.md)。

### Markdown 折叠结构

共享聊天消息正文显式启用 Markdown 折叠结构：专用解析规则识别块级 `<details>`、
`<details open>` 与 `<summary>`，内部继续解析普通 Markdown；其它原始 HTML 仍转义。
代码、转义与原始 HTML 字面区域内的标签不成为折叠结构。缺少标题时由 Renderer 提供
中英文“查看详情”；嵌套最多 32 层，非法或超限标签保留文字。其它 Markdown 消费者
（审批、进度卡、设置说明等）不随消息正文默认启用；渲染选项参与缓存键。

流式折叠块和所属 Markdown 容器保持完整，不在内部空行或代码围栏结束处切开。
未闭合结构只在显示层临时配平，不改写原生历史、模型原文或复制内容；大消息继续
遵守既有纯文本回退限制。消息控件按物理会话／历史代次、明确正文 owner 与块路径
保存有界的内存开合状态，更新前同步捕获、滚动测量前恢复。用户选择优先于原文
默认状态；焦点只在更新前位于同一标题且没有文本选区时恢复，不主动抢焦点。
状态随会话身份变化或卸载清理，不持久化，不按相同文字猜测实时／历史归属。

搜索可命中收起内容并打开祖先折叠块，展开后复用现有 Mermaid 和代码阅读控件。
同一活动正文从 streaming 到 completed 保持选择，持久历史分页按精确 projection key
恢复。锁定版本普通 assistant 流的随机 itemId 与持久历史没有公开的逐段身份映射；
真实历史接管后无法精确关联的新正文 owner 使用原文默认状态，不以文字、位置、
provider textSignature 或单独 runId 推断对应关系。

首版不保留被替换的同一 DOM 节点，
也不保证流式正文文本选区完整延续。

锁定 OpenClaw 的 WebChat 渠道已自动声明 `markdownDetails` 并注入 Collapsible Details
指导；消息正文渲染与该现有能力对齐，不增加 `connect.caps`、Main 注入或运行时补丁。
核心结论及必要操作保留在折叠外属于模型输出指导，Renderer 不做语义判定。

Mermaid 卡片使用复制、放大查看、下载三个图标操作，提供 title/aria-label。
放大弹窗仅显示右上角关闭图标；滚轮按鼠标锚点缩放（0.2–5 倍），指针捕获支持拖动平移，
释放/取消拖动清理状态，Esc 与关闭按钮恢复既有焦点。

历史加载提示在消息区域水平居中，使用“首次加载会话历史可能需要一些时间，请稍候”的通俗文案，
文字后显示三点错峰跳动动画；Windows 关闭动画或启用减少动态效果时仍保持加载动画。
独立运行记录早于 Gateway 正文抵达时不渲染孤立的
时间/运行时长页脚；时间线出现内容后才显示对应元数据。

## 5. 媒体与文件工具

### 播放器寿命和本地字节流

消息和 Tool 返回的显式媒体共用 `message-media.ts`：原生 audio/video 控件，不自动播放，失败可重新加载。消息卸载停止播放并释放资源，同步 DOM 移动不重置播放。既有图片使用 `localfile:`；音视频使用独立的 `localmedia://local/` 标准流式协议，Main 在 ready 前注册，在 handler 中支持单段字节 Range（206/416）、本地 MIME 与按范围读取，不改写消息或重新调用工具。CSP 仅为媒体增加本地协议与内联媒体来源。未扩展远程节点或平台能力。

原生托管音视频的平铺 `audio` / `video` block 按 `url`、`fileName`、`mimeType` 和
`artifactId` 投影为附件，保留真实交付身份。音频工具的自动交付可能只有托管地址，
不能要求最终正文附带 `MEDIA` 或本地文件路径。

聊天播放器绑定实际原生 sessionKey，
摘要按精确 artifact/消息身份解析已加载附件后，在媒体预览弹窗复用同一个播放器；
切会话关闭旧预览，不从文件名猜测原路径、不调用 `artifacts.download` 或保存副本。
换源、媒体类型或会话时先同步暂停旧原生播放器、移除 src 并重新 load，避免旧节点
移出 DOM 后继续播放已有缓冲。工作区侧聊和成员历史的固定文档只加载媒体最小
preload，通过同一目标窗口的窄桥申请/释放，不复制主窗口的完整应用桥。

### 原生媒体的受限代理

托管播放器按需经受管应用窗口主 frame 的 prepare/release bridge 申请随机
`localmedia://gateway/` 播放地址。Main 核对 canonical outgoing route 与会话，固定访问
当前 Gateway loopback，内部附加认证和 requester session；Renderer 不取得 token。
默认 session 的窄 WebRequest owner 核对确切窗口和 frame，浏览器 partition 保持独立。

流只转交原始音视频字节及白名单响应头，支持 GET/HEAD、单段 Range 和经过验证的
206/416，不整文件 IPC、不新增 HTTP 服务或放宽 CSP。换源、卸载、窗口导航/销毁和
Gateway process/lifecycle generation 变化撤销地址及正在读取的流，迟到准备结果立即释放。
播放地址最多每窗口 256 个、总计 512 个，超限拒绝而不淘汰正在播放的地址，且不持久化；
失败可手动重新加载，不重放合成工具。

原始容器和编码仍由
Chromium 解码，不承诺转码或所有编码可播。聚焦测试覆盖交付、摘要解析及授权/范围校验；
真实 Electron 的隔离工作区播放验证了 WAV 和 VP8 WebM 的解码与播放推进、最小媒体
preload、owner/frame 和 Range 路径；同源外来窗口与工作区 iframe 的地址盗用被拒绝。
验证不启动 Gateway，音频静音；不替代其它编码、硬件输出或所有交付场景的验收。

`file-tool-presentation.ts` 仅适配 Read、Write、Apply Patch 及可确认的原生包装身份。Read/Write 复用分页原文 reader 做代码高亮；Read 始终对原始输出直接高亮，不以 details.content 替换正文，不重复显示路径或“原始结果”；仅使用原生 details.kind 判断结果类型，不猜测文件正文 JSON 的业务含义。实际 write/edit diff 在已完成时优先显示。

Apply Patch 按文件呈现输入补丁，明确新增、修改、删除和移动，不重建不存在的旧文件版本；未知或不完整 patch 回退原文。保留原始参数/结果入口，不增加 JSON 树、文件定位或会话跳转。

## 6. 验证入口与限制

回归分别验证模型活动、真实 Tool start、错误详情和历史接管，不能用一种信号代替另一种。媒体验证应包含换源、隐藏、窗口销毁及 Gateway 换代；富内容验证包含非法/超大输入、用户展开状态和实际 ownerDocument。当前真实模型、代理及安装版限制随[会话诊断](../features/chat/session-diagnostics.md)、[文件链接](../features/chat/message-file-links.md)及相应功能文档维护。
