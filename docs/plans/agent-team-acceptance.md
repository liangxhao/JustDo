# Agent Team 验收与后续候选

当前已实施的用户流程、资源参数及原生所有权只在 [Agent Team](../features/assistants/agent-team.md) 维护。这里记录尚未完成的业务/界面验收和候选能力，不能作为产品承诺。原双模式、设置和优化方案中已完成的规则已归入现行说明；逐轮调研和审查结果由 Git 历史追溯。

## 尚需集成验收

| 场景                   | 核对结果与边界                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 真实模型首次建队       | “+”选两种模式、普通自然语言组织、助手不足/插件关闭；精确工具与实际团队对应，失败保留草稿                            |
| 首条消息与 viewer 委托 | dev 新初始发送流程、Team 发起登记、附件与原生身份一致；失效/重载/切换不回退双发，未知保持冻结                       |
| 完整生产群 FIFO        | Main 接收、真实 production room、holding、附件到群执行与来源汇总；同群跨窗口最多 3 条且严格队头，不自动重发 unknown |
| 组织者身份与权限       | 不参与仍自动汇总，同一个来源参与，Plan/Goal/harness/细粒度政策拒绝；外部客户端竞争不能冒充原子空闲                  |
| 详情补充               | 文本/文件/语音、旧 delivery 定位、来源模型真实转发和明确未转发；主草稿和模式保留，sealed 旧批次不重开               |
| 侧栏与独立窗口         | 完整 Tab、窄窗口、多附件、长历史、自动滚动与键盘 @；输入区可见、窗口切换和旧 ACK 不覆盖新草稿                       |
| 语音用户操作           | 麦克风开关、录音/识别/取消、离开和重试；文件转录与麦克风启用状态独立                                                |
| 停止、禁用及删除       | active/queued/unknown/summary 各阶段故障，快速开关、离线和重启；borrowed source 保留，精确 holding 清理补偿         |
| 长期记忆隔离           | 当前 custom-role/隐藏上下文与 FTS 已有局部证据；REM/NREM dreaming 及其他原生恢复/读取入口需实际验收                 |
| 系统与内容质量         | 签名安装包、多平台、断电/进程失联/配置损坏、真实模型独立验收质量与讨论成本；fixture 不能替代这些结论                |

验收使用隔离状态与明确模型配置，区分源码核查、fixture、真实业务以及付费模型质量。运行后只记录必要结论与剩余条件，原始日志、凭据和数据库不进入提交；不得将旧版本或旧工作树结果改写成当前环境已通过。

当前隔离 Gateway 的 `--history-toggle-only` 验证通过：Team 历史 RPC 在关闭后不可用，常驻离线回执仍可核对，重新启用并重启后恢复原有公开回复。完整探针在组织者模型上下文的 sender／relay／authorization 联合断言处失败，尚需逐项核对原生事实；本次历史开关结果不代表完整组织者流程已通过，也未放宽该断言。

## 后续候选

| 候选                                    | 推进前条件                                                                                                              |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 原生 queued/followup 统一 Team 发起绑定 | 证明可信当前输入、精确 execution lineage、权限与副作用边界；不能猜 latest message/runId 后缀或伪装 browser toolBindings |
| 确定性 peer 直投/运行中指导             | 单独验收公开 agent/steer 等合同的接纳、输入归属、权限、附件、忙碌和恢复；现有来源模型转发不承诺直投                     |
| 协作公平运行池                          | 证明互发和回复不会形成循环等待，不把普通全局/Subagent/Swarm 并发混作协作池                                              |
| 上下文增量与大型汇总                    | 可核对引用覆盖、稳定来源与完整性，超限明确失败；禁止产品 transcript 缓存和无标记截断                                    |
| 汇总开关、批次时间上限与助手创建策略    | 新批快照和取消/unknown/source fence；不得倒改旧 outbox 或扩大工具授权                                                   |
| 动态群成员、永久仅 @、更大团队          | roster/incarnation/修订与批次公平性、预算和负载重新验收，不能只改 UI 数值                                               |
| 精确 token/金额预算                     | 真实计费、失败调用、重试、缓存与工具费用可证明，不能把投递次数当扣费上限                                                |

MoA 继续作为独立可选扩展推进，见 [MoA 交接方案](moa-extension-plan.md)。它不负责 Team 成员生命周期、群广播或工作批次验收。其他原生委派候选见[高级协作候选](multi-agent-adaptation-plan.md)。完成某项后将实际契约和限制归入现行功能说明，删除对应候选与完成验收条目。
