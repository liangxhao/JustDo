# 语音增量响应剩余工作

状态：未实施。本文只保留原语音计划中尚未完成的 HTTP 响应流与逐块播放要求。

四种通用协议、独立用途绑定、离线兼容和 Gateway relay 实时对话已经接入，现行合同见[通用语音接口](../features/speech/speech-protocols.md)、[模型管理](../features/models/model-management.md)与[语音功能](../features/speech/voice-and-transcription.md)。自动化证据及真实设备、内网服务的验证限制随现行功能维护，不在本页重复实施记录。

## 1. 需要解决的问题

当前录音 HTTP ASR 完整缓冲 JSON，HTTP TTS 完整缓冲音频字节或 JSON/Base64，再校验和返回。支持增量响应的目标服务仍需等到完整结果后才能显示文字或播放声音。

响应流分别处理上传结束后的文字增量、合成音频增量，不改变完整录音输入的语义，也不替代已经接入的 Realtime 听写和双向语音会话。

## 2. 实施边界

| 剩余工作 | 必须明确的合同 | 完成条件 |
| --- | --- | --- |
| HTTP ASR SSE | 标准转写响应的事件名、文字 delta/final、结束、错误和重复事件 | 显式选择受支持响应方式；有界解析分段 UTF-8/SSE；取消或配置变化后停止更新；最终文字不重复、不自动发送 |
| HTTP TTS 增量返回 | 标准 Speech 的音频字节流与 Chat SSE 的音频字段分别适配；固定输出编码和分块解码规则 | 不把 HTTP 分块等同 SSE；首块前验证响应类型，后续持续校验大小/时长；截断、空块和格式变化明确失败 |
| 有界增量播放 | 上传、响应、解码、播放各自背压；音频格式、播放标记、配置代次和当前请求身份 | 队列与累计大小有上限；慢设备不无限积压；停止、撤权、导航和换音色撤销旧缓冲；迟到块不串入新请求 |

响应模式必须由明确的协议实现和服务合同准入，不从供应商名称、域名或一次成功调用推断。沿用现有模型分类和用途隔离，不增加厂商选择器，不在请求失败后自动改为另一接口或重发完整音频。

标准转写事件与 Speech 二进制格式分别验证；目标服务没有已确认的响应流合同就继续完整返回。现有完整缓冲路径、本地五模型、工具权限和独立用途选择继续可用。

## 3. 验证门槛

- 先取得目标内网服务的实际协议声明及代表性响应，明确增量是否被该部署支持，再实现对应适配器。
- 使用合成响应验证跨网络分块的事件/编码边界、重复与缺失 final、错误尾块、无结束事件、超时、超限和背压。
- 验证停止与取消的差异、发送前撤权、A → B → A、服务处理结果未知、迟到块以及旧播放队列释放；不自动重试提交。
- 分别验证输入框与 STT 工具、回复朗读与 TTS 工具的权限、偏好和生命周期，不将工具启停变成其它入口的开关。
- 记录真实目标服务和设备的首字/首音延迟、持续播放、音质与代理兼容性；模拟测试不替代现场结果。

音色克隆/设计、组合式 ASR → 助手 → TTS 自动对话、WebRTC、手动音频 commit、断线续传、私有认证或专用 SDK 不属于这项剩余工作；如有明确需求，另行设计。
