# OpenClaw v2026.10.4 runtime patches

The source is the pristine `openclaw@2026.10.4` npm archive locked by `source-lock.json`, compared with sibling source tag `v2026.10.4` (`383c124cc32ffee3f8e56f549b88da94d269a4af`). Historical and partial shapes require a pristine rebuild.

## Disposition

The target contains 31 independently removable patches. Native in-process dispatch now separates both transcript and CLI-history writer scopes after caller-context restoration and authority capture; former 039 is removed. Pristine contracts and cross-bundle SDK tests retain this boundary. Former 043 remains necessary: the target native stop/close lifecycle still reproduces foreground SQLITE_BUSY. Its new 025 transformer preserves scheduled-maintenance joining and checks six native copies plus the final bundle. Real UI acceptance additionally exposed global finalization-hook buffering; 026 scopes that hold to the admitted native attempt without weakening owned revisions. Fresh-session acceptance exposed Windows canonical-readiness aliases and response publication during deferred reads; 027/028 address those separate native boundaries. Structured reasoning exposed an independent provider-parser and Agent delivery hold; 029 streams native normalized public text independently of the private thinking lane. Manual Apps exposed a persisted-workspace mismatch that retires their MCP runtime on the next model run; 031 aligns native workspace selection.

Most former worker/recovery duplicates are now shared imports. Target counts are audited from this archive; old 9.8 counts are not target evidence. Source application, current-shape idempotence and final bundle verification are separate requirements.

## Native bindings and ordinary implementations

MCP Apps use the native authenticated WebSocket APIs without a lifecycle patch. Former MCP Apps patch `030-mcp-app-operation-lifecycle.cjs` is removed (distinct from the later `030-tool-call-format-recovery.cjs` already on dev) by an explicit host contract decision: closing stops local interaction and attempts exact known-context cleanup, while dispatched operations may complete and view grants/resources retire under the native lease (currently up to ten minutes from creation). This is not a missing MCP Apps protocol capability. Recheck native cancellation and public final-view release during each upgrade; see [the host contract](../../../docs/features/chat/mcp-apps.md#原生接口与插件替代审计).

031 fixes a separate native workspace bug. Pristine `mcp-app-extension-runtime.ts` chooses `entry.spawnedWorkspaceDir ?? agent home`, while model ingress resolves lineage/inherited workspace and `spawnedCwd`. A project session opened manually therefore installs a runtime in the role home; the next model run selects the project and retires it, revoking original App interactions and stopping its local asset server. Public App launch/prepare APIs expose no workspace override, and a plugin cannot replace native runtime ownership. The patch imports the existing ingress resolver into the single locked native module and includes persisted workspace facts in its preparation fingerprint. No grants, TTL, request cancellation, view release, or plugin admission checks change. Tests: `tests/openclaw/patches/v2026.10.4/mcp-app-session-workspace.test.ts` covers pristine failure, current-shape idempotence, source/bundle atomicity, exact helper bindings, native precedence and changed-owner rejection; `tests/drawio/editing-native-smoke.cjs` covers the actual desktop bundle with different role/project directories, an existing run during manual open, continued editing, original source/resource liveness, suspension/rebinding and restart recovery. Remove 031 once upstream manual preparation uses the same persisted workspace semantics and current-owner guard as model ingress.

Owned execution and compaction implementations remain in `src/main/openclaw/runtime/native-support/`; 019 and 022 bind native live owners and opaque authority. Required Runtime Services remains independent of optional plugins. No second transcript store or migration bridge is introduced.

026 addresses the pristine `prepareStream` global `before_agent_finalize` gate: merely registering the required Team guard otherwise buffers all ordinary replies until completion, even when its handler has nothing to revise. The public hook options cannot scope that gate in 10.4. Its identity-only synchronous `appliesToAgentRun` option receives the frozen agent/run/session/workspace projection. Only explicit `false` with a complete native run/session identity excludes a registration; missing, throwing or asynchronous selectors remain protected. Admission locks after `before_prompt_build` and its host-authority check, before agent-run hooks/model output. Delivery and final dispatch use the same registration and original handler references, across reset/revision passes. A different final identity is rejected, rather than selecting new revisions after text may have escaped. Native lifecycle, timeout/error handling and reasoning-specific buffering remain unchanged. Runtime Services and Workflow declare their exact ownership checks; their existing execution/revision authority remains separate.

The SDK contract covers both `PluginHookRegistration` and `PluginHookRegistrationOptions` even when they share one declaration file; the runner factory and both declarations must have the same patch state. Product options instantiate `api.on<'before_agent_finalize'>` precisely, preserving native hook-specific tool-authority restrictions. The semantic suite uses a real strict TypeScript program through the core API and all four SDK declaration surfaces, including positive product options and negative non-finalize, async-selector, readonly-context, foreign-context-field and overly broad option contracts. Transpilation alone is insufficient evidence for these declarations.

029 addresses a separate native hold: `beginReasoning` makes the Markdown partitioner permanently strict after structured reasoning, and `handleMessageUpdate` independently withholds reasoning-associated completions text. Public provider wrappers receive already-parsed events; their response callback exposes status/headers, not the raw iterator. Replacing the whole transport in a new provider plugin would duplicate SSE, tool assembly, usage, cancellation and egress policy. The patch separates parser recovery from buffering and admits replaceable Agent previews instead.

Admission uses the native normalizer's text/thinking channels, without provider names, model IDs, URL checks, time thresholds or capability guesses. The native reasoning fields (`reasoning_content`, `reasoning`, `reasoning_text`, private `reasoning_details`) and typed thinking remain separate from public content/refusal. This follows the [Chat Completions content contract](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events) and the [documented separate reasoning fields](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens). Resumed thinking preserves native commentary/final classification rather than revoking the public-channel contract.

The partitioner's structured recovery mode retains incremental Markdown and inline tag ownership, but never recovers unclosed reasoning as public text, including same-packet success/tool flushes. An orphan closing tag retains native visible-lane literal behavior and cannot retroactively hide already-public bytes. Explicit strict mode retains the original whole-turn buffer and retroactive orphan-prefix protection; inline-only parsing keeps its original behavior. The `structuredTextStreaming` internal delivery flag admits Agent previews only. `textPhaseRequiresTerminal`, durable partial/block gates, error/abort classification, finalization and whole-run settlement remain native. A preview that settles as commentary is retracted with an empty replacement for the same assistant item, without clearing independent thinking, tools or preamble.

The exact nested `@openclaw/ai` transport and partitioner are included in the patch transaction/index and syntax checks. Their bytes and package identity join the current/frozen manifest and Windows archive proof. All three native modules and the final bundle must agree; older manifests and partial patch shapes require a pristine rebuild. Bundle checks follow the AI transport's actual factory/reducer bindings, leaving the core Markdown copy untouched. Coverage lives in `reasoning-completions-streaming.test.ts`, `structured-reasoning-stream-parser.test.ts`, `reasoning-completions-semantic.test.ts` and the no-network `tests/openclaw/runtime/completions-stream-latency.native-smoke.mjs` control/patched probe.

Exact target sets cover the root canonical-key and validation-cache modules plus both inlined functions in the pristine `dist/state/openclaw-state-read.worker.js`; final-bundle verification retains all three source files.

028 addresses publication inside `withReadySessionRows`: an inner reader may catch the private deferred signal and return a fallback, while its outer frame still requires readiness and will retry the consumer. Both successful and failed responses therefore remain subject to the existing readiness loop, sharing, permission and cancellation checks, within the same read view. There is no response cache, deduplication, alternate history API or arbitrary retry limit. 027 supplies real readiness convergence; the two patches have independent removal conditions.
