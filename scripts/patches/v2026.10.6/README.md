## Target semantic changes

- **005/012/018/025:** startup recovery uses the new native settlement aggregate; message forks forward one shared native intent to the main, incognito and worker implementations; session creation is now guarded by `assertSessionEntryCreationTarget` with the native database-identity branch first; SQLite retirement keeps the new void `beginClose()` and the asynchronous `stop()` join before a zero-wait final checkpoint.
- **019:** target `loadSubagentSessionEntry` is asynchronous. Managed tool preparation awaits a native current-session proof in `createOpenClawCodingToolsInternalAsync`; the shared generator consumes that proof for the same options object, exact run and native registry owner. Synchronous managed callers without preparation fail closed. Registration preserves the original `SessionEntry` returned by `params.assertCurrent()` and creates execution metadata separately. Harness selection stays in `selectEmbeddedRunHarness`; the deleted selector is not recreated. Native subagent completion/wait APIs still do not establish exact `executionSettled` facts or run-owned cleanup.
- **020:** native `terminal.close` now uses `terminalSessionHandler`. The patch keeps its validation and connection checks, and changes only the inner close call to carry the explicit terminate flag.
- **022:** the target mutation-authority module exports the handler-custody binder as `t`; `n` is the different in-process binder. The installer checks both the injected import and the actual native export before any writes. The final bundle must bind the real handler-custody function. Pristine/current controls reject the wrong `n` alias and a swapped `t` export.
- **024:** native recovery already relocates in-tree junctions and validates hardlinks. The retained gap is an accepted external absolute Windows directory junction. The new wrapper preserves the whole native filter and adds directory junction type only after that filter allows the copy. An actual Windows filesystem control reproduces native `EPERM` without this change.
- **026/029:** the target publishes one `config-contracts-C65kIjn4.d.ts` owner, including `PluginHookRegistration$1`. Strict TypeScript programs test actual consumer admission; transpilation does not prove these contracts.
- **028:** the parser retains the target `allowRecovery` argument and adds a separate terminal flush flag. Tool-boundary flushes still pass `false`. The target subscriber reads fallback text from `raw.text` and keeps its new assistant projection/error transcript paths. Native retained-commentary collection alone does not provide common source-message identity, true completion facts and reconnect scope snapshots.
- **029:** candidate routing is authoritative only from native `runOptions.modelRoutingProvenance` and the exact embedded candidate plan. Outer request fields cannot bootstrap initial-candidate eligibility. All insertions are atomic and mixed source states fail. Native terminal completion now reads final assistant text from `input.prepared`; rejected finalize-hook drafts are cleared there as well as from payloads and durable partials.
- **030/031:** manual Apps use the native persisted session workspace resolver. Goal settlement persistence moved into `persistPreparedGatewaySessionLifecycleEvent`; the outer delegate is not patched. New native session facts/delivery generation are useful fences but cannot substitute for exact whole-run settlement, durable conditional admission or registry ownership.
- **033:** fs-safe is now 0.25.0 and native package publication shares `publish(from,to,kind)` across install, backup and restore. Recovery is enabled only for the explicit extension install transaction and `kind === "install"`; backup and restore are never opted in.

## Why these remain native seams

Supported application and Runtime Services APIs remain the first choice. They cannot retroactively change native transcript-to-provider projection, insert metadata at final prompt assembly, alter closed RPC schemas, select the database writer transaction, resume a specific refused filesystem publication, or observe an unexposed native runner terminal. Provider wrappers see normalized events after the reasoning parser and cannot restore withheld chunks without replacing the full transport. Main cannot close the Goal status-read/send race after native work owners change. Those boundaries justify the retained narrow insertions; ordinary policy and state machines stay in their owning application/plugin support modules.

The 019 async adaptation also requires one narrow predicate extension to native `captureSessionEntryCurrentCheck` in `dist/session-binding-runtime-BErg3yzP.mjs`. The existing asynchronous worker preparation returns a real synchronous native guard, but its default predicate compares only session ID and lifecycle revision. Native APIs permit `pluginOwnerId` to change without either changing. An optional `expectedSessionEntry` therefore copies all three expected fields before any await and checks them in the initial worker read, every live guard and prepared source authority. It cannot be disabled by `matchGeneration: false`; calls without the option retain native behavior. A retained worker consumer cannot supply an escaping synchronous cancel/actor guard, a cached boolean cannot establish current ownership, and a source-assertion property alone is insufficient because native registry mutation invokes its callback synchronously. The parent, SDK and build agents independently reviewed these limits and approved this smallest native change before implementation. Tests include the complete native function, mutable expectations, same-ID/revision owner changes, delayed actor/session/epoch changes and the original admitted registration return object. A real native SQLite control confirms owner-only replacement invalidates the guard and preserves native source preparation.

The same capability also preserves publication of the real producer's settled lifecycle event after cancellation.
